## Active engine boundary proof

The active `Engine` interface still contains the routed snapshot mutation
methods:

- `SnapshotCreate`
- `SnapshotDelete`
- `SnapshotRestore`

The active `Engine` interface still excludes repair/recovery methods,
including:

- `Repair`
- `SnapshotRepair`
- `RepairPlan`
- `Recover`
- `SnapshotRecover`
- `RecoveryPlan`

Candidate `Repair*` and `Recover*` request/result types remain contract shapes
only. They are not active engine methods.

## CLI and lower-layer ownership proof

- `doctor` remains CLI-owned orchestration over lower-layer recovery,
  schema/version, verify, and audit hooks
- `repair` remains CLI-owned orchestration over lower-layer maintenance repair
  hooks
- lower-layer recovery, maintenance, verify, and storage corrective helpers
  remain internal primitives rather than public engine repair/recovery APIs
- engine contract neutrality tests still prevent lower-layer package types from
  leaking into engine repair/recovery contracts
