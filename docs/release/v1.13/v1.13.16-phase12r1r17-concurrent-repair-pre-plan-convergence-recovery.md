## Frozen convergence state machine

Every current-state classification pass holds the completed-object repair
mutex. A zero-entity plan invalidates the complete validation, recipe,
fingerprint, entity, placement, and staging decision that produced it. The
caller releases the mutex, performs any bounded wait or backoff outside all
locks, reacquires the mutex, and classifies again from current authority.

Fresh classification has exactly four outcomes:

- a healthy object uses normal transactional path attachment and returns
  `AlreadyStored=true` without a repair attempt or loser retry increment;
- a `PROCESSING` recipe chunk uses the existing typed, bounded contention
  protocol outside repair and publication locks;
- a trustworthy repairable terminal object builds an entirely fresh plan and
  uses normal atomic publication;
- an ambiguous, unsupported, or genuinely unrepairable object fails closed
  with the fresh cause and no authoritative mutation.

All observations share the existing single contention deadline. The first
zero restart may immediately reacquire. An identical immediate second zero is
only provisionally stable: one existing bounded backoff and a third complete
pass are required before fail-closed stability. Known contention or a changed
canonical state resets the consecutive stability decision. No new timeout or
unbounded stabilization loop is authorized.

## Canonical observational signature

The zero-decision signature is the deterministic SHA-256 composition of:

```text
AUTHORITATIVE_RECIPE_FINGERPRINT
DISTINCT_CHUNK_STATE_FINGERPRINT
ACTIVE_PLACEMENT_ACCOUNTING_FINGERPRINT
RELEVANT_CONTAINER_STATE_FINGERPRINT
VALIDATION_REASON_CODE
ZERO_PLAN_DISPOSITION
```

Inputs use sorted, length-delimited semantic tuples. They include ordered
recipe and mapping authority; one state tuple per distinct chunk; exact active
legacy or packed placement/accounting including packed companion consistency;
and relevant container authority plus physical existence, actual length, and
cryptographic hashes of referenced authoritative extents. Error strings,
timestamps, pointer identity, and incidental iteration order are forbidden.

Validation reason codes distinguish recipe/graph structure, terminal
status/retry, placement/accounting, missing payload, semantic hash mismatch,
codec/decode/authentication, container quarantine/state, and other trustworthy
graph validation rejection. `PROCESSING` is typed contention, not a signature
reason. Operational context, database, schema, configuration, unexpected
filesystem, I/O, or durability errors propagate and never become restart
signals.

Signature construction is strictly observational. It may query catalog and
physical state, and may encode `ENOENT` as the canonical missing marker. It
must not mutate status, counters, mappings, placements, quarantine, attempts,
or physical bytes, and it must not repair or clean anything.
