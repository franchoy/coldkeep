## Root cause

The legacy validator inferred merged-not-tagged on main without the active
tag, then required every recognized phase Complete and passed
phases_complete() into the candidate gate. That model was valid for older
simple fixtures but could not represent v1.13.15 truthfully:

    Phase 0–8: Complete
    Phase 9: Next
    Phase 10: Not started

The same defect would have forced tag CI to claim publication complete before
Phase 9 performed it and caused the old post-release-closed name to describe a
repository whose final closure remained active.

## Bounded correction

The validator now:

- parses generic consecutive terminal merge/publication/closure boundaries;
- validates exact state-specific progressions;
- adds canonical tagged and post-release-pending-closure states;
- retains released only for legacy contracts without boundary metadata;
- uses exact lifecycle gate statuses;
- recognizes validated recovery and post-publication closure PR contexts;
- fails closed on malformed metadata, invalid progression, premature release
  claims, wrong tag ancestry, and untrusted PR identity.

No release/version/phase literal is hardcoded in validator implementation.
