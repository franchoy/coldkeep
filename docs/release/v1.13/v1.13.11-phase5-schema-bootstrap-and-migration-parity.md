# v1.13.11 Phase 5 — Schema, Bootstrap, and Migration Parity

**Release:** `v1.13.11 — Safety and Backend Compatibility Gate Closure`
**Phase:** 5
**Starting commit:** `6e1a0675`
**Status:** Implementation complete; required-CI PostgreSQL proof pending

## Scope and result

Phase 5 adds outcome-oriented schema contracts in `internal/db`, using the
Phase 3 `internal/testutil/backendtest` fixture. It does not change production
schema, migration, catalog, engine, or runtime-backend behavior. SQLite ran
locally; PostgreSQL is deliberately optional locally and was unavailable for
this build. Required CI must still prove the `/postgres` child events.

The current schema version is **16** (`requiredPostgresSchemaVersion` and the
SQLite embedded schema). SQL representation differs by design; this phase
asserts observable results, not a generic DDL diff.

## CI execution and classifications

The existing plain-codec `correctness-matrix` package-contract step already
runs `./internal/db` with `COLDKEEP_TEST_DB=1`. Its JSON proof parser now also
requires Phase 5 PostgreSQL `/postgres` passes for SCH-001 through SCH-007,
SCH-009, and the empty-bootstrap boundary. No job, service, matrix, or package
list changed.

Local SQLite success is not dual-backend proof. BKC-004 and BKC-005 remain
`Separate evidence — no parity proof` until the required run confirms these
tests. BKC-006 remains `Unproven` as a broad claim; only the listed invariants
are candidates for an `Equivalent — proven` conclusion after that remote proof.
Intentional historical-version asymmetry remains explicit.
