# Coldkeep v1.13.3 — Read-Side Contract Cleanup

## Status

`Planning / in progress`

## Release Objective

`v1.13.3` cleans and stabilizes read-side contracts for stats, inspect,
snapshot show, and snapshot diff using the `v1.13.2` taxonomy baseline while
preserving public CLI behavior, JSON output, exit codes, routing, schema,
storage format, backend defaults, and PostgreSQL compatibility.

## Context From v1.13.2

`v1.13.2` established the baseline taxonomy language and narrow code-backed
primitives that `v1.13.3` must carry forward without broadening into a general
framework.

That baseline includes:

- engine unsupported taxonomy primitive: `engine.IsUnsupported`
- catalog deferred taxonomy primitive: `catalog.IsDeferred`
- validation-versus-unsupported boundary tests
- domain/invariant/runtime classification mapping
- CLI translation preservation tests
- explicit unknown and provisional surface tracking

`v1.13.3` applies that baseline to active read-side contract cleanup for
`stats`, `inspect`, `snapshot show`, and `snapshot diff`.

## Read-Side Surfaces

### `stats`

Primary concerns:

- repository, storage, and catalog summary ownership
- usage and dedup metric boundaries
- backend assumptions
- domain, invariant, and runtime boundaries
- JSON and human output preservation

### `inspect`

Primary concerns:

- object and relationship inspection ownership
- entity-specific not-found behavior
- domain-versus-invariant distinction
- output contract stability
- dependency direction between CLI, observability, engine, and catalog

### `snapshot show`

Primary concerns:

- snapshot-specific read contract ownership
- missing snapshot behavior
- result shape expectations
- CLI JSON and human output preservation
- backend compatibility

### `snapshot diff`

Primary concerns:

- query and narrowing semantics
- missing snapshot behavior
- path and filter behavior
- result shape expectations
- provisional surfaces carried from `v1.13.2`
- preservation of current behavior unless a later phase explicitly documents
  otherwise

## Compatibility Statement

`v1.13.3` must preserve:

- CLI behavior
- human output contract
- JSON output shape
- JSON error envelope
- exit codes
- command routing
- engine routing
- schema and migrations
- storage and repository format
- backend defaults
- PostgreSQL compatibility
- SQLite compatibility
- `v1.13.2` taxonomy boundaries

## Taxonomy Use Rules

`v1.13.3` must apply the `v1.13.2` taxonomy baseline narrowly and honestly.

Rules:

- use `engine.IsUnsupported` only for active unsupported engine modes
- use `catalog.IsDeferred` only for deferred catalog metadata seams
- do not introduce broad taxonomy helpers
- do not overclassify provisional read-side surfaces
- domain not-found must remain distinct from invariant inconsistency
- runtime, catalog, storage, and environment origins must be documented
  honestly
- CLI translation must remain stable
- taxonomy helper names must not leak into public JSON or human output

## Release Success Definition

`v1.13.3` is complete when Coldkeep has documented and test-protected
read-side contracts for `stats`, `inspect`, `snapshot show`, and `snapshot
diff`, with preserved CLI behavior, JSON output, exit codes, routing, schema,
storage format, backend defaults, and backend compatibility.
