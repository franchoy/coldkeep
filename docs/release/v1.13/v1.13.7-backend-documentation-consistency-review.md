# Coldkeep v1.13.7 Backend and Documentation Consistency Review

**Release:** `v1.13.7 — SQLite-First Repository Portability Baseline`
**Phase:** Phase 8
**Status:** Complete
**Branch:** `release/v1.13.7`

## Purpose

Review user-facing, architectural, roadmap, and release documentation against
the current backend behavior and the evidence completed in `v1.13.7`.

## Authoritative runtime facts

- PostgreSQL remains the normal local runtime backend.
- SQLite remains simulated/test-only in production startup.
- `coldkeep init` does not create a SQLite repository.
- no backend-default transition occurred.
- PostgreSQL remains mandatory in `PRE_RELEASE_CHECKLIST.md` Profile A.

## v1.13.7 contract facts

- the future local SQLite catalog target is
  `<repository-root>/.coldkeep/catalog.sqlite`
- the accepted local portability contract is catalog plus payload, not catalog
  alone
- clean-close/checkpoint expectations remain part of the portability contract
- PostgreSQL portability remains an external-catalog operational concern, not a
  directory-copy claim

## v1.13.7 direct evidence

- Phase 7A remediated the migration-idempotency blocker for existing
  physical-file mappings
- Phase 7B added a narrow rename/reopen/verify/restore guard through explicit
  SQLite seams
- the relocation guard proved exact restored-byte equality
- the relocation guard proved source-root independence after rename

## Claims not authorized

- normal SQLite local runtime support
- SQLite as the current default local backend
- automatic repository discovery
- live-copy support
- recursive-copy safety
- clone semantics
- cross-platform relocation proof
- broad codec or storage-format relocation proof
- PostgreSQL directory-copy portability

## Documentation classification model

- `current behavior`: describes what users can run today
- `proposed contract`: accepted future behavior target that is not current
  runtime truth
- `test-proven seam`: directly proven through explicit tests without implying
  user-facing product support
- `roadmap direction`: intended later product direction
- `historical statement`: accurate statement about an earlier release state
- `incorrect or ambiguous`: wording that mixes the categories above or implies
  an unimplemented capability

## Backend-default conclusion

`v1.13.7` does not change Coldkeep's runtime backend default.

PostgreSQL remains the current normal local runtime backend.

SQLite-first remains the intended future local direction.

## Portability wording conclusion

`v1.13.7` now has direct test evidence for explicit-seam SQLite
repository-root relocation.

This evidence does not constitute a user-facing normal SQLite runtime or an
automatic repository-move feature.

## PostgreSQL conclusion

- PostgreSQL remains supported and unchanged.
- PostgreSQL compatibility was hardened indirectly by the Phase 7A migration
  predicate fix.
- PostgreSQL remains mandatory in release validation.
- PostgreSQL operational portability remains external-catalog based.
