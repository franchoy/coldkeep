# Coldkeep v1.13.14 Release-State Validator Contract

**Release:** `v1.13.14 — Final v1.x Correctness Remediation and Closure Certification`
**Status:** Released and operationally closed
**Branch:** `release/v1.13.14`

## Applicability

Active source identity remains `1.13.14`. Phase 26 extends the generic
fail-closed validator with `post-release-closed` so a repository may advance
after publication without moving or weakening the immutable release tag.

The lifecycle distinction is exact:

```text
released:
checkout is the immutable tagged release artifact itself

post-release-closed:
repository HEAD is a strict descendant of that immutable artifact
and tracked publication/closure truth is reconciled
```

The reusable implementation derives `v{version}` and
`release/v{version}` from the active source identity; it contains no
v1.13.14-specific branch or tag literal.

## Development contract

- The branch is `release/v1.13.14` and tag `v1.13.14` is absent.
- Scope, phase list, and validation checklist agree on identity and `Active`.
- The Phase 0–26 topology is contiguous in both trackers: Complete, one Next,
  then Not started.
- v1.13.13 canonical scope, gate, and release-train evidence prove released
  and operationally closed state.

Expected Phase 0 result:

```json
{"status":"ok","validator":"coldkeep-release-state","state":"development","active_version":"1.13.14","violations":[],"error":null}
```

## Released artifact contract

`released` remains unchanged. The active-version tag must exist, be annotated,
and peel exactly to `HEAD`. No descendant or branch inference satisfies this
state.

## Post-release-closed contract

Inference checks `released` first. It selects `post-release-closed` only when:

- the active-version tag exists and is annotated;
- its peeled target differs from `HEAD`;
- `git merge-base --is-ancestor <tag-target> HEAD` succeeds; and
- context is `main`, exact `release/v{version}`, or an accepted authoritative
  same-repository post-release pull request.

The post-release PR event path must be readable valid JSON. Its base must be
`main`; payload and `GITHUB_HEAD_REF` must both equal
`release/v{version}`; and `pull_request.head.repo.full_name` must equal the
nonempty `GITHUB_REPOSITORY`. Missing or mismatched identity fails closed. The
historical `accepted_release_pr()` behavior for development and pre-release is
unchanged.

Current root and release README sections must say v1.13.14 is published.
Scope, phase list, and validation checklist status must be `Released and
operationally closed`; recognized Phase 0–26 states must all be `Complete`.
The canonical release gate must have exact status `Passed and released` and a
present, nonempty, nonpending `## Final verdict`.

Expected Phase 26 descendant result:

```json
{"status":"ok","validator":"coldkeep-release-state","state":"post-release-closed","active_version":"1.13.14","violations":[],"error":null}
```

No workflow change is required. Existing quality checkout history and the
current release-branch, main, tag, and release-PR invocation contexts supply
the Git and event evidence needed by this contract.
