# Coldkeep v1.13.4 — Validation Checklist

## Per-Phase Documentation Validation

Commands:

```bash
git status -sb
git diff --check
rg -n "TODO|TBD|FIXME" <changed-doc-files>
git status -sb
```

Use the concrete changed doc paths for each phase. If `TODO`, `TBD`, or
`FIXME` appears only because a checklist documents the literal command string,
record that as expected. Otherwise resolve or remove the marker before marking
the phase complete.

## Per-Phase Go Validation

Commands:

```bash
git status -sb
git diff --check
gofmt -l $(git ls-files '*.go')
go test -count=1 ./cmd/coldkeep
go test -count=1 ./internal/engine
go test -count=1 ./internal/observability
go test -count=1 ./internal/snapshot
go test -count=1 ./internal/catalog
go test -count=1 ./...
go test -race -count=1 ./...
go vet ./...
golangci-lint run ./...
git status -sb
```

Run the targeted package tests that match the touched code in addition to the
repo-wide checks. Do not claim these commands were run in Phase 0 unless a
later code-bearing phase actually executes them.

## Honesty Rules

- Do not mark a command green if it was not run.
- Record blocked commands honestly.
- Record environment and tooling blockers honestly.
- Do not call the release PR-ready until Phase 10 Profile A is complete.
- Do not fabricate CI, benchmark, or matrix results.
- If a command is replaced by an equivalent command, record why.
- Distinguish confirmed code-backed behavior from documented intent.
