## Summary

Phase 13 closes the missing tracker-definition gap after Phase 12.

This phase is docs-only. It does not implement repair or recovery routing,
does not change the active snapshot mutation boundary, and does not change any
runtime behavior.

Its purpose is to define the exact next implementation phase for `v1.13.9`
using the checked-in release documents as the source of truth.

## Current confirmed ownership state

Production CLI mutation ownership remains:

- `snapshot create -> Engine.SnapshotCreate`
- `snapshot delete -> Engine.SnapshotDelete`
- `snapshot restore -> Engine.SnapshotRestore`

Compatibility-only lower-layer seams remain intentionally available for
non-CLI callers and lower-level tests where needed.

## Defined next implementation phase

The next implementation phase after Phase 13 is:

`Phase 14 — Repair and Recovery Boundary Decision`

That phase is expected to align with the broader `v1.13.x` release-train
definition:

- decide whether repair and recovery belong in engine;
- decide whether they remain separate maintenance boundaries;
- or make them explicitly deferred with honest unsupported-boundary behavior.

- `internal/engine`
