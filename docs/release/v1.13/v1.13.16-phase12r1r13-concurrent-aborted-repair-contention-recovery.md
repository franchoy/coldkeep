## Frozen contention protocol

`PROCESSING` is transient contention only when it is attributable to another
Store's normal chunk claim. The repair path returns a private typed contention
result with the chunk identity. One deadline, derived from the existing bounded
chunk-claim polling policy, is shared across all repeated observations.

The caller must release the completed-repair mutex before waiting. It must
never wait while holding a publication transaction, repository advisory lock,
publication row lock, or database lock belonging to the rejected snapshot.
After terminal observation it reacquires serialization and repeats healthy-
reuse validation, recipe validation, placement/accounting validation, and plan
construction entirely from current state. No pre-wait fingerprint, recipe,
placement, or staging decision may be reused.

`COMPLETED` converges through normal healthy reuse and path attachment without
a second publication or additional repair retry increment. `ABORTED` restarts
full validation and may perform one normal atomic repair. That publication
adds one logical retry and one retry per distinct existing chunk actually
repaired, relative to the competitor's terminal state. Repeated recipe
occurrences do not multiply staging or counters. Cancellation and timeout are
bounded and mutation-free. Errors other than the private contention result are
terminal.

## Attempt cleanup boundary

R1R13 introduces no repair-attempt status or schema change.
`REPAIR_ATTEMPT_ABORTED` is an operational disposition, not a persisted state.
If contention is detected before attempt creation, the caller only unlocks and
waits. If the current Store already owns an attempt, publication work first
rolls back; then its quarantined, pre-publication staging is removed using the
existing safe ownership checks and cleanup order. Successful cleanup removes
the attempt-owned files, container rows, staging rows, and attempt row before
unlock-and-wait.

Cleanup failure is terminal. The caller does not wait or retry and leaves the
still `PREPARING` or `READY`, quarantined, positively owned attempt for leased
startup recovery. The old authoritative graph remains unchanged. Historical
schema support and non-contention attempt handling are outside this phase.

## Regression contract

The compiling RED commit asserts observable behavior only and cannot refer to
the private contention type introduced by the implementation commit. It must
prove same-logical and shared-chunk Stores cannot deadlock; `PROCESSING` to

cancellation and timeout are bounded and mutation-free; and successful
convergence leaves no `PROCESSING` chunk or losing live repair attempt. The
existing stress test retains its all-workers-success assertion.
