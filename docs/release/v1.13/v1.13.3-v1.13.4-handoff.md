# Coldkeep v1.13.3 to v1.13.4 Handoff

## Recommended next release

`v1.13.4 — Read-Side Dependency Direction and Result Ownership Review`

## Why v1.13.4 should exist

`v1.13.3` documented the active read-side seams and added boundary and CLI
preservation coverage, but it intentionally did not resolve the ownership seams
across engine, observability, snapshot, renderer, and CLI layers.

`v1.13.4` should exist to review and reduce those ownership seams without
causing public behavior drift.

## Handoff principles

- no public behavior drift
- no JSON drift
- no exit-code drift
- no routing migration without tests
- no SQLite-only assumptions
- no PostgreSQL compatibility removal
- no broad refactor
- no result-shape duplication
- preserve current read-side behavior first

## Candidate v1.13.4 scope

- engine-owned read-side result ownership decision
- `stats` result ownership
- inspect direct observability path
- `snapshot show` mixed metadata, stats, and file-list ownership
- `snapshot diff` provisional query seam
- renderer coupling to observability and snapshot result types
- CLI JSON assembly boundaries
- package dependency direction
- backend compatibility evidence review
- no public behavior drift

## Candidate v1.13.4 non-goals

- no CLI redesign
- no JSON redesign
- no exit-code change
- no schema or storage change
- no SQLite default switch
- no PostgreSQL removal
- no daemon, API, or UI work
- no snapshot mutation implementation
- no broad routing migration unless explicitly scoped and test-protected

## Suggested v1.13.4 phase candidates

1. Scope and ownership baseline docs.
2. Current read-side dependency graph audit.
3. `stats` result ownership decision.
4. Inspect ownership decision.
5. `snapshot show` ownership decision.
6. `snapshot diff` ownership decision.
7. Renderer and result coupling preservation tests.
8. Backend compatibility review updates.
9. Documentation and release gate.
10. `PRE_RELEASE_CHECKLIST.md` execution and PR opening.

This is a proposed starting point, not a binding release plan.

## Risks to carry forward

- routing drift
- result-shape drift
- CLI JSON assembly drift
- renderer coupling drift
- engine narrowing query semantics prematurely
- accidentally changing `snapshot diff` filters
- accidentally hiding backend-specific behavior
- over-refactoring before test protection

## v1.13.3 evidence v1.13.4 should reuse

- Phase 1 inventory
- Phase 2 `stats` contract map
- Phase 3 inspect contract map
- Phase 4 `snapshot show` contract map
- Phase 5 `snapshot diff` contract map
- Phase 6 taxonomy tests
- Phase 7 CLI preservation tests
- Phase 8 backend and dependency review
