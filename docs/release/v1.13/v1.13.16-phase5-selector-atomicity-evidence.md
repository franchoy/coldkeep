## Implemented contract

The Engine snapshot-create route now constructs one accounting entry for each
distinct canonical explicit selector while preserving exact versus prefix
kind. Every eligible `COMPLETED` physical source is evaluated against every
selector in the existing canonical `SelectionBase` namespace. This means an
overlapping source increments each matching selector while still producing
only one member.

After enumeration, unmatched selectors are deduplicated by canonicalization,
sorted deterministically for reporting, and returned as typed `not_found`.
The create transaction then rolls back its provisional snapshot row and cannot
leave membership or operation-created `snapshot_path` rows. Existing shared
path rows remain unchanged. Component-safe prefix matching, collision
classification, full-snapshot behavior, Phase 4 capture-root semantics, and
legacy lower-level compatibility behavior remain unchanged.
