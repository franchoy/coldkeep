# Coldkeep v1.13.6 Validation Checklist

**Release:** `v1.13.6 — Catalog Contract Expansion and Backend Parity Review`  
**Branch:** `release/v1.13.6`  
**Status:** In progress

## Default validation posture

v1.13.6 is review-first and docs-first.

For docs-only phases, required validation is:

- branch/status check
- `git diff --check`
- targeted `rg` checks for required release-doc content
- `TODO|TBD|FIXME` scan over touched release docs
- docs-only drift check

For phases that add tests, required validation expands to:

- `gofmt`
- targeted package tests
- relevant backend-specific or dual-backend tests
- `go test ./...`
- `go vet ./...`
- `golangci-lint run ./...`

The final gate is always:

```text
PRE_RELEASE_CHECKLIST.md Profile A
```

## PostgreSQL requirement

PostgreSQL-backed validation is mandatory in the final release gate.

SQLite-first direction must not remove PostgreSQL compatibility.

## Release-blocking rules

Block release if:

- PostgreSQL-backed validation cannot run
- any production behavior changes without explicit scope
- any schema/storage/repository format change appears unexpectedly
- any public CLI/human/JSON/error/exit contract changes unexpectedly
- any SQLite-only assumption is introduced
- any full release-gate command fails
