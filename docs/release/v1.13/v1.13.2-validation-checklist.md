# v1.13.2 Validation Checklist

## Per-Phase Lightweight Validation

- `git diff --check`
- `git status -sb`
- targeted package tests when Go code changes
- docs `TODO` / `TBD` / `FIXME` checks for changed release docs

## Code-Phase Validation

- `gofmt -l $(git ls-files '*.go')`
- `go test -count=1 ./internal/engine`
- `go test -count=1 ./internal/catalog`
- `go test -count=1 ./cmd/coldkeep`
- additional targeted package tests as touched

## Release-Gate Validation

```bash
git status -sb
git diff --check
gofmt -l $(git ls-files '*.go')
go vet ./...
go test -count=1 ./...
go test -race -count=1 ./...
golangci-lint run ./...
scripts/audit_ci_enforcement.sh
```

- run `PRE_RELEASE_CHECKLIST.md` using `Profile A`
- record `git status -sb` before and after the final validation run
- record the exact command lines executed and whether each command passed, failed, or could not be
  run

## Compatibility Validation

Explicitly confirm that `v1.13.2` preserves:

- CLI behavior unless a later phase explicitly documents a non-user-facing internal classification
  addition
- JSON output
- exit codes
- no schema changes
- no storage format changes
- no repository format changes
- no backend default changes
- PostgreSQL compatibility

## Documentation Validation

- `v1.13.2-scope.md` exists
- `v1.13.2-phase-list.md` exists
- `v1.13.2-validation-checklist.md` exists
- later `v1.13.x` handoff is recorded
- no unresolved `TODO`, `TBD`, or `FIXME` markers remain except where a validation checklist or
  gate document intentionally records the command string itself

## Honesty Rules

- do not mark a gate green if a command was not run
- record unavailable tools or environment limits honestly
- if a command is blocked by the environment, state why
- do not fabricate green validation results
- distinguish confirmed code-backed behavior from documented intent

## Runtime-Change Constraint

`v1.13.2` must preserve current runtime behavior unless a later phase explicitly scopes a narrow
internal classification addition that does not change CLI behavior, JSON output, exit codes,
schema, migrations, storage format, repository format, backend defaults, or PostgreSQL
compatibility.
