## SQLite catalog placement contract

The accepted future local SQLite catalog target is:

`<repository-root>/.coldkeep/catalog.sqlite`

This remains a future local contract target, not a current runtime default.

## Repository portability contract

The accepted portability contract defines a directory-portable repository as a
complete:

`catalog + payload`

generation, not merely a readable SQLite file.

The contract also preserves:

- active versus cleanly closed repository distinction
- checkpoint and sidecar concerns
- destination verification and restore requirements
- directory portability versus PostgreSQL operational portability
- independent writable cloning deferral

## Migration-idempotency defect discovered

During Phase 7 relocation-guard implementation, destination reopen exposed a
real schema-reopen defect:

```text
logical_file.ref_count mismatch: logical_file_id=1 expected=1 actual=2
```

The root cause was that migration looked for absence of a generated synthetic
path rather than absence of any physical mapping for the logical file.

That allowed repeated reopen to add another synthetic mapping to an already
valid logical file.

## Production remediation

`v1.13.7` includes one narrow production behavior correction:

- SQLite backfill now checks whether any `physical_file` mapping exists for the
  `logical_file_id`
- PostgreSQL backfill now uses the same invariant
- existing physical mappings remain unchanged
- one-to-many mappings remain supported
- only legacy unmapped logical files receive one synthetic mapping
- unrelated corruption is not silently repaired
- no global ref-count rewrite was introduced
- no schema version changed

The only production behavior change is a narrow migration-idempotency
correction that preserves valid physical-file mappings during schema reopen.
