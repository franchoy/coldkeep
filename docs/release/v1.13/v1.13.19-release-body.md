## Why this recovery exists

The public one-level annotated `v1.13.18` tag remains object
`e03ede234275ced07b21a00ee9e4bfc539af9446` (A18), directly targeting protected
main commit `ad82794064c31b337949f0aa47c7639ca2f1d9c2` (M18), tree
`0342c2f845a9e6e2f9b7c235fbf3004b271e43c4`. Its natural original-attempt tag
CI run `41330297821` failed the quality job and required aggregate; its separate
CodeQL run `41330297820` passed. No GitHub Release was created for v1.13.18.
The tag, failed run, successful bounded dimensions, and all prior evidence are
preserved rather than rewritten as certification success.

The reproduced failure was a release-test fixture portability defect, not a
product-runtime correction. The affected disposable fixture represented a
pre-release candidate and inherited the
already-public active snapshot tag and production rule CKRS017 correctly
rejected that pre-release state. The correction removes only the active
snapshot tag from the helper's newly created disposable fixture. It does not
delete or move A18, does not alter donor or source refs, retains the historical
v1.13.17 annotated tag A17, and does not weaken or bypass CKRS017 in production
validation.

The correction's first complete 281-test run in the shared workspace was a
truthful NONPASS: a deliberately removed historical fixture reference
reappeared, and its writer remains unidentified. The unchanged correction then
passed the complete 281-test suite in a fresh isolated `/tmp` operation. Both
outcomes and the focused red control remain retained; the isolated pass does
not erase the workspace failure or establish that every environment passes.
The reviewed fixture patch has SHA-256
`ea282d2383e700bee79a5a690590cdc3fa949daecc687dc5ae746fe38bc18220`.
