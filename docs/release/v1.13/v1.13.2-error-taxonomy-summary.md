# Coldkeep v1.13.2 — Error Taxonomy Summary

## Status

`complete`

## Release Objective

`v1.13.2` establishes the first engine/catalog error taxonomy baseline without
changing public behavior.

This release is:

- taxonomy baseline
- contract-language hardening

- full error framework
- full project-wide error wrapping migration
- CLI error redesign
- JSON output redesign
- exit-code redesign
- engine routing migration
- catalog implementation expansion
- deferred operation implementation
- `v2` work

## New Primitives

### `engine.IsUnsupported(err error) bool`

- returns true for `errors.Is(err, engine.ErrNotImplemented)`
- intentionally narrow
- classifies active unsupported engine modes only
- does not classify validation, domain, invariant, runtime, catalog, storage,
  or environment failures
- does not make candidate-only surfaces active

### `catalog.IsDeferred(err error) bool`

- returns true for `errors.Is(err, catalog.ErrNotImplemented)`
- intentionally narrow
- classifies deferred catalog metadata seams only
- does not classify engine unsupported errors
- does not implement catalog graph, placement, restore-plan, or GC-plan
  behavior

## Boundary Protections Added

Tests added or updated across `v1.13.2` protect:

- engine unsupported sentinel behavior
- catalog deferred sentinel behavior
- validation versus unsupported boundaries
- CLI translation preservation

What these protections cover:

- `errors.Is` compatibility remains intact for existing engine/catalog sentinels
- engine and catalog sentinels remain distinct
- unsupported active modes are not validation failures
- malformed requests are not unsupported
- CLI JSON error envelopes do not expose taxonomy fields or helper names
- exit-code mapping remains unchanged

## Public Behavior Preservation

`v1.13.2` does not change:

- CLI behavior
- human output contract
- JSON error envelope
- exit codes
- command routing
- engine routing
- schema/migrations
- storage/repository format
- backend defaults
- CI/scripts

## Remaining Document-Backed Or Provisional Surfaces

- validation taxonomy remains mixed and not unified
- domain taxonomy remains mixed and not unified
- invariant taxonomy remains existing-wrapper-based but not fully unified
- runtime/catalog/storage origins remain mostly mapped, not wrapped
- external/environment remains release-gate/tooling-oriented
- verify category-prefixed failures remain later-decision
- provisional `VerifyResult` remains later-decision
- snapshot diff/query narrowing remains later-decision
- mixed CLI/engine ownership paths remain later-decision
- string-dependent CLI fallback matching remains later-decision
- candidate-only snapshot mutation/repair/recovery surfaces remain inactive

## Risk Controls Established

- avoid broad framework
- avoid taxonomy leakage into public JSON
- avoid exit-code drift
- keep `ErrNotImplemented` sentinel-compatible
- keep engine/catalog sentinels distinct
- avoid collapsing deferred into unsupported
- avoid classifying ordinary not-found as invariant corruption
- avoid classifying invariant failures as domain not-found
- preserve fail-closed invariant behavior
- preserve release-gate honesty around environment failures
