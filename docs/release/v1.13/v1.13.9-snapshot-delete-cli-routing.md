## Old production route

Before Phase 9, production CLI `snapshot delete` used this direct CLI/domain
flow:

```text
runSnapshotDeleteCommand
  -> parser and flag validation
  -> snapshot ID validation
  -> preview-wins mode selection
  -> loadSnapshotDB
  -> db.NewOperationContext
  -> if preview:
       snapshotDeleteLineagePreviewPhase
     else:
       deleteSnapshotPhase
  -> existing human or JSON rendering
```

That route kept snapshot delete outside the active engine boundary even after
Phase 8 activated `Engine.SnapshotDelete`.

## New production route

Phase 9 changes the production CLI path to:

```text
runSnapshotDeleteCommand
  -> parser and flag validation
  -> snapshot ID validation
  -> preview-wins mode selection
  -> require --force when not preview
  -> loadSnapshotDB
  -> newCommandEngine
  -> Engine.SnapshotDelete(ctx, SnapshotDeleteRequest{SnapshotID, Mode})
  -> existing human or JSON rendering through CLI-owned projection
```

The production preview path no longer calls
`snapshotDeleteLineagePreviewPhase`, and the production execute path no longer
calls `deleteSnapshotPhase`.

The legacy snapshot-domain seams remain in-tree for compatibility tests and
direct domain callers, but not for the production CLI path.

## Mode translation

CLI-to-engine translation is frozen as:

- effective `--dry-run` or `--dryRun` true -> `SnapshotDeleteModePreview`
- otherwise effective `--force` true -> `SnapshotDeleteModeExecute`
- otherwise -> unchanged CLI usage error before repository or engine
  initialization

The engine request does not receive CLI booleans.

## Preview-wins and explicit false preservation

Phase 9 preserves:

- preview-wins precedence when both `--force` and `--dry-run` are present
- `--force=false` alone remains a CLI usage error before initialization
- `--dry-run=false` alone remains a CLI usage error before initialization
- blank snapshot ID remains a CLI usage error before initialization
- malformed flag values remain parser/CLI failures before initialization

The engine independently validates normalized snapshot ID and mode for direct
engine callers, but the CLI still owns its pre-initialization validation
surface.

## Preview output projection

Preview routing uses engine raw facts only. The CLI projects:

- `SnapshotDeleteResult.SnapshotID`
- `SnapshotDeletePreviewResult.Parent`
- `SnapshotDeletePreviewResult.Children`
- `SnapshotDeletePreviewResult.TotalFiles`
- `SnapshotDeletePreviewResult.UniqueFiles`
- `SnapshotDeletePreviewResult.SharedFiles`

into the existing dry-run text and JSON output shapes.

Compatibility preserved:

- existing preview heading and field ordering
- `parent_id` / `parent_missing`
- exact child listing
- exact total/unique/shared counts
- missing-parent compatibility note
- metadata-only and no-reclaim wording
- duration and hint lines

## Execute output projection

Execute routing preserves the existing sparse JSON compatibility behavior.

The engine returns:

```text
Mode=execute
Deleted=true
Preview=nil
```

The CLI still emits:

- `action: delete`
- `dry_run: false`
- `parent_id: null`
- `parent_missing: false`
- `children: null`
- `total_files: 0`
- `unique_files: 0`
- `shared_files: 0`
- `warnings: null`

No preview facts are loaded during execute to enrich those fields.

## Warning rendering ownership

Warning rendering remains CLI-owned.

The engine does not return presentation warnings. The CLI derives the existing
`lineage_breakage` warning and the human warning section from
`Preview.Children`.

## Error compatibility

Phase 9 preserves the existing CLI error path by returning engine errors
without adding new wrapper layers in the CLI delete route.

Stable error behavior preserved includes:

- snapshot not found
- invalid snapshot ID
- preview query failures
- live delete failures
- affected-row honesty failures
- transaction failures
- context cancellation

## Create and restore boundaries

Phase 9 changes only CLI `snapshot delete`.

Proof retained:

- `snapshot create` remains routed through `Engine.SnapshotCreate`
- `snapshot restore` remains on its existing direct CLI/domain seam

This phase does not activate or route restore.
