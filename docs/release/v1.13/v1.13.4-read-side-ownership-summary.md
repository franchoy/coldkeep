## Final ownership decisions

### `stats`

Decision:

- keep current ownership unchanged for `v1.13.4`
- treat `engine.StatsResult` wrapping `observability.StatsResult` as a
  documented transitional seam
- observability owns concrete aggregation
- renderer owns human output and success JSON output
- CLI owns public error envelopes
- broad result-shape migration remains deferred

### `inspect`

Decision:

- keep direct `CLI -> observability` routing unchanged for `v1.13.4`
- observability owns inspect logic and the production result type
- public targets remain:
  `repository`, `file`, `logical-file`, `snapshot`, `chunk`, and `container`
- `EntityPhysicalFile` remains internal-only
- renderer owns human output and success JSON output
- CLI owns public error envelopes
- engine-owned inspect seam decision remains deferred

### `snapshot show`

Decision:

- keep mixed ownership unchanged for `v1.13.4`
- metadata and stats remain engine-backed through CLI helpers
- file listing remains snapshot-package-backed
- CLI owns success JSON assembly
- renderer owns human output
- CLI owns public error envelopes
- preserve `matched_file_count` and `total_snapshot_file_count`

### `snapshot diff`

Decision:

- keep split ownership unchanged for `v1.13.4`
- CLI owns validation, richer query parsing, summary fast-path selection,
  filter post-processing, count projection, and success JSON assembly
- engine owns the provisional diff request/routing seam
- snapshot package owns core detailed diff logic
- renderer owns human output
- CLI owns public error envelopes
- preserve `matched_entry_count`, `total_diff_entry_count`, summary/detailed
  behavior, and `entries` inclusion/omission behavior

## Guard coverage added in v1.13.4

Phase 7 added the following narrow CLI guard tests:

- `TestReadSideJSONOwnershipFamiliesRemainDistinct`
  - protects renderer-envelope success JSON for `stats` / `inspect` versus
    CLI-envelope success JSON for `snapshot show` / `snapshot diff`
- `TestReadSideJSONErrorsRemainCLIEnvelopeOwned`
  - protects the CLI-owned JSON error envelope family across representative
    read-side failures
- `TestInspectPublicTargetsRemainDocumentedSet`
  - protects the public inspect target list, the `logical-file` alias, and
    `physical-file` remaining unsupported publicly
- `TestReadSideOutputDoesNotLeakTaxonomyHelperNames`
  - protects representative success and error payloads from leaking internal
    taxonomy helper terminology

## Final release note

The original `v1.13.4` scope was documentation plus narrow guard tests.
During PR validation, `v1.13.4` also included narrow production hardening for:

- database environment integer parsing in `internal/db/db.go`
- `verify file` fileID bounds validation in `cmd/coldkeep/main.go`

These changes were narrow validation/static-analysis hardenings and did not
intentionally change public CLI behavior, JSON output, error envelopes,
routing, schema, storage format, repository format, or backend defaults.
