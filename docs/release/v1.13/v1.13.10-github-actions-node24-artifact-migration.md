# Coldkeep v1.13.10 Phase 6 — GitHub Actions Node 24 Artifact Migration

## Purpose

Phase 6 moves all current Coldkeep CI artifact uploads to the current
Node.js 24-compatible `actions/upload-artifact@v7` major. This is workflow
runtime maintenance, not an artifact-policy redesign.

## Baseline inventory

Before this phase, `.github/workflows/ci.yml` contained exactly five
`actions/upload-artifact@v5` uses and no v6 or v7 uses:

| Job | Step | Artifact name | Path |
| --- | --- | --- | --- |
| `correctness-matrix` | Upload correctness-matrix diagnostic JSON | `correctness-matrix-diag-${{ matrix.codec }}` | `${{ runner.temp }}/integration-diag/*.json` |
| `adversarial` | Upload G6 failure diagnostics | `g6-failure-${{ matrix.codec }}-${{ runner.os }}-${{ github.run_id }}-${{ github.run_attempt }}` | `${{ runner.temp }}/g6-failure-artifacts` |
| `smoke` | Upload smoke artifacts on failure | `smoke-artifacts-${{ matrix.codec }}` | `${{ github.workspace }}/.ci-storage/${{ matrix.codec }}` |
| `benchmark-matrix` | Upload benchmark outputs | `benchmark-matrix-${{ matrix.compression }}` | the four benchmark and regression JSON paths selected by the compression matrix |
| `critical-coverage-report` | Upload critical coverage report | `v1.10.7-critical-coverage-report` | `docs/release/v1.10/v1.10.7-ci-coverage-report.csv` |

The baseline had no `archive:` input.

## Selected action version

`actions/upload-artifact@v7` is the selected current major for the Node.js 24
runtime. The migration skips the superseded v6 target, adopts no new v7
functionality, and leaves the existing archive behavior unchanged because no
`archive` input was added.

## Migrated upload steps

All five existing upload steps were migrated in place:

1. `correctness-matrix` — `Upload correctness-matrix diagnostic JSON`.
2. `adversarial` — `Upload G6 failure diagnostics`.
3. `smoke` — `Upload smoke artifacts on failure`.
4. `benchmark-matrix` — `Upload benchmark outputs`.
5. `critical-coverage-report` — `Upload critical coverage report`.

## Preserved artifact semantics

The exact pre-change and post-change workflow comparison found five changed
lines, each changing only `actions/upload-artifact@v5` to
`actions/upload-artifact@v7`. Artifact names, paths, conditions, retention,
compression, no-files-found behavior, hidden-file behavior, overwrite
behavior, the job graph, and the trigger graph are preserved. The existing
`continue-on-error` behavior on the G6 diagnostic upload is also unchanged.

## CI audit enforcement

`scripts/audit_ci_enforcement.sh --local-only` now requires exactly five
`actions/upload-artifact@v7` uses, zero v5 uses, and zero v6 uses. The audit
continues to protect the Phase 5 full-history checkout, blocking fixture-test
step, and context-gated blocking real-repository validator step.

## Explicit non-changes

- no runtime source or tests;
- no validator behavior;
- no artifact input, naming, or path change;
- no download action change;
- no workflow trigger, permission, job dependency, or graph change;
- no schema or migration;
- no PR, tag, or release operation.

## Validation evidence

- The workflow contains exactly five `actions/upload-artifact@v7` uses and zero
  v5/v6 uses.
- The exact workflow comparison proves five and only five version-token
  substitutions.
- No `archive:` input was introduced.
- Shell syntax, the local CI audit, smart-quote, validation-matrix, and
  versioned-row-writer checks passed.
- Phase 5 validator tests and the real-repository validator passed unchanged.
