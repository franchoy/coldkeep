## 2. Four-file core repair

`scripts/validate_release_linearity.sh` now accepts
`--candidate-ref <commit-or-ref>`, defaulting to `HEAD`. It resolves the
requested object as a commit, reports the requested ref and normalized SHA,
and uses that SHA for both `merge-base` and `rev-list --merges`.

`scripts/audit_ci_enforcement.sh` keeps ordinary local, release-push, and
release-tag validation on `HEAD`, and skips release-linearity for non-release
PRs. A release PR fails closed unless its event is readable valid JSON, its
base is `main`, its head ref matches `GITHUB_HEAD_REF`, its head repository
equals `GITHUB_REPOSITORY`, and its head SHA is lowercase full-length and
locally resolvable as a commit. Only that event head SHA is supplied through
`--candidate-ref`. There is no fallback to synthetic `HEAD`, `HEAD^2`, or a
branch-name inference.

The deterministic test additions cover direct, inherited-main,
independently-advanced-main, release-local merge, missing origin/main,
unrelated history, synthetic merge with authoritative candidate, malformed
arguments, non-commit objects, same-repository PR identity, wrong base, fork,
mismatched head ref, missing/malformed event data, missing repository,
uppercase/missing/non-string/invalid/unresolvable SHA, wrong event type,
ordinary release push/tag, and non-release PR skip behavior.
