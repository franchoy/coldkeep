## Key Changes Summary

- 37 boundary targets were inventoried and constrained as the Phase 1 source of truth.
- Active engine unsupported modes were tested and locked behind explicit unsupported behavior.
- Catalog deferred methods were tested for explicit deferred failure, nil results, and no obvious mutation.
- Candidate-only engine contracts were clarified so their type presence no longer implies active support.
- Partial routing seams were documented and tested without adding new routing.
- Request/result support surfaces were clarified where exported shapes overstated active ownership.
- CLI transitional ownership was preserved and test-backed.
- The Phase 8 boundary summary turned the release into a clean `v1.13.2` handoff.

## Boundary Coverage Summary

- recursive `Engine.Store`
- stored-path `Engine.Restore`
- stored-path and stored-paths `Engine.Remove`
- deferred catalog graph / placement / restore-plan / GC-plan surfaces
- snapshot create / delete / restore candidate contracts
- repair / recover candidate contracts
- partial `inspect`, `snapshot show`, `snapshot diff`, `restore`, and `remove` routing
- request/result support-surface limitations
- CLI-owned snapshot mutation, repair, and recovery paths

## Remaining Intentional Gaps

- no recursive store implementation
- no stored-path restore/remove engine implementation
- no snapshot mutation engine implementation
- no repair/recovery engine implementation
- no deferred catalog graph/placement/restore-plan/GC-plan implementation
- no daemon/API/UI/v2 work
- no SQLite default switch
- no PostgreSQL compatibility removal

## v1.13.2 Handoff Summary

`v1.13.2` should take `v1.13.1` as the explicit boundary baseline and focus on engine error taxonomy.

- define stable unsupported / deferred / validation / domain / runtime / invariant distinctions
- preserve `ErrNotImplemented` as distinct from validation failure and runtime failure
- avoid broad routing changes while error categories are being stabilized
- avoid CLI behavior drift
- preserve JSON output and exit-code behavior
- prepare later releases to route or split contracts safely using explicit unsupported boundaries
