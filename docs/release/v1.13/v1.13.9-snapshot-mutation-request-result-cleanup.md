## Purpose

Freeze the structural snapshot mutation request/result surface in code so the
candidate types now match the Phase 2, Phase 3, and Phase 4 contract
documents exactly, while leaving all snapshot mutation runtime behavior
inactive and unchanged.

Phase 5 freezes the structural snapshot mutation contract surface. It does not
implement or activate snapshot mutation engine methods.

## Starting candidate-shape problems

Before Phase 5:

- `SnapshotCreateResult` still exposed speculative generic warnings.
- `SnapshotDeleteRequest` still used contradictory `Force` / `DryRun`
  booleans.
- `SnapshotDeleteResult` still exposed preview-shaped top-level fields rather
  than a preview/live split.
- delete parent state still leaked as `ParentID` plus `ParentMissing` instead
  of an explicit renderer-neutral parent model.
- `SnapshotRestoreRequest` still used flat `DestinationMode`, `Destination`,
  `Strict`, `NoMetadata`, and the narrower read-side `SnapshotQuery`.
- `SnapshotRestoreResult` still exposed CLI-owned `Type`, ambiguous
  `OutputRoot`, generic warnings, and `int` restore counts.
- repeated restore exact-path and prefix selectors could not be represented
  without narrowing.

## Final create contract surface

Frozen create request:

```go
type SnapshotCreateRequest struct {
	ID       string
	Label    string
	ParentID string
	Paths    []string
}
```

Frozen create result:

```go
type SnapshotCreateResult struct {
	SnapshotID    string
	Type          SnapshotType
	PathsCount    int
	FilesInserted int
	Label         string
	ParentID      string
}
```

Phase 5 cleanup:

- preserved caller-supplied or generated-ID representability through `ID`;
- preserved full versus partial derivation through `Paths`;
- kept `SnapshotType` in the result only, not the request; and
- removed speculative create-result warnings.

Phase 5 cleanup:

- introduced a restore-specific selection type instead of reusing read-side
  `SnapshotQuery`;
- preserved repeated exact-path and repeated prefix selectors as `[]string`;
- moved destination shape into an explicit destination object;
- replaced contradictory `Strict` / `NoMetadata` booleans with one metadata
  mode;
- replaced generic `OperationWarning` with restore-specific structured warning
  types; and
- removed CLI-owned `Type` and ambiguous `OutputRoot` from the result.

## Repeated-selector preservation and renderer neutrality

Phase 5 explicitly preserved:

- restore positional `Paths` separately from query-style selection;
- repeated restore exact-path selectors as `[]string`;
- repeated restore prefixes as `[]string`;
- regex crossing the boundary as `string`;
- size and time bounds as pointer types so unset remains distinct; and
- renderer-neutral warning and preview data rather than human or JSON output
  envelopes.

## Backend neutrality and non-activation

Phase 5 preserved backend-neutral contract structure:

- no snapshot mutation request/result type exposes `*sql.DB`, `sql.Tx`,
  `sql.NullString`, driver types, `storage.StorageContext`, filesystem handles,
  or output writers;
- the active `Engine` interface still excludes `SnapshotCreate`,
  `SnapshotDelete`, and `SnapshotRestore`; and
- active `DefaultEngine` methods still do not consume the cleaned snapshot
  mutation request types.

Current runtime remains unchanged:

- CLI still owns snapshot mutation parsing, routing, output, and direct
  snapshot-package calls;
- snapshot create/delete/restore domain execution remains inactive in the
  engine; and
- no snapshot mutation method was added to `Engine` or `DefaultEngine`.
