# Coldkeep v1.13.8 By-ID Contract Narrowing

**Release:** `v1.13.8 — Restore / Remove Contract Split and Stored-Path Boundary`
**Phase:** `Phase 5`
**Status:** Complete
**Branch:** `release/v1.13.8`
**Starting commit:** `06167ae15f7bd120ecfdce92850a1d7cfc25c7cb`

## Summary

Phase 5 narrowed the active engine restore and remove contracts to the by-ID
semantics they actually implement today.

The active engine surface no longer carries restore/remove addressing-mode enums
or stored-path-only fields. Stored-path restore, single stored-path remove, and
stored-path batch remove remain intentionally direct CLI/storage paths after
this phase.

## Contract Changes

- removed `RestoreMode`, `RestoreModeFileIDs`, and `RestoreModeStoredPath`
- removed `RemoveMode`, `RemoveModeFileIDs`, `RemoveModeStoredPath`, and
  `RemoveModeStoredPaths`
- narrowed `RestoreRequest` to `FileIDs`, `DestinationRoot`, `Overwrite`,
  `DryRun`, and `FailFast`
- renamed restore item output from `OutputPath` to `DestinationPath`
- narrowed `RemoveRequest` to `FileIDs`, `DryRun`, and `FailFast`
- renamed by-ID remove result fields from `RemovedMappings` and `Removed` to
  `RemovedChunkAssociations` and `LogicalFileRemoved`
- removed `RemoveResult.Warnings` because active by-ID remove does not assign
  it meaning

## Behavioral Outcome

- `Engine.Restore` is now a by-ID-only contract
- `Engine.Remove` is now a by-ID-only contract
- by-ID runtime behavior remains sequential and unchanged
- by-ID dry-run and fail-fast semantics remain unchanged
- stored-path CLI restore remains direct CLI/storage
- single stored-path CLI remove remains direct CLI/storage
- batch stored-path CLI remove remains direct CLI/storage

## Compatibility Notes

- CLI syntax did not change
- human output did not change
- JSON output did not change
- exit behavior did not change
- retention, GC ownership, schema, backend behavior, and repository/storage
  formats did not change
