## Phase 4 — Restore/remove contract-split design

**Status:** Complete

Created `v1.13.8-restore-remove-contract-design.md`.

Phase 4 fixed the implementation target:

- by-ID `Restore` and `Remove` requests become mode-free;
- stored-path restore receives a dedicated single-operation engine method;
- stored-path removal receives one dedicated batch-capable engine method;
- destination root and exact destination path become distinct fields;
- batch-input file reading remains CLI-owned;
- stored-path trim, invalid-target, duplicate, and batch fail-fast behavior
  becomes engine-owned;
- internal result fields become entity-specific and honest;
- CLI syntax, human output, JSON output, ordering, exit behavior, retention
  policy, GC ownership, backend behavior, and formats remain compatible;
- Phases 5 through 8 now have a fixed implementation sequence.

No implementation or observable behavior changed.
