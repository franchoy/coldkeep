# v1.13.17 Release-State Validator Contract

**Merge-complete phase:** 5
**Tag/publication phase:** 8
**Post-publication closure phase:** 9
**Lifecycle declaration model:** immutable-transition-v1
**Canonical repository:** franchoy/coldkeep
**Predecessor disposition model:** failed-publication-predecessor-v1

## Selected predecessor

The exact ordered predecessor disposition selects the immediate dated
`[failed-publication-predecessor]` changelog entry. It is not an ordinary
operationally closed predecessor and cannot fall back to that route. An
unselected disposition, including a dangling symlink, belongs to CKRS019.
Selected absent, unsafe, unreadable, malformed, or inconsistent disposition
input belongs to CKRS010.

The selected canonical path is opened relative to checked repository
directories without following symlinks. The opened descriptor must describe a
regular file. At most 65,537 bytes are read, the maximum accepted size is
65,536 bytes measured before decoding, and parsing consumes those captured
bytes without reopening the path. Directories, symlinks, special files,
replacement/type races, invalid UTF-8, UTF-8 BOM, CR/CRLF, open/read errors,
and oversize input fail closed. There is no unchecked or network fallback.

## Immutable-state projection and tag identity

The immutable lifecycle adds these structural, non-authorizing projections:
`merged-pending-final-main-certification`,
`tagged-pending-tag-certification`, and
`post-release-closure-candidate`. They do not establish hosted
certification, authorization, publication, or terminal closure.

For the selected active-version annotated tag, raw runtime SHA and event
`after` may independently be the exact merge commit M or the exact named
annotated tag object A. Diagnostic classification is respectively
`EXACT_COMMIT_M` or `EXACT_NAMED_TAG_A`; both resolve to checkout HEAD M. The
evaluator rejects lightweight, nested, alternate, missing, replaced, grafted,
shallow, or alternate-object-store observations. M must have exactly two
distinct ordered parents B,C, B must be a strict ancestor of C, and
`tree(M)=tree(C)`. An unavailable Git observation is `UNAVAILABLE`, not an
ordinary negative; a proven wrong relation is `FAIL`.

## Diagnostic v2 closed schema

The artifact schema literal is `coldkeep-release-state-diagnostic/v2`.
`validator.result` is `ok` only for exit 0 and `error` for exit 1 or 2. This
does not rename ordinary CLI JSON status. Predicate and evaluation results use
only `PASS`, `FAIL`, `NOT_EVALUATED`, and `UNAVAILABLE`.

The top-level object has exactly these keys:

```text
schema created_at_utc validator attribution event_snapshots evaluations capture
```

`schema` and `created_at_utc` are strings, with the latter an UTC RFC3339
second-resolution timestamp. `validator` has exactly:

```text
requested_state resolved_state result exit_code rule_codes
authorization_status certification_status checkout_commit checkout_tree sources
```

`requested_state` is `auto` or one of the ten lifecycle states accepted by
`--state`; `resolved_state` is one of those ten states excluding `auto`, or
null on an internal/setup error. `result` is `ok` exactly with exit 0 and is
`error` with exit 1 or 2. `checkout_commit` and `checkout_tree` are 40
lowercase hexadecimal strings or null. `rule_codes` is a sorted unique array
of 0 through 18 values drawn only from `CKRS002` through `CKRS019`; it is empty
on success and on an internal/setup error. The two status strings remain
`NOT_EVALUATED_BY_VALIDATOR` and `PENDING_EXTERNAL_EVIDENCE`.
`sources` contains exactly two records, for
`scripts/release_state_support.py` and
`scripts/validate_release_state.py`, each with exactly:

```text
path loaded_path_match git_blob measured_git_blob measured_sha256
matches_git_blob bytes
```

The array cardinality is exactly 2 and order is the order above. `path` is the
corresponding literal. `loaded_path_match` and `matches_git_blob` are boolean
or null. `git_blob` and `measured_git_blob` are 40 lowercase hexadecimal
strings or null; `measured_sha256` is 64 lowercase hexadecimal or null; and
`bytes` is a nonnegative integer or null. A complete source record has all
measurements, both booleans true, and the measured Git blob equal to `git_blob`.
Loaded bytes are measured independently from the Git blob and a dirty or
synthetic source leaves capture incomplete.

`attribution` has exactly `repository`, `run_id`, `run_attempt`, `job`,
`workflow`, and `event_name`. Each is a bounded identity object. The successful
exposed values are respectively canonical repository; one or more decimal
digits; one or more decimal digits; `quality`; `CI`; and `pull_request` or
`push`.

Every bounded identity has exactly `category`, `type`, `length`, `sha256`, and
`value`. Its complete scalar rules are:

Each event snapshot has exactly:

```text
id route selector safe_basename path_string_sha256 present readable
size_bytes content_sha256 size_limit_bytes size_limit_status utf8_status

```

The snapshot scalar contract is:

| Field | Type and values |
|---|---|
| `id` | positive integer equal to one-based array position |
| `route` | `release-pr`, `release-push`, or `tag-push` |
| `selector` | exact `GITHUB_EVENT_PATH` |
| `safe_basename` | bounded identity expecting `event.json` |
| `path_string_sha256` | exactly 64 lowercase hexadecimal characters, hashing the original path string bytes |
| `present` | false for not found, true after a read, null before observation or for another read error |

| `size_bytes` | nonnegative integer for complete consumed bytes; null before read and for oversized tag input |
| `content_sha256` | 64 lowercase hexadecimal for complete consumed bytes; otherwise null |
| `size_limit_bytes` | 1,048,576 for tag push; null for both non-tag routes |
| `size_limit_status` | `PASS` or `FAIL` after tag read; otherwise `NOT_EVALUATED` |
| `utf8_status`, `json_status` | `PASS`, `FAIL`, or `NOT_EVALUATED` in processing order |
| `top_level_shape` | `unavailable` before parse, else `null`, `boolean`, `integer`, `number`, `string`, `array`, `object`, or `other` |

Tag `projection` has exactly `ref`, `before`, `after`, `created`, `deleted`,
`forced`, and `repository`; all seven values are bounded identities. Non-tag
projection has exactly `repository`, `number`, `pull_request_shape`,
`base_shape`, `head_shape`, `base_ref`, `base_sha`, `base_repository`,
`head_ref`, `head_sha`, `head_repository`, `merge_member`, `merge_type`, and
`merge_value`. Its repository/ref/SHA/number/merge-value members are bounded
identities. The three shape members are type-name strings; `merge_member` is
`present`, `missing`, or `unavailable`; and `merge_type` is a type-name string
or `absent`/`unavailable`.

Tag event input is read once with a 1,048,577-byte budget and has a
1,048,576-byte acceptance limit. At or below the limit, `size_bytes` and
`content_sha256` describe the complete consumed event. Above it, the read
establishes only that the event is oversized, so both whole-event fields are
null, `size_limit_status` is `FAIL`, and UTF-8/JSON remain `NOT_EVALUATED`.
No prefix measurement is represented as a whole-event measurement.
Non-tag `size_limit_bytes` is null and `size_limit_status` is
`NOT_EVALUATED`; its unrestricted read means `size_bytes` has no producer
maximum. Every `_load_event` call creates at most one snapshot. A failure
before `_load_event` creates none; a missing/unreadable event still creates one.

Each evaluation has exactly:

```text
id site route sequence event_snapshot_id runtime_context result
first_rejecting_predicate predicates
```

`id` and `sequence` are the same positive integer and equal the one-based array
position. `site` is one of the literal route/site combinations below. `route`
is the corresponding `release-pr`, `release-push`, or `tag-push` value.
`event_snapshot_id` is null when that evaluation did not call `_load_event`,
otherwise it identifies exactly one snapshot; a snapshot is linked from
exactly one evaluation. `result` is `PASS`, `FAIL`, or `UNAVAILABLE`.
`first_rejecting_predicate` is the first `FAIL` predicate ID or null; null does
not mean PASS. PASS requires the applicable nonempty complete inventory,
expected site/route/snapshot, every required predicate PASS, exit 0, result
`ok`, and complete capture. Each predicate record has exactly:

```text
id source_path source_sha256 source_line input_source required_relation
result observed
```

`id` is the literal inventory ID. `source_path` is exact
`scripts/release_state_support.py`; `source_sha256` is that loaded source's
64-lowercase-hexadecimal digest or null; `source_line` is positive or null.
`input_source` and `required_relation` are the literal inventory values.
`result` is `PASS`, `FAIL`, `NOT_EVALUATED`, or `UNAVAILABLE`; `observed` is
one bounded identity. A first actual FAIL is recorded; all later inventory
members are `NOT_EVALUATED`. An unavailable predicate has result
`UNAVAILABLE`, leaves first rejector null, and later members are
`NOT_EVALUATED`.

Tag runtime context has exactly `github_actions`, `event_name`, `full_ref`,
`short_ref`, `ref_type`, `repository`, `runtime_sha`,

All tag context members except `isolation` and `checkout_parents` are bounded
identities. `isolation` has exactly `shallow`, `alternates`, `grafts`, and
`replacements`, each boolean or null. `checkout_parents` has cardinality 0
before observation and 0..2 afterward because only the first two observed
parents are retained; a successful tag evaluation has exactly 2 distinct
ordered 40-hexadecimal parents. `first_parent_tree` and `second_parent_tree`

Release-PR runtime context has exactly `github_actions`, `event_name`,
`full_ref`, `short_ref`, `head_ref`, `base_ref`, `repository`, `runtime_sha`,
`actual_checkout_commit`, `actual_branch`, `checkout_parents`,
`checkout_tree`, `payload_head_tree`, and `object_availability`.
All noncollection PR context members are bounded identities.
`checkout_parents` is empty before synthetic topology inspection and for a
direct-head route. At synthetic inspection it preserves the complete ordered

The route/site and document cardinalities are:

| Invocation path | Sites in order | Evaluations | Snapshots |
|---|---|---:|---:|

`source-attribution-unavailable`,
`event-snapshot-unavailable`, `predicate-recording-unavailable`,
`diagnostic-construction-unavailable`, `output-size-limit`, and

## Serialization and authority boundary

The diagnostic is one UTF-8 JSON line plus LF, at most 262,144 encoded bytes,
installed exclusively with mode 0600. Capture is best effort and cannot alter
the validator's stdout, stderr, or exit status except for the fixed bounded
warning if diagnostic construction or writing fails. It includes no full
event, environment, credentials, private paths, arbitrary exception text, or
network-derived authority.

All validator and diagnostic outputs are structural and non-authorizing.
External review, protected merge, hosted certification, tag creation,
publication, and terminal closure remain separately owned.
