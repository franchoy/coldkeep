# v1.13.17 Release-State Validator Contract

**Merge-complete phase:** 5
**Tag/publication phase:** 8
**Post-publication closure phase:** 9
**Lifecycle declaration model:** immutable-transition-v1
**Canonical repository:** franchoy/coldkeep
**Predecessor disposition model:** failed-publication-predecessor-v1

## Selected predecessor

The exact ordered predecessor disposition selects the immediate dated
`[failed-publication-predecessor]` changelog entry. It is not an ordinary
operationally closed predecessor and cannot fall back to that route. An
unselected disposition, including a dangling symlink, belongs to CKRS019.
Selected absent, unsafe, unreadable, malformed, or inconsistent disposition
input belongs to CKRS010.

The selected canonical path is opened relative to checked repository
directories without following symlinks. The opened descriptor must describe a
regular file. At most 65,537 bytes are read, the maximum accepted size is
65,536 bytes measured before decoding, and parsing consumes those captured
bytes without reopening the path. Directories, symlinks, special files,
replacement/type races, invalid UTF-8, UTF-8 BOM, CR/CRLF, open/read errors,
and oversize input fail closed. There is no unchecked or network fallback.

## Immutable-state projection and tag identity

The immutable lifecycle adds these structural, non-authorizing projections:
`merged-pending-final-main-certification`,
`tagged-pending-tag-certification`, and
`post-release-closure-candidate`. They do not establish hosted
certification, authorization, publication, or terminal closure.

For the selected active-version annotated tag, raw runtime SHA and event
`after` may independently be the exact merge commit M or the exact named
annotated tag object A. Diagnostic classification is respectively
`EXACT_COMMIT_M` or `EXACT_NAMED_TAG_A`; both resolve to checkout HEAD M. The
evaluator rejects lightweight, nested, alternate, missing, replaced, grafted,
shallow, or alternate-object-store observations. M must have exactly two
distinct ordered parents B,C, B must be a strict ancestor of C, and
`tree(M)=tree(C)`. An unavailable Git observation is `UNAVAILABLE`, not an
ordinary negative; a proven wrong relation is `FAIL`.

## Diagnostic v2 closed schema

The artifact schema literal is `coldkeep-release-state-diagnostic/v2`.
`validator.result` is `ok` only for exit 0 and `error` for exit 1 or 2. This
does not rename ordinary CLI JSON status. Predicate and evaluation results use
only `PASS`, `FAIL`, `NOT_EVALUATED`, and `UNAVAILABLE`.

The top-level object has exactly these keys:

```text
schema created_at_utc validator attribution event_snapshots evaluations capture
```

`schema` and `created_at_utc` are strings, with the latter an UTC RFC3339
second-resolution timestamp. `validator` has exactly:

```text
requested_state resolved_state result exit_code rule_codes
authorization_status certification_status checkout_commit checkout_tree sources
```

`requested_state` and `result` are strings; `resolved_state`,
`checkout_commit`, and `checkout_tree` are string or null; `exit_code` is 0,
1, or 2; `rule_codes` is a sorted unique string array. The two status strings
remain `NOT_EVALUATED_BY_VALIDATOR` and `PENDING_EXTERNAL_EVIDENCE`.
`sources` contains exactly two records, for
`scripts/release_state_support.py` and
`scripts/validate_release_state.py`, each with exactly:

```text
path loaded_path_match git_blob measured_git_blob measured_sha256
matches_git_blob bytes
```

Boolean fields may be null when unavailable; object IDs and digests are
lowercase hexadecimal strings or null; `bytes` is a nonnegative integer or
null. Loaded bytes are measured independently from the Git blob and a dirty or
synthetic source leaves capture incomplete.

`attribution` has exactly `repository`, `run_id`, `run_attempt`, `job`,
`workflow`, and `event_name`. Each is a bounded identity object. Every bounded
identity has exactly `category`, `type`, `length`, `sha256`, and `value`.
Validated exposed strings are at most 256 characters; other values expose
type, optional length, and a SHA-256 rather than arbitrary content. A value is
otherwise string, positive integer, or null according to the producer's
declared allowlist.

Each event snapshot has exactly:

```text
id route selector safe_basename path_string_sha256 present readable
size_bytes content_sha256 size_limit_bytes size_limit_status utf8_status
json_status top_level_shape projection
```

`id` is a positive sequence integer; `route` is `release-pr`,
`release-push`, or `tag-push`; `selector` is `GITHUB_EVENT_PATH`;
`safe_basename` is a bounded identity; `path_string_sha256` is lowercase
SHA-256; `present` is boolean or null; `readable` is boolean. Status fields use
`PASS`, `FAIL`, or `NOT_EVALUATED`; shape is a bounded type name. Tag
`projection` has exactly `ref`, `before`, `after`, `created`, `deleted`,
`forced`, and `repository`. Non-tag projection has exactly `repository`,
`number`, `pull_request_shape`, `base_shape`, `head_shape`, `base_ref`,
`base_sha`, `base_repository`, `head_ref`, `head_sha`, `head_repository`,
`merge_member`, `merge_type`, and `merge_value`.

Tag event input is read once with a 1,048,577-byte budget and has a
1,048,576-byte acceptance limit. At or below the limit, `size_bytes` and
`content_sha256` describe the complete consumed event. Above it, the read
establishes only that the event is oversized, so both whole-event fields are
null, `size_limit_status` is `FAIL`, and UTF-8/JSON remain `NOT_EVALUATED`.
No prefix measurement is represented as a whole-event measurement.
Non-tag `size_limit_bytes` is null and `size_limit_status` is
`NOT_EVALUATED`.

Each evaluation has exactly:

```text
id site route sequence event_snapshot_id runtime_context result
first_rejecting_predicate predicates
```

IDs and sequence are positive integers; snapshot ID is a positive integer or
null; the first rejecting predicate is an inventory ID or null. Null does not
mean PASS. PASS requires the applicable nonempty complete inventory, expected
site/route/snapshot, every required predicate PASS, exit 0, result `ok`, and
complete capture. Each predicate record has exactly:

```text
id source_path source_sha256 source_line input_source required_relation
result observed
```

Source line is a positive integer or null and `observed` is one bounded
identity. A first actual FAIL is recorded; later predicates are
`NOT_EVALUATED`. Failed observations remain `UNAVAILABLE` where the required
relation could not be observed.

Tag runtime context has exactly `github_actions`, `event_name`, `full_ref`,
`short_ref`, `ref_type`, `repository`, `runtime_sha`,
`actual_checkout_commit`, `actual_branch`, `checkout_tree`, `selected_ref`,
`tag_object`, `tag_object_type`, `direct_target`,
`direct_target_declared_type`, `direct_target_actual_type`,
`runtime_sha_classification`, `runtime_sha_resolved_commit`, `event_after`,
`event_after_classification`, `event_after_resolved_commit`, `isolation`,
`checkout_parents`, `first_parent_tree`, and `second_parent_tree`.
`isolation` has exactly `shallow`, `alternates`, `grafts`, `replacements`,
each boolean or null; parent/object collections are bounded to the observed
roles required by the evaluation.

Release-PR runtime context has exactly `github_actions`, `event_name`,
`full_ref`, `short_ref`, `head_ref`, `base_ref`, `repository`, `runtime_sha`,
`actual_checkout_commit`, `actual_branch`, `checkout_parents`,
`checkout_tree`, `payload_head_tree`, and `object_availability`.
Release-push uses that non-tag closed shape and its five-predicate inventory.

`capture` has exactly `complete`, `incomplete_reasons`, `same_process`,
`network_lookups`, `whole_event_included`, `whole_environment_included`, and
`non_authorizing`. The fixed values are same-process true, network lookups 0,
whole event/environment false, and non-authorizing true. The only incomplete
reasons are `source-attribution-unavailable`,
`event-snapshot-unavailable`, `predicate-recording-unavailable`,
`diagnostic-construction-unavailable`, `output-size-limit`, and
`tag-observation-unavailable`. The array is unique and bounded by that six-item
vocabulary.

## Serialization and authority boundary

The diagnostic is one UTF-8 JSON line plus LF, at most 262,144 encoded bytes,
installed exclusively with mode 0600. Capture is best effort and cannot alter
the validator's stdout, stderr, or exit status except for the fixed bounded
warning if diagnostic construction or writing fails. It includes no full
event, environment, credentials, private paths, arbitrary exception text, or
network-derived authority.

All validator and diagnostic outputs are structural and non-authorizing.
External review, protected merge, hosted certification, tag creation,
publication, and terminal closure remain separately owned.
