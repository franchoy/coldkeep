## 2. Frozen contracts

For `CK-V1-AUD-010`, `TotalEntryCount` is the complete raw diff population
before SnapshotQuery and change filtering. `MatchedEntryCount` and `Summary`
describe the complete query-and-change-filtered population before Limit.
Detailed `Entries` are the first N matches ordered by normalized stored path;
zero means unlimited and a negative value is `invalid_argument`. Summary mode
returns no entries and remains independent of positive Limit.

For `CK-V1-AUD-012`, `SnapshotMeta.FileCount` is the count of persisted
`snapshot_file` memberships for that exact snapshot. It is independent of
SnapshotShow selectors, file Limit, current physical-file existence, and
lineage reuse. Find, unlimited/limited list, graph, and tree projections must
carry the count through existing backend-neutral queries without a new Catalog
method, schema change, or N+1 query loop.

## 3. Pre-change SnapshotDiff pipeline map

| Stage | Phase 8 behavior | Defect |
| --- | --- | --- |
| Request validation | IDs, change filter, and Phase 8 selector validated | negative Limit accepted |
| Raw diff | `snapshot.DiffSnapshots` received the normalized selector | unfiltered total population no longer available |
| Change filter | Engine removed nonmatching change classes | correct ordering relative to selector |
| Summary | Engine aggregated change-filtered entries | correct population before Limit, but Limit was absent |
| Count | `MatchedEntryCount=len(entries)` and `TotalEntryCount=len(raw.Entries)` | total meant post-query count |
| Sort | lower diff happened to return stored-path order | Engine projection did not enforce the frozen key |
| Limit | absent | all matched entries returned |
| Summary fast path | SQL aggregate for empty query/filter | correct for Limit zero only |

The final detailed path obtains the selector-filtered population once. When a
selector is present it independently obtains the complete raw classification
count through the existing backend-neutral SQL summary; without a selector the
materialized raw entry length is already the raw total. Change filtering and
summary aggregation then operate on the full matched population. Engine sorts
the projected matches by `StoredPath`, records the full matched count, and only
then slices detailed entries. The existing SQL summary fast path remains for
summary requests with no selector/change filter; positive Limit does not eject
that semantically equivalent request from the fast path.

## 5. Final SnapshotDiff projection

`SnapshotDiff` explicitly rejects negative Limit before any diff operation.
The detailed result builder preserves three separate populations:

```text
TotalEntryCount   = raw diff count before query/filter
MatchedEntryCount = full query + change-filter match count before Limit
Summary           = aggregate of that same full pre-limit population
Entries           = [] in summary mode
                    otherwise sorted matches capped only when Limit > 0
```

The candidate matrix covers zero, one, below/equal/above matched population,
negative, query-only, change-filter-only, query plus change filter, and query
plus change filter plus Limit. Added, removed, modified, and all-change cases
retain deterministic normalized-path order. Both detailed and summary modes
preserve raw Total and pre-limit Matched/Summary semantics.

## 8. Final Catalog and Engine FileCount design

The internal `catalog.SnapshotRef` now carries `FileCount int`, matching the
existing public Engine field without a narrowing conversion. The SQL driver
scans `COUNT(*)` directly into that destination and therefore fails rather than
silently narrowing an out-of-range value.

`FindSnapshot`, both list query forms, and `LoadSnapshotGraph` add the same
portable correlated membership projection:

```sql
(SELECT COUNT(*)
 FROM snapshot_file sf
 WHERE sf.snapshot_id = s.id) AS file_count
```

No schema, index, migration, placeholder convention, or public Catalog method
changed. Unlimited list, limited list, and graph each remain one Catalog query;
there is no Engine loop issuing per-snapshot counts. SnapshotShow copies the
FindSnapshot count before listing filtered files. Tree list and graph metadata
copy the graph node count, including when a parent is excluded from the
selected projection.

## 9. FileCount proof matrix

Focused Catalog and Engine tests prove:

- empty snapshots report zero in Find, list, show, graph, and tree;
- one-file and multi-file snapshots report exact persisted membership;
- list-row Limit does not change each returned snapshot's own count;
- SnapshotShow prefix filtering and file Limit do not change metadata count;
- parent and child counts are independent persisted memberships;
- graph nodes and tree/list projections carry the same value;
- SQLite and PostgreSQL produce identical results;
- no count is derived from returned slices, filesystem state, or lineage reuse.
