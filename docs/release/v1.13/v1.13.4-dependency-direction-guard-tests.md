ownership decisions documented in Phases 1–6.

documented public-contract seams so later work does not accidentally change

## Test strategy

Phase 7 adds narrow CLI guardrails rather than new ownership abstractions.

The tests protect:

- renderer-envelope versus CLI-envelope success JSON split
- CLI-owned JSON error envelopes
- inspect public target boundary
- representative taxonomy-helper invisibility
- previously documented transitional seams without changing implementation

This phase intentionally reuses the existing preservation suite where it
already protects count-field stability and no-taxonomy-leak behavior, rather
than duplicating those tests for volume.

## Guarded invariants

| Invariant | Test coverage | Why it matters |
| --- | --- | --- |
| `stats` / `inspect` success JSON remains renderer-envelope family | `TestReadSideJSONOwnershipFamiliesRemainDistinct` | protects the Phase 6 boundary that renderer-owned success JSON remains distinct from CLI-owned success JSON |
| `snapshot show` / `snapshot diff` success JSON remains CLI-envelope family | `TestReadSideJSONOwnershipFamiliesRemainDistinct` | protects the Phase 6 boundary that CLI-owned success JSON remains surface-specific and stable |
| JSON error envelopes remain CLI-owned | `TestReadSideJSONErrorsRemainCLIEnvelopeOwned` | protects the shared public error-family contract across read-side surfaces |
| Taxonomy helper names remain internal | `TestReadSideOutputDoesNotLeakTaxonomyHelperNames` plus existing preservation helpers | prevents accidental leakage of internal unsupported/deferred helper terminology |
| Snapshot show count fields remain stable | existing `cmd/coldkeep/read_side_cli_preservation_test.go` and routing tests reused | avoids duplicating already-effective count-field guards |
| Snapshot diff count fields remain stable | existing `cmd/coldkeep/read_side_cli_preservation_test.go`, `cmd/coldkeep/main_test.go`, and routing tests reused | preserves matched-versus-total count behavior without adding redundant tests |
| Inspect public targets remain documented | `TestInspectPublicTargetsRemainDocumentedSet` | protects the documented public target set, the `logical-file` alias, and `EntityPhysicalFile` remaining internal-only |

## Deferred guard gaps

The following desired guards were intentionally not added in Phase 7:

- package-level stats transitional-wrapper tests
  - deferred because current CLI-level and package-level tests already cover the
    public contract, and a new wrapper test would likely be brittle
- additional snapshot show/diff count-field tests
  - deferred because existing CLI, routing, adversarial, and integration tests
    already protect those count fields well
- additional observability or engine ownership tests
  - deferred because current Phase 7 needs were satisfied cleanly at the CLI
    contract layer
