# Coldkeep v1.13.4 to v1.13.5 Handoff

**Completed release:** `v1.13.4 — Read-Side Dependency Direction and Result Ownership Review`
**Recommended next release:** `v1.13.5 — Release Record Closure and Engine-Level Invariant Ownership`
**Status:** Final handoff after `v1.13.4` release

`v1.13.4` completed after the Phase 10 gate passed, PR CI passed, main CI
passed, and the release was tagged.

## Why v1.13.5 exists

`v1.13.4` reviewed and documented the active read-side ownership seams, added
narrow guard tests, and then closed with two narrow production hardenings
during final validation.

`v1.13.5` starts by closing the post-release record gap from that final
validation, then proceeds into engine-level validation and invariant ownership
review without broad routing migration or public behavior change.

## Recommended v1.13.5 objective

Close the `v1.13.4` release-record gap and review engine-level validation and
invariant ownership for active engine-facing operations without changing public
behavior and without performing a broad ownership migration.

## Candidate scope

`v1.13.5` may include:

- post-release cleanup for stale `v1.13.4` pending/draft wording
- documentation of the final `v1.13.4` narrow production hardenings in
  `internal/db/db.go` and `cmd/coldkeep/main.go`
- engine-level validation and invariant ownership inventory across active
  engine-facing operations
- narrow guard-test follow-up only if documented gaps are found
- backend-neutral validation review for any new invariant or validation guards

## Non-goals

`v1.13.5` should not introduce:

- broad read-side routing migration
- unified read-side result abstraction
- unified JSON envelope abstraction
- engine-owned inspect migration unless explicitly proven narrow and
  behavior-preserving
- full `snapshot show` consolidation
- full `snapshot diff` query/result migration
- restore/remove stored-path expansion
- snapshot mutation routing
- repair/recovery routing migration
- catalog facade rewrite
- backend default changes
- schema or migration changes
- storage or repository format changes
- daemon, API, UI, or `v2` work

## Deferred from v1.13.4

The following seams remain deferred after `v1.13.4`:

- `stats` result wrapper remains transitional
- `inspect` direct observability path remains transitional
- `snapshot show` mixed ownership remains transitional
- `snapshot diff` split ownership remains transitional
- success JSON ownership remains split
- backend parity evidence remains partly indirect

## Suggested first phase for v1.13.5

Phase 0 should:

- create `release/v1.13.5` from `main`
- close stale `v1.13.4` post-release documentation
- record the final `v1.13.4` narrow production hardenings honestly
- create the `v1.13.5` scope, phase list, and validation checklist
- reconcile the release title as
  `v1.13.5 — Release Record Closure and Engine-Level Invariant Ownership`

## Handoff conclusion

`v1.13.5` should be treated as a narrow correctness-focused follow-up, not the
start of a read-side rewrite.
