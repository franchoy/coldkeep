# Coldkeep v1.13.4 to v1.13.5 Handoff

**Completed release:** `v1.13.4 — Read-Side Dependency Direction and Result Ownership Review`  
**Recommended next release:** `v1.13.5 — Read-Side Guard Coverage and Seam Hardening Follow-up`  
**Status:** Draft handoff pending `v1.13.4` Phase 10 release-gate completion

## Why v1.13.5 exists

`v1.13.4` reviewed and documented the active read-side ownership seams and
added narrow guard tests.

`v1.13.5` should not perform a broad read-side migration. It should exist only
if a narrow follow-up is needed after `v1.13.4` to strengthen guard coverage
or harden one of the documented seams without changing public behavior.

## Recommended v1.13.5 objective

Strengthen targeted guard coverage around the read-side seams documented in
`v1.13.4` without changing public behavior and without performing a broad
ownership migration.

## Candidate scope

`v1.13.5` may include:

- targeted `snapshot show` / `snapshot diff` count-field guard follow-up if
  Phase 10 or later audit finds coverage insufficient
- targeted backend-parity guard review for read-side surfaces if a narrow test
  can be added safely
- targeted renderer/JSON ownership guard improvements if current tests prove
  too indirect
- targeted documentation cleanup after Phase 10
- narrow release-gate blocker remediation if Phase 10 finds a concrete issue

## Non-goals

`v1.13.5` should not introduce:

- broad read-side routing migration
- unified read-side result abstraction
- unified JSON envelope abstraction
- new public CLI fields
- JSON output shape changes
- engine-owned inspect migration
- full `snapshot show` consolidation
- full `snapshot diff` query/result migration
- backend default changes
- schema or migration changes
- storage or repository format changes
- daemon, API, UI, or `v2` work

## Deferred from v1.13.4

The following seams remain deferred after `v1.13.4`:

- `stats` result wrapper remains transitional
- `inspect` direct observability path remains transitional
- `snapshot show` mixed ownership remains transitional
- `snapshot diff` split ownership remains transitional
- success JSON ownership remains split
- backend parity evidence remains partly indirect

## Suggested v1.13.5 decision gate

Before starting `v1.13.5`, decide whether it is needed at all.

If Phase 10 and post-release audit show no meaningful new guard gaps,
`v1.13.5` may be skipped or re-scoped.

If `v1.13.5` is started, keep it short and test-focused.

## Suggested first phase for v1.13.5

Phase 0 should:

- create `release/v1.13.5` from `main`
- review `v1.13.4` Phase 10 evidence
- review post-release audit findings
- decide whether the release is test-only, docs-only, or a narrow
  blocker-remediation release
- explicitly reject broad ownership migration unless a real correctness issue
  requires it

## Handoff conclusion

`v1.13.5` should be treated as an optional narrow follow-up, not the start of
a read-side rewrite.
