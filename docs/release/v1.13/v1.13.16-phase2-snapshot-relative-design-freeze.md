# v1.13.16 Phase 2 Snapshot-relative Design Freeze

**Release:** v1.13.16 — Snapshot Retention Integrity, Observability Truth, and Final v1.x Closure
**Phase:** 2 — Complete
**Mode:** PLAN
**Implementation status:** Not started

## Reconciliation history

The initial Phase 2 analysis correctly identified the Store-to-Snapshot
namespace mismatch and incomplete selector accounting, but its first proposed
format encoded physical root identity into `snapshot_path.path`. That design
was rejected because it would replace the frozen snapshot-relative public
identity with values such as `posix/home/...`, expose source-machine topology,
and change query, pattern, diff, and restore layout.

Phase 2R restored the required distinction between canonical physical identity
and relative snapshot-member identity. Phase 2R2 finalized the relative-only
create-selector surface, standalone-dot rejection, host-native capture-root
validation, and lossless source-to-member representability. This document is
the resulting implementation authority for Phases 3–6.

CK-V11316-001 and CK-V11316-002 remain `OPEN_DESIGN_FROZEN`. No finding is
fixed or closed, no product implementation has occurred, existing snapshot
rows remain unchanged, and the catalog schema remains version 16.

## Namespace and capture-root contract

- `physical_file.path` remains the canonical host-native absolute physical
  identity. Existing absolute, clean, case-preserving, and symlink-resolution
  behavior is unchanged.
- `snapshot_path.path` remains a normalized relative member identity using the
  existing safe-relative grammar and `/` persisted separators.
- Every full or partial SnapshotCreate request supplies a nonempty host-native
  absolute `SelectionBase`.
- The CLI obtains its current working directory once and passes it explicitly.
  No Engine, snapshot-domain, query, or restore layer may infer process CWD.
- The Engine validates the structural base requirement. The snapshot domain
  requires an existing, canonicalizable directory and uses its resolved
  physical identity as the single transient capture root.
- Capture-root identity is not persisted or exposed. `SnapshotQuery` and
  `SnapshotRestoreSelection` receive no `SelectionBase` field.
- No `--root`, `--base`, or `--capture-root` CLI option is added.

## Create-selector contract

Create selectors retain the existing relative snapshot-path surface:

- `docs/a.txt` is an exact selector.
- `docs/` is a component-bounded directory-prefix selector.
- Absolute POSIX, Windows-drive, and UNC selectors are invalid arguments.
- Standalone `.` and `./` are invalid; an empty selector list is the only full
  snapshot form.
- Existing leading-`./` normalization for a genuine member such as
  `./docs/a.txt` remains compatible.
- Traversal, empty selectors, malformed drive/UNC spellings, and rooted forms
  are invalid arguments.

Selector spelling is normalized in the snapshot-selector namespace first.
The normalized `/`-separated components are then joined beneath the capture
root with host-native path rules and canonicalized for comparison with
`physical_file.path`. On POSIX a literal backslash in a native filename remains
a literal character; selector backslash convenience must not silently change
native component identity.

Every distinct explicit selector must match at least one eligible completed
source. Duplicate and overlapping selectors form a union but remain
individually accounted. One miss, including a missing prefix in a mixed set,
fails the complete create operation and commits no partial snapshot.

## Lossless member representability

A canonical source may become a snapshot member only when its capture-root-
relative native component sequence round-trips through the existing snapshot
grammar without identity change:

1. Prove component-safe containment beneath the canonical capture root.
2. Compute and split the host-native relative source path using native
   separators only.
3. Join the exact components with `/` as the candidate snapshot member.
4. Normalize and validate the candidate through the frozen snapshot grammar.
5. Require normalized bytes and decoded components to equal the original
   candidate and native component sequence exactly.
6. Reconstruct beneath the capture root and require canonical physical
   equality with the source.

Invalid UTF-8, empty/dot/traversal components, rooted or drive reinterpretation,
and any separator splitting, component combining, case change, Unicode change,
or other lossy normalization are forbidden. In particular, a POSIX component
containing a literal backslash cannot silently become multiple snapshot
components. No escaping or sanitization format is introduced.

An otherwise valid physical source that is not losslessly representable fails
creation with Engine `invariant_violation` and invariant code
`SNAPSHOT_MEMBER_PATH_UNREPRESENTABLE`. No snapshot, membership, or new path
dictionary row from the failed create commits.

## Full, partial, and multi-root behavior

Partial creation resolves relative selectors beneath the one capture root and
persists matched sources relative to that root. For capture root
`/home/u/project`, selector `docs/`, and physical source
`/home/u/project/docs/a.txt`, the member is `docs/a.txt`.

Full creation always enumerates every eligible completed physical mapping:

- all eligible mappings beneath the capture root: success containing every
  mapping;
- zero eligible mappings: successful empty full snapshot;
- any eligible mapping outside the root: Engine `conflict` and complete
  rollback;
- any unrepresentable source or member collision: fail closed and rollback.

The outside-root rule is a representability constraint, not an in-root source
filter. A full snapshot may never silently omit an outside source. One
v1.13.16 snapshot cannot span independent capture roots, Windows drives, or UNC
shares. A future explicit CLI capture-root or multi-root addressing feature
requires separate authorization.

## Windows and UNC behavior

On Windows, `SelectionBase` may be a valid existing drive directory such as
`C:\repo`. A canonical source `C:\repo\docs\a.txt` becomes `docs/a.txt`.
Another drive is outside the capture root and makes full creation fail.

An existing reachable UNC directory such as `\\server\share\repo` may be the
capture root. Source `\\server\share\repo\docs\a.txt` becomes `docs/a.txt`.
A different server/share is outside the root. Drive, server, and share identity
are never persisted in the member path. Foreign-OS root syntax is not resolved
on the current host.

## Collision, read, and restore behavior

- Same relative member plus same logical-file ID is a benign duplicate and is
  inserted once.
- Same relative member plus different logical-file IDs, or two distinct native
  sources mapping to one member, is an Engine `conflict`.
- Snapshot identity comparisons remain case-sensitive and byte-preserving.
- Show, query, and diff operate directly on persisted relative members and are
  independent of process CWD.
- Exact and prefix filters retain their current relative semantics. Pattern and
  regex filters continue operating on the user-facing relative member.
- Restore member `docs/a.txt` resolves beneath the caller's trusted destination
  as `<destination>/docs/a.txt`; source roots, drive tags, and UNC prefixes are
  never introduced into normal restore layout.
- Existing traversal, rooted-path, symlink, overwrite, destination-collision,
  and preflight safety rules remain authoritative.

## Legacy, schema, errors, and transaction

Existing snapshot rows are never rewritten. Historical root-stripped values
remain their historical relative member identities. Corrected snapshots may
therefore differ by persisted name; diff reports the stored identity difference
without guessing an unavailable legacy base. No text heuristic, lazy migration,
capture-root metadata, or path-format discriminator is introduced.

`SCHEMA_CHANGE` is `NOT_REQUIRED`; schema version remains 16 for SQLite and
PostgreSQL.

Stable Engine classifications are:

- invalid/missing/nonabsolute/non-directory/nonexistent SelectionBase,
  absolute/dot/traversal selector: `invalid_argument`;
- unexpected base-resolution I/O failure: `operation_failed`;
- unmatched selector or mixed selector miss: `not_found`;
- outside-root full source or relative-member collision: `conflict`;
- unrepresentable source or malformed catalog identity:
  `invariant_violation`.

Snapshot metadata insertion, complete source enumeration, root/selector
validation, per-selector match accounting, lossless conversion, collision
validation, path resolution, and membership insertion share one transaction.
Any error rolls back the snapshot row, membership, and newly created path rows.
