## Reconstruction contract common to live routes

- Catalog supplies complete logical metadata and a strict packed-or-legacy
  placement for every chunk.
- Storage reconstructs in `chunk_order`, checks segment bounds, plaintext
  lengths and chunk hashes, and requires the final file SHA-256 to match before
  publication.
- Restore pins all referenced chunks before reads and unpins on success or
  failure. Focused race tests prove the pin lifecycle and deterministic bytes.
- Missing, malformed, truncated, unauthenticated, oversized, or incorrectly
  ordered payload cannot be renamed into place as a successful restore.

That reconstruction contract is `PROVEN`. The matrix remains `BLOCKER` because
destination confinement and installation occur after successful
reconstruction and violate separate mandatory invariants.

## Platform installation result

Linux and macOS ordinary rename can replace an existing destination, so the
final absence check does not create no-replace semantics. The Windows path
uses Go's ordinary rename abstraction rather than a create-new/no-replace
primitive, and parent-directory sync is explicitly skipped. No supported OS
has source proof of the required atomic no-replace install. Static lexical and
symlink tests are portable, but none closes the checked-parent replacement
window.
