## Physical-file count

`physical.total_physical_files` is exactly:

```sql
SELECT COUNT(*) FROM physical_file
```

One row is one current stored-path mapping. Two paths to one logical file
count as two. Snapshot-only logical data without a current mapping counts as
zero. Unlink decrements the count by removed mappings. Deduplication, packed
versus legacy placement, codecs, compression, chunker version, and snapshots
do not collapse or expand it. Unusual linked logical status does not remove a
mapping from this structural count. Query failure fails stats closed.

Maintenance executes the one backend-neutral query and owns the value in:

```go
TotalPhysicalFiles int64 `json:"total_physical_files"`
```

Observability maps that value. Engine, CLI, human, and JSON adapters preserve
it without re-query or recomputation. SQLite and PostgreSQL return the same
int64 for equivalent metadata.

## Shared protected-storage API

Implement only in `internal/retention/reachability.go`:

```go
type ProtectionOptions struct {
    ExcludeSnapshotIDs []string
}

type ProtectedStorageSet struct {
    GraphReachableCompletedChunkIDs map[int64]struct{}
    ProtectedCompletedChunkIDs      map[int64]struct{}
    ProtectedPackedBlockIDs         map[int64]struct{}
}

func BuildProtectedStorageSet(
    ctx context.Context,
    dbconn *sql.DB,
    opts ProtectionOptions,
) (*ProtectedStorageSet, error)
```

Graph-reachable completed chunks descend from current roots in
`physical_file` and retained roots in `snapshot_file`, excluding only supplied
snapshot IDs after every excluded ID is proved to exist. Reuse the current
catalog root loader and graph traversal.

Protected completed chunks are the union of:

```text
GRAPH_REACHABLE_COMPLETED
UNION COMPLETED_WITH_LIVE_REF_COUNT_GREATER_THAN_ZERO
UNION COMPLETED_WITH_PIN_COUNT_GREATER_THAN_ZERO
```

Positive live references are conservative additional protection, not a
replacement for current/snapshot reachability. Public `ReachableChunks`
remains the graph-reachable count.

A packed block is protected when any referenced completed chunk is protected.
Each `storage_blocks.id` is counted once. The helper loads live refs and pins
once, builds deterministic ID sets, performs no database/filesystem mutation,
and imports no CLI, engine, maintenance, GC, or verify package.

Classification fails closed on an unreferenced storage block, missing block or
chunk ref, negative size, out-of-extent offset/size, impossible simultaneous
legacy and packed placement, or any indeterminate state. Malformed metadata is
never silently dead.

## Packed accounting

GC-plan eligible containers are non-quarantined and either stable sealed
(`sealed=TRUE`, `sealing=FALSE`) or active (`sealed=FALSE`). Mid-seal
(`sealed=TRUE`, `sealing=TRUE`) is excluded.

For eligible storage blocks:

```text
packed_blocks_live = COUNT(DISTINCT protected storage_blocks.id)
packed_blocks_dead = COUNT(DISTINCT unprotected storage_blocks.id)
packed_bytes_live = SUM(stored_size once per protected block)
packed_bytes_reclaimable = SUM(stored_size once per unprotected block)
retained_dead_bytes_due_to_packed_blocks =
  SUM(size_in_block once per completed unprotected chunk in a protected block)
```

Snapshot-only and pinned-only chunks protect their block and contribute no
retained-dead bytes themselves. A mixed block is one protected physical block:
its entire `stored_size` is live and none immediately packed-reclaimable; only
unprotected chunk slices contribute retained-dead logical bytes. Multiple
chunks or snapshots never multiply a block. Excluding one of two snapshots
keeps shared data protected; excluding the last can expose it only when no
current root, positive live ref, or pin remains.

Quarantined and mid-seal blocks are excluded from GC reclaimability.
Quarantined structurally valid physical units remain visible in descriptive
stats.

## Logical and physical byte domains

Keep these independent:

- `reachable_chunks`: unique completed graph-reachable chunks after exclusions;
- `unreachable_chunks`: all completed minus graph-reachable completed;
- `logically_reclaimable_bytes`: `chunk.size` once per completed unprotected
  chunk with classifiable eligible placement;
- `packed_bytes_reclaimable`: packed `stored_size` once per unprotected
  eligible block;
- per-container `reclaimable_bytes`: unprotected legacy plus packed stored
  sizes, once per physical unit;
- `physically_reclaimable_bytes`: `container.current_size` only for fully
  reclaimable eligible containers.

Partial dead payload does not become immediately physical reclaimability;
Phase 8 does not implement compaction. Maintenance live-GC `BytesReclaimed`
continues to use inspected file size after successful live deletion, or the
same inspected size in dry-run.

## Descriptive maintenance stats

Descriptive global and per-container physical accounting includes structurally
valid legacy `blocks` and packed `storage_blocks`, once per row/block, in every
container state. Whole-block protection classifies packed storage. Packed
`stored_size` is never multiplied by refs.

Per container:

```text
TotalBytes = container.current_size
LiveBytes = protected legacy stored size + protected packed stored size
DeadBytes = unprotected legacy stored size + unprotected packed stored size
LiveRatioPct = LiveBytes / TotalBytes * 100, or zero for zero TotalBytes
```

If classified physical-unit bytes exceed `container.current_size`, fail; do
not clamp or approximate.

Globally, `LiveBlockBytes` and `DeadBlockBytes` are the corresponding
descriptive legacy-plus-packed values. Preserve the existing dedup formula
unless the source proves mathematical impossibility. Fragmentation is
non-quarantined dead physical payload divided by the existing healthy-
container byte domain. Quarantined bytes never inflate fragmentation.
`BlockLayoutStats` and logical-file `SnapshotRetentionStats` stay independent.

## Per-container GC plan

For every eligible container:

```text
TotalBytes = container.current_size
ReclaimableBytes = unprotected legacy + unprotected packed stored size
LiveBytesAfterGC = TotalBytes - ReclaimableBytes
ReclaimableChunks = reclaimable physical units
TotalChunks = total physical units
```

The retained JSON names count physical units, not packed refs.
`FullyReclaimable` requires eligibility, at least one unit, and every unit
unprotected. `RequiresCompaction` requires both protected and unprotected
units. Physical-unit sums exceeding current size fail closed. Impact order
remains deterministic by container ID and filename.
