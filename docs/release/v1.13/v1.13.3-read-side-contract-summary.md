## Release objective

`v1.13.3` cleans and stabilizes read-side contracts for stats, inspect,
snapshot show, and snapshot diff using the `v1.13.2` taxonomy baseline while
preserving public CLI behavior, JSON output, exit codes, routing, schema,
storage format, backend defaults, and PostgreSQL compatibility.

## Read-side surfaces covered

### stats

- `stats` is engine-wrapped.
- The concrete success result is still observability-owned.
- Public JSON and CLI behavior were preserved.
- The taxonomy boundary is now test-protected.
- Backend and dependency state were accepted for `v1.13.3`, but result
  ownership and renderer coupling remain provisional.

### inspect

- The production path is still `CLI -> observability`.
- `engine.InspectRequest` and `engine.InspectResult` exist, but engine is not
  the production owner.
- Supported targets and not-found behavior are now documented.
- Public JSON and CLI behavior were preserved.
- The taxonomy boundary is now test-protected.
- Direct observability ownership remains provisional.

### snapshot show

- `snapshot show` remains mixed ownership.
- Metadata and stats use engine-backed seams.
- File listing remains direct snapshot-package ownership.
- CLI JSON assembly and renderer-owned human output remain active.
- Missing snapshot, empty snapshot, and count behavior are documented.
- Public JSON and CLI behavior were preserved.
- The taxonomy boundary is now test-protected.
- Mixed ownership remains provisional.

### snapshot diff

- The CLI still owns richer parsing and filtering semantics.
- The engine seam is active but provisional.
- The detailed path still delegates to the snapshot package.
- The summary fast path remains distinct from the detailed path.
- Summary JSON omits `entries`.
- Detailed JSON includes `entries`.
- Query and filter semantics were preserved.
- Public JSON and CLI behavior were preserved.
- The taxonomy boundary is now test-protected.
- The provisional seam is now explicitly documented.

## Taxonomy boundary summary

- Active read-side validation errors remain outside `engine.IsUnsupported(err)`.
- Active read-side errors remain outside `catalog.IsDeferred(err)` where that
  distinction applies.
- Success paths remain success and do not broaden unsupported or deferred
  classification.
- No broad taxonomy helper framework was introduced.
- No public taxonomy fields were introduced.

## Public CLI preservation summary

- Representative JSON success and error envelopes are protected.
- Representative no-taxonomy-leak assertions exist.
- Representative usage, domain, and mixed-seam behavior is protected.
- No CLI behavior was intentionally changed.
- No JSON output was intentionally changed.
- No exit code was intentionally changed.
- No routing was intentionally changed.
