# Coldkeep v1.13.13 Remediation Workstream Freeze

**Release:** `v1.13.13 — Final v1.x and v2 Handoff Gate`
**Phase:** `6 — Deferred-Item and Blocker Freeze`
**Status:** Frozen

This document fixes outcomes and proof obligations, not implementation design.
Phase 7 must design within these bounds; Phase 8 may implement only the frozen
blocker outcomes; Phase 9 must prove them without weakening the contracts.

## `WS-CATALOG-TYPED-ERRORS`

- **Purpose/findings:** close `P2-ARCH-001` and complete `V1R-CAT-003`.
- **Mandatory behavior:** `FindLogicalFile`,
  `FindPhysicalFilesForLogicalFile`, `FindSnapshot`, `ListSnapshots`, and
  `LoadReachabilityRoots` return stable backend-neutral Catalog codes while
  preserving unwrap causes, cancellation, and deadline meaning. Query and
  scan failure paths must be deterministic.
- **Non-goals:** Catalog or Engine redesign, DTO changes, new operations,
  presentation errors, schema changes, or forcing Engine callers to expose
  Catalog codes.
- **Likely source areas:** `internal/catalog/logical_files.go`,
  `physical_files.go`, `snapshots.go`, `reachability.go`, error translators,
  recursive typed-error guards, and backend fixtures.
- **Regression contract:** injected query/scan failures, cancellation and
  deadline cases, unknown failure fallback, cause preservation, all five
  methods, SQLite and PostgreSQL. Race execution is not required for this
  workstream.
- **Platform/backend matrix:** platform-neutral Go boundary; both supported
  database backends are required.
- **Dependencies/risk:** overlaps `WS-BACKEND-LABEL-SEMANTICS` in snapshot
  queries. Phase 7 must co-design them, and Phase 8 must establish typed error
  translation before or atomically with label-query normalization. Risk is
  accidental loss of `errors.Is` meaning or backend leakage.
- **Phase contract:** Phase 7 selects one reusable translation pattern and
  exact fixtures; Phase 8 implements only those changes; Phase 9 proves all
  five methods and both backends.

## `WS-RESTORE-DESTINATION`

- **Purpose/findings:** close distinct `P3-COR-001` and `P3-COR-002`.
- **Mandatory behavior:** a planned exact destination remains exact;
  no-overwrite performs an atomic non-replacing publication; overwrite is an
  explicit replacing mode; dry-run/live destination interpretation agrees;
  and parent replacement cannot redirect any create, write, metadata, or
  install operation outside the trusted root.
- **Non-goals:** repository format, Engine/Catalog redesign, remote/NAS
  semantics, multi-file snapshot atomicity, new restore modes, or a hostile
  same-user protection promise beyond the frozen concurrent path invariant.
- **Likely source areas:** Engine restore planning, snapshot restore planning,
  `internal/storage/restore.go`, `internal/pathsafe`, `internal/fsx`, and
  platform-specific atomic publication primitives.
- **Regression contract:** deterministic occupation of the final install
  window; exact target that is an existing directory; overwrite true/false;
  by-ID single/batch, stored original/prefix/exact, snapshot original/prefix/
  exact across full/exact-path/prefix/query selections; parent-swap fixtures;
  sync/close/rename/cleanup faults; destination preservation; Linux, macOS,
  and Windows. Relevant race execution is required.
- **Platform/backend matrix:** all three supported operating systems;
  backend-independent behavior exercised with applicable SQLite/PostgreSQL
  routes.
- **Dependencies/risk:** the two findings share the destination mutation
  boundary but remain separate closure identities. Risk is platform-specific
  replacement semantics, semantic drift among selectors, or cleanup that
  destroys a pre-existing destination.
- **Phase contract:** Phase 7 must specify primitive-level publication and
  trusted-parent ownership; Phase 8 implements the smallest common route;
  Phase 9 closes each root independently.

## `WS-VERIFY-PACKED-DEEP`

- **Purpose/findings:** close `P3-COR-003`.
- **Mandatory behavior:** file-deep verification enumerates every
  authoritative legacy and packed placement, covers all chunks of a mixed
  file, rejects missing or conflicting placement metadata, validates bytes
  through the appropriate container/legacy path, and reports truthful checked
  and failed counts.
- **Non-goals:** storage-format migration, repair of corruption, new verify
  levels, container redesign, or performance productization.
- **Likely source areas:** `internal/verify/verify_file.go`, placement query/
  scan helpers, container readers, maintenance verify projection, and backend
  fixtures.
- **Regression contract:** valid and corrupt legacy-only, packed-only, and
  mixed files; missing/conflicting placement; selected file IDs; truthful
  counts; SQLite and PostgreSQL. Fault injection is required where reads or
  metadata fail; a race suite is not required.
- **Platform/backend matrix:** both supported backends; platform-neutral file
  semantics with normal hosted OS coverage.
- **Dependencies/risk:** independent of the other four workstreams. Risk is
  duplicate chunk verification, nondeterministic ordering/counts, or turning a
  metadata inconsistency into a skip.
- **Phase contract:** Phase 7 freezes one placement enumeration rule; Phase 8
  implements it; Phase 9 proves all repository shapes on both backends.

## `WS-BACKEND-LABEL-SEMANTICS`

- **Purpose/findings:** close `P4-BE-001` and satisfy `V1R-BE-003`.
- **Mandatory behavior:** snapshot-label filters are narrow ASCII
  case-insensitive substring matches in limited and unlimited Catalog queries,
  Engine `SnapshotList`, and CLI projection, with identical deterministic
  ordering on SQLite and PostgreSQL.
- **Non-goals:** Unicode case folding, locale collation, normalization,
  fuzzy/full-text search, current-file search redesign, or product-default
  changes.
- **Likely source areas:** `internal/catalog/snapshots.go`, query helpers,
  Engine snapshot tests, CLI integration fixtures, and dual-backend contracts.
- **Regression contract:** mixed-case labels and opposite-case filters,
  ordinary substring behavior with existing wildcard treatment unchanged,
  limited and unlimited results, identical ordering and IDs through Catalog/Engine/CLI on
  SQLite and PostgreSQL. Race/fault injection is not required solely for this
  workstream.
- **Platform/backend matrix:** both supported backends; platform-neutral.
- **Dependencies/risk:** co-design with `WS-CATALOG-TYPED-ERRORS`; error
  translation must precede or land atomically with query normalization. Risk
  is SQL dialect drift or accidental broad Unicode policy.
- **Phase contract:** Phase 7 freezes dialect-safe SQL and exact expected
  order; Phase 8 implements only the narrow contract; Phase 9 compares named
  dual-backend results.

## `WS-SIMULATE-GC-COORDINATION`

- **Purpose/findings:** close `P5-COORD-001`.
- **Mandatory behavior:** `simulate gc` acquires the native repository lease
  before any shared schema/application work and retains it through GC planning,
  result projection, application cleanup, and lease cleanup. Simulated store/
  folder and benchmarks remain isolated; init, help, version, and invalid
  commands remain no-repository bypasses.
- **Non-goals:** distributed coordination, treating PostgreSQL advisory locks
  as repository identity, making isolated simulation acquire a lease, or
  changing GC algorithms/productization.
- **Likely source areas:** CLI coordination policy and dispatch, startup
  ordering, `runSimulateGCCommand`, application session composition, policy
  guards, and subprocess fixtures.
- **Regression contract:** exact policy classification; no schema, migration,
  recovery, cleanup, or plan work before acquisition; a real independent
  holder blocks `simulate gc`; safe exceptions remain repository-free;
  PostgreSQL subprocess coverage; relevant policy/concurrency race execution.
- **Platform/backend matrix:** Linux/macOS/Windows native lifecycle; SQLite
  and PostgreSQL route evidence where supported. PostgreSQL advisory ownership
  remains an additional backend barrier, never cross-host coordination.
- **Dependencies/risk:** independent of other workstreams. Risk is acquiring
  after `application.Open`, over-coordinating isolated tooling, or releasing
  before application cleanup.
- **Phase contract:** Phase 7 freezes the operation policy and lifecycle
  assertion; Phase 8 changes only the shared GC simulation path and guards;
  Phase 9 proves contention, ordering, exceptions, and backend bounds.

## Aggregate sequencing

Phase 7 designs all five workstreams. The Catalog error and label workstreams
must be co-designed; the remaining workstreams may proceed independently.
Phase 8 must not claim closure. Phase 9 closes findings only after every
frozen targeted, platform, backend, fault, and race obligation applicable to
the finding passes. Phase 10 may start only after all six blocker roots are
`CLOSED`, no Phase 8 regression is known, and release-state validation passes.
