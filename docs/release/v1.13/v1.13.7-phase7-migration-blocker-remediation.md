# Coldkeep v1.13.7 Phase 7 Migration Blocker Remediation

**Release:** `v1.13.7 — SQLite-First Repository Portability Baseline`
**Phase:** Phase 7A
**Status:** Complete
**Branch:** `release/v1.13.7`

## Blocker

The initial portability relocation test failed after destination reopen and
verification with:

```text
logical_file.ref_count mismatch: logical_file_id=1 expected=1 actual=2
```

## Root cause

The physical-file migration backfill selected logical files by synthetic-path
absence rather than by physical-mapping absence.

On schema reopen, that allowed migration to add a synthetic `/migrated/...`
mapping to a logical file that already had one or more real `physical_file`
mappings.

## Violated invariant

Migration must create a synthetic physical mapping only when a logical file has
no physical mappings at all.

Repeated migration must not change an already-valid physical-file graph.

## Remediation

- SQLite backfill now checks `physical_file.logical_file_id`
- PostgreSQL backfill now applies the same invariant
- legacy unmapped logical files still receive one synthetic mapping
- existing one-to-many mappings remain unchanged
- ref counts are not globally recalculated
- unrelated mismatches remain visible to `verify`

## Regression coverage

Added or strengthened:

- focused SQLite mapped-file migration regression
- multiple-mapping migration regression
- storage migration-idempotency regression
- PostgreSQL schema-rerun regression
