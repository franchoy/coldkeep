## 4. Public contract alignment

### Search syntax

The root README now uses:

```text
coldkeep search --name report
```

The positional `coldkeep search report` form remains a usage error with exit
2. No compatibility alias or repository-opening parser path was added.

### Process exits and JSON layers

Top-level help and README now expose the complete process contract:

| Exit | Meaning |
| --- | --- |
| 0 | success |
| 1 | general/execution error |
| 2 | usage/pre-execution validation error |
| 3 | verification/invariant-integrity error |
| 4 | recovery error |

Batch failure precedence is explicitly
`invariant > execution > validation`; no-failure remains exit 0. Recovery was
not invented as a batch category.

The automation text distinguishes the numeric process `exit_code`, the
process-level `error_class`, the coarse `error.code` family, the stable
invariant identity in `invariant_code`, and operator remediation guidance in
`recommended_action`. The JSON payload shape and contract version are
unchanged.

### Init compression discoverability

Top-level help now advertises:

```text
init [--compression <none|zstd>] [--compression-level <1-9>]
```

Help and README include the canonical none and zstd/level-1 commands and state
that compression is block-level, happens before encryption, affects new writes
only, and accepts a compression level only for zstd in the range 1–9. They
also state that none stores new blocks without compression and zstd uses the
configured compression behavior for new blocks. Existing blocks are not
described as recompressed.

## 5. Regression and compatibility proof

The final regressions prove:

- the README command parses to search with no positional and `name=report`;
- the historical positional search form remains exit-2 usage-invalid;
- all five constants and representative general, usage, verify/invariant, and
  recovery classifications remain exact;
- invariant-bearing batch failure outranks simultaneous execution and
  validation failures;
- JSON retains the numeric exit, process class, coarse family, stable
  invariant code, and recommended action as separate fields;
- bare init, none, zstd, and zstd levels 1 and 9 succeed in test-owned working
  directories;
- level 0, level 10, none plus level, level without compression, and an invalid
  codec retain their existing rejection behavior;
- successful init keeps key/codec output, compression variables, and `0600`
  `.env` permissions; and
- README and top help expose every frozen syntax and semantic statement.

The contracts are backend-neutral and platform-neutral. Existing plain and
AES-GCM, none and zstd, SQLite and PostgreSQL, Linux, macOS, and Windows
behavior is preserved.
