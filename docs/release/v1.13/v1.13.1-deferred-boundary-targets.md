# v1.13.1 Deferred Boundary Targets

## Purpose

This document is the authoritative Phase 1 target matrix for `v1.13.1`.

Its job is to translate the completed `v1.13.0` inventories plus live code inspection into one
deduplicated list of misleading engine/catalog boundaries that `v1.13.1` may clarify, harden, or
test without expanding into broad routing or implementation work.

This phase is documentation/planning only. It does not change Go code, tests, schema, migrations,
CLI behavior, JSON output, exit codes, storage format, repository format, default backend
behavior, engine routing, catalog implementation, CI behavior, or scripts.

## Classification Rules

Categories used in the target matrix:

- `explicit ErrNotImplemented`
- `candidate-only engine operation`
- `direct CLI bypass`
- `partial engine routing`
- `field/option narrowing`
- `fallback behavior`
- `catalog deferred method`
- `request/result support surface that implies more support than exists`

Current owner values used here:

- `CLI`
- `engine`
- `catalog`
- `domain package`
- `mixed`
- `unclear`

Desired `v1.13.1` outcomes used here:

- `explicit unsupported error`
- `explicit candidate-only documentation`
- `explicit partial-routing note`
- `explicit fallback note`
- `explicit field support limitation`
- `preservation test only`
- `defer beyond v1.13.1`

## Dedupe Rules

- One row represents one distinct misleading runtime or contract boundary.
- `v1.13.0` inventory rows and live code references are evidence for the same target, not separate
  duplicate targets.
- Request/result-only rows are kept only when the type or field shape creates a distinct
  support-overclaim risk beyond the operation-level row.
- Formatting-only splits are not promoted to first-class targets unless they could mislead a future
  daemon/API caller about business ownership or stable engine/catalog completeness.

## Bottom Line

The point of this matrix is not to maximize row count. The point is to make every later
`v1.13.1` code/test phase target one of these explicit misleading boundaries and nothing broader.

If a later phase cannot map a change or test to one or more `CK-1131-BND-*` targets above, it
should be treated as out of scope for `v1.13.1`.
