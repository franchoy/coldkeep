The failure is classified as

reported as an insert into `chunk`. The same prefix error affects names such
as `chunk_something`, `logical_file_something`, and `chunk.schema_table`.

This is not a runtime defect, a CK-V11316-015 implementation defect, or a new
finding. CK-V11316-007 and CK-V11316-015 remain open, CK-V11316-014 remains
external and excluded, and the totals remain 14 confirmed and 12/14 closed.

## Authoritative guard contract

The guard rejects direct inserts from non-test Go code into exactly the two
chunker-version-bearing tables `logical_file` and `chunk`, except for the
authorized owner `internal/storage/store.go`. No additional protected table
was found. `chunk_block_refs`, `file_chunk`, `retired_chunk_block_ref`, and
`store_repair_chunk` are distinct unprotected identifiers under this guard.

The corrected shared ERE is exactly:

```text
INSERT INTO (logical_file|chunk)([[:space:](]|$)
```

It preserves the existing case-sensitive, unquoted, unqualified, same-line
contract and accepts a whitespace delimiter, an opening parenthesis, or end
of line after the complete protected identifier. It does not expand the guard
into a SQL parser. The historical quoted, qualified, flexible-keyword-spacing,
multiline-keyword, and scan-root limitations tracked as CK-110-1814/1815
remain outside this recovery.
