# Coldkeep v1.13.7 Scope

**Release:** `v1.13.7 — SQLite-First Repository Portability Baseline`
**Status:** In progress
**Branch:** `release/v1.13.7`

## Goal

Establish the SQLite-first local repository portability baseline while
preserving PostgreSQL compatibility.

The release will inventory current repository initialization and
backend-selection behavior, review SQLite catalog placement, define repository
portability expectations, classify existing evidence, and add only narrowly
justified portability guards.

## Core direction

SQLite-first does not mean SQLite-only.

SQLite is the intended local repository direction.

PostgreSQL remains supported and mandatory in compatibility validation and the
final release gate.

## In scope

- repository initialization inventory
- backend-selection inventory
- SQLite catalog-location review
- repository-root and portability assumptions
- WAL/SHM/checkpoint considerations
- repository move/reopen contract
- portability evidence classification
- SQLite/PostgreSQL compatibility review
- minimal portability smoke-test design
- narrow test-only guards if justified
- backend-direction documentation consistency
- v1.13.8 handoff preparation

## Out of scope

- daemon
- API
- UI
- scheduling
- NAS
- cloud/object storage
- distributed storage
- network/server mode
- multi-user mode
- broad schema rewrite
- broad migration rewrite
- storage format change
- repository format change
- PostgreSQL compatibility removal
- SQLite-only engine/catalog assumptions
- public CLI behavior changes unless explicitly required
- JSON shape changes
- error-envelope changes
- exit-code changes
- broad refactors

## Compatibility requirements

- existing repositories remain readable
- SQLite behavior remains supported
- PostgreSQL behavior remains supported
- no backend default change without explicit scope and validation
- no storage or repository format change
- public CLI and output contracts remain stable unless explicitly scoped

## Release process

All phases remain on `release/v1.13.7`.

One PR is opened only after:

- every phase is complete
- the full `PRE_RELEASE_CHECKLIST.md Profile A` gate passes
- PostgreSQL-backed validation passes
- release evidence is recorded
