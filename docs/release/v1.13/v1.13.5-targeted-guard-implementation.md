# Coldkeep v1.13.5 Targeted Guard Implementation Pass

**Release:** `v1.13.5 — Release Record Closure and Engine-Level Invariant Ownership`  
**Phase:** Phase 8  
**Status:** Complete  
**Branch:** `release/v1.13.5`

## Purpose

This document records the Phase 8 targeted guard decision.

Phase 8 reviewed the backend-neutral candidate guard gaps identified in
Phases 2–7 and either added narrow tests for confirmed gaps or rejected or
deferred candidates that were already covered, duplicate, backend-sensitive,
over-brittle, or not worth freezing in `v1.13.5`.

## Guard selection rules

- add only backend-neutral guards
- add only tests for already-intended behavior
- do not freeze incidental wording
- do not duplicate existing direct assertions
- do not add broad fixtures
- do not change production behavior
- do not change public output contracts

## Candidate decision table

| Candidate guard | Source phase | Backend classification | Decision | Rationale |
| --- | --- | --- | --- | --- |
| verify invariant metadata + verify-failure public detail guard | Phase 2 / Phase 7 | backend-neutral | already covered | invariant metadata is already asserted in `cmd/coldkeep/cli_translation_preservation_test.go` and integration tests, while verify-failure detail extraction is already asserted in `cmd/coldkeep/main_test.go` and domain-layer verify tests; adding another combined guard would mostly restate existing coverage |
| verify empty-target default guard | Phase 2 / Phase 7 | backend-neutral | not worth freezing in `v1.13.5` | `DefaultEngine.Verify` currently defaults empty target to `system`, but direct validation intentionally treats empty target as invalid; that defaulting step is an internal flow detail rather than a boundary that needs a new explicit guard in this release |
| remove unsupported stored-path fails-before-mutation guard | Phase 3 / Phase 7 | backend-neutral | already covered | `internal/engine/unsupported_modes_test.go`, `internal/engine/remove_engine_test.go`, and `internal/engine/validation_vs_unsupported_test.go` already cover unsupported stored-path classification and no-mutation behavior |
| restore unsupported stored-path fails-before-mutation guard | Phase 4 / Phase 7 | backend-neutral | already covered | `internal/engine/unsupported_modes_test.go`, `internal/engine/restore_engine_test.go`, and `internal/engine/validation_vs_unsupported_test.go` already cover unsupported stored-path classification and no-mutation behavior |
| restore empty output directory engine-level guard | Phase 4 / Phase 7 | backend-neutral | already covered | `internal/engine/validation_vs_unsupported_test.go` already directly asserts that restore requires an output directory |
| GC invariant wrapping/extraction guard | Phase 5 / Phase 7 | backend-neutral | already covered | `internal/invariants/errors_test.go` already directly covers invariant code extraction and wrapped extraction through `fmt.Errorf("%w", ...)` |
| CLI maintenance invariant JSON error guard | Phase 5 / Phase 7 | backend-neutral | already covered | `cmd/coldkeep/main_test.go` and `cmd/coldkeep/cli_translation_preservation_test.go` already assert stable invariant metadata in CLI JSON error output for maintenance and verify-adjacent paths |
| read-side extra guards | Phase 6 / Phase 7 | duplicate / no longer justified | rejected | Phase 6 already found direct read-side coverage sufficient and no new evidence contradicts that decision |
| remove snapshot-retained invariant metadata guard | Phase 3 / Phase 7 | backend-sensitive but existing coverage sufficient | deferred | retained-delete behavior already has engine, storage, integration, and adversarial coverage; adding more would be backend-sensitive and unnecessary for `v1.13.5` |
| restore dry-run/live result ownership guard | Phase 4 / Phase 7 | backend-sensitive but existing coverage sufficient | deferred | existing engine, CLI, and integration tests already cover dry-run and public behavior without adding a broader backend-sensitive parity guard |
| repair orphan-row refusal invariant metadata guard | Phase 5 / Phase 7 | backend-sensitive but existing coverage sufficient | deferred | maintenance and CLI tests already cover orphan-row refusal metadata, and broader backend-sensitive coverage is not justified in this release |
