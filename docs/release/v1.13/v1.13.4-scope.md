# Coldkeep v1.13.4 — Read-Side Dependency Direction and Result Ownership Review

## Status

`Planning / in progress`

## Release Objective

`v1.13.4` reviews and stabilizes the dependency direction and result ownership
boundaries for the read-side surfaces documented in `v1.13.3`: `stats`,
`inspect`, `snapshot show`, and `snapshot diff`.

This release must clarify which package owns each request, result, renderer,
JSON assembly path, and backend-facing dependency while preserving all public
behavior.

## Core Rule

`v1.13.4` is not a broad routing migration release.

## Included Scope

- release-scope and validation documents for `v1.13.4`
- read-side ownership inventory for `stats`, `inspect`, `snapshot show`, and
  `snapshot diff`
- dependency-direction review for current read-side production paths
- result ownership review for engine, observability, snapshot, renderer, and
  CLI seams
- renderer and CLI JSON assembly boundary review
- backend compatibility review for read-side ownership decisions
- narrow tests that protect intended dependency direction and ownership seams
- documentation of stable versus provisional read-side seams
- `v1.13.5` handoff

## Excluded Scope

- CLI behavior changes
- human output changes
- JSON output changes
- JSON error envelope changes
- exit-code changes
- command routing changes
- engine routing changes unless explicitly scoped and fully protected
- schema or migration changes
- storage or repository format changes
- backend default changes
- SQLite compatibility removal
- PostgreSQL compatibility removal
- daemon, API, UI, or `v2` work
- snapshot mutation features
- restore/remove stored-path expansion
- recursive store
- repair or recovery expansion
- broad engine routing migration
- broad catalog abstraction rewrite
- broad result-type rewrite
- public CLI taxonomy fields
- public JSON shape changes
- style-only cleanup

## Read-Side Surfaces

### `stats`

Primary concerns:

- result ownership between engine and observability
- renderer dependency stability
- backend-sensitive expectations
- taxonomy and contract preservation

### `inspect`

Primary concerns:

- direct CLI-to-observability dependency direction
- inspect result ownership clarity
- supported-target and not-found contract stability
- renderer coupling

### `snapshot show`

Primary concerns:

- metadata, file-list, and stats path ownership
- CLI JSON assembly ownership
- human renderer ownership
- missing and empty snapshot behavior

### `snapshot diff`

Primary concerns:

- CLI query parsing ownership
- engine narrowing ownership
- snapshot diff result ownership
- summary versus detailed path ownership
- `--filter` post-processing ownership

## Compatibility Statement

`v1.13.4` must preserve:

- CLI behavior
- human output
- JSON output
- JSON error envelopes
- exit codes
- command routing
- engine routing unless a later phase explicitly scopes and protects a narrow
  change
- schema and migrations
- storage and repository format
- backend defaults
- SQLite compatibility
- PostgreSQL compatibility

## Release Success Definition

`v1.13.4` is complete when Coldkeep has documented and, where needed, narrowly
test-protected the intended dependency direction and result ownership seams for
`stats`, `inspect`, `snapshot show`, and `snapshot diff` without changing
public CLI behavior, JSON output, error envelopes, exit codes, routing,
schema, storage format, repository format, backend defaults, or backend
compatibility.
