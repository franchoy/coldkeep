# Coldkeep v1.13.14 GC Execution Scheduler Design

**Owner finding:** `CK-V1-AUD-003`
**Implementation phase:** `Phase 11 — GC Workers and Accurate Reclaimed Bytes`
**State:** `CONFIRMED_OPEN_DESIGN_FROZEN`

## Contract

Engine rejects a negative `GarbageCollectRequest.Workers` as
`ErrorInvalidArgument`. Zero and one normalize to one. Every positive value is
a strict concurrency maximum, not a promise that the database or fixture will
produce that much overlap. `maintenance.RunGCWithDB` remains the serial
compatibility entry; a worker-aware maintenance entry or equivalent private
option carries the normalized maximum. Maintenance exclusively owns scheduling.
Engine validates, forwards, projects the result, then translates errors.

## Serial preparation and pass boundary

One invocation retains one dedicated PostgreSQL connection for the advisory
lock. Advisory locking, integrity checks, reachability, reachable-chunk
collection, live packed/legacy unit-map construction, and candidate planning
remain serial.

The sealed query is fully materialized and closed before execution begins.
Candidates are sorted by container ID ascending and then filename ascending.
All started sealed units become terminal and sealed aggregation completes
before active discovery. Live-only active discovery is then materialized,
closed, and sorted by the same key. Legacy dry-run has no active pass.

The global plan index is the sealed order followed by the active order. It is
the only authority for public filenames, affected count, byte accumulation,
and error ordering.

## Bounded coordinator

The coordinator holds at most the effective worker count in flight. It creates
no goroutine per undispatched candidate and maintains no queued candidate
backlog. Initial dispatch fills only the available in-flight slots.

When a unit returns a non-error terminal result, the coordinator may dispatch
the next candidate. This definition includes all three normal outcomes:

- `affected`;
- `retained`;
- `skipped`.

A retained or skipped result with nil error never stops scheduling. “Success”
in this scheduler means any non-error terminal result, not only physical
reclamation.

A unit error, caller cancellation/deadline, or another explicitly frozen stop
condition closes dispatch. No additional unit starts after the coordinator
observes that condition. Units already started continue with the real caller
context to their existing safe terminal boundary; the coordinator waits for
all of them and retains their real outcomes. It does not cancel, invent, or
discard a started outcome merely because a peer failed. No goroutine or channel
may leak.

## Unit and observer ownership

Each unit owns one independent transaction from `database/sql.DB`; no
transaction is shared. Candidate data and preflight maps are immutable. The
unit returns a private result equivalent to:

```text
global plan index
unit kind: sealed or active
container ID and filename
terminal outcome: affected, retained, or skipped
captured physical bytes, when creditable
unit error
```

Workers never mutate `GCResult`, filename slices, counters, byte totals, or a
shared error. The existing Phase 3 observer is invoked exactly once by the
executing unit at its begin boundary, before unit work that the deterministic
test gate controls. It remains invocation-local and nil by default.

## Deterministic aggregation and partial results

After all started units in a pass are terminal, the coordinator aggregates
private results in global plan order. `SnapshotRetainedContainers` preserves
its current sealed retained population; an active retained/skipped candidate
does not increment it.

Every physically successful unit contributes its affected entry and filename.
Byte credit follows the separate byte-accounting design. Unit errors are joined
in global plan-index order. The first accounting-overflow error occupies the
first overflowing unit's plan position. An otherwise unrepresented caller
cancellation/deadline follows plan-indexed errors. Advisory-unlock failure is
joined last. Worker completion timing does not affect the public result or the
error chain.

Current maintenance behavior:

```text
sealed error -> return GCResult{}, error
active error -> return GCResult{}, error
```

Phase 11 behavior:

```text
aggregate every terminal started-unit result
-> return accumulated GCResult + non-nil error
```

Preflight errors before meaningful execution retain a zero result. Engine
projects the returned maintenance result before translating its error.
Deferred advisory unlock joins its error without replacing the accumulated
result.

## PostgreSQL pool and transaction proof

`database/sql.DB` is concurrency-safe, and a transaction is bound to a single
pool connection. The advisory lock owns one dedicated connection for the
invocation; each worker unit obtains its own transaction. Materializing the
candidate cursor before dispatch avoids a cursor/worker connection hazard.
Immutable inputs and private outputs avoid shared-memory result hazards.

Row locks, foreign keys, exact-one deletion checks, and valid-schema ownership
of a physical container cause conflicting or stale work to fail closed. No
production pool value changes and no dedicated worker connection is reserved.
If pool capacity is below requested concurrency, the pool may serialize units.
Workers remains an upper bound.

## Deterministic regression environment

The PostgreSQL actual-overlap proof uses at least two reclaimable units and
sets the fixture DB to `SetMaxOpenConns(3)`: one connection for the advisory
lock and at least two simultaneous worker transactions. With `Workers=2`, each
Phase 3 observer callback reports entry, increments active/max counters, and
blocks on channel gates. The test waits until both units have entered, asserts
`maxObserved >= 2` and `maxObserved <= 2`, releases both gates without sleeps,
and verifies plan-ordered results. A smaller-pool PostgreSQL case proves natural
serialization and successful completion without rejecting `Workers=2`.

SQLite dry-run proves effective limits, deterministic result/error ordering,
non-error continued dispatch, stop-new-dispatch, already-started outcomes, and
correctness. Actual overlap greater than one is not required on SQLite.

The focused matrix also proves `Workers=-1`, `0`, `1`, `2`, and a larger value;
nil observer behavior; retained and skipped continuation; unit failure and
caller cancellation; multiple error ordering; unlock failure; pass separation;
no undispatched credit; and race-detector safety.
