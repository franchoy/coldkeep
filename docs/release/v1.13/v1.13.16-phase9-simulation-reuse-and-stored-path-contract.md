## CK-V11316-005

Simulation duplicate reuse is determined by candidate content identity plus a
complete, internally consistent simulation-local catalog graph. The storage
implementation must use an explicit private validation scope distinguishing
full repository validation from simulation graph-only validation. The zero
scope is invalid, full validation requires a nonblank container directory,
and an empty string must never select graph-only behavior.

Simulation derives graph-only scope only from `StorageContext.IsSimulated()`.
It may read candidate source files and mutate its disposable SQLite catalog.
It must not access the live repository catalog, open or read repository
containers, write temporary payload files, perform semantic decode/hash replay,
or depend on filesystem emptiness. `COLDKEEP_REUSE_SEMANTIC_VALIDATION` remains
authoritative for full repository Store but cannot trigger payload validation
in simulated scope.

Logical identity remains `(file_hash,total_size)` and chunk identity remains
`(chunk_hash,size)`. Reuse requires completed objects, contiguous recipe
ordering, valid chunk/container placement metadata, and valid legacy or packed
relationships. Zero-byte content requires zero `file_chunk` rows. Roots,
current path count, snapshot-only retention, pins, live refs, codec,
compression, and chunker version are not identity keys. Invalid graphs are not
reused and follow existing safe rebuild/fail-closed behavior. Quarantine and
real Store semantic policies are unchanged.

Public `StoreFileResult`, Engine Store, `SimulateStoreReport`, human output,
and JSON shapes do not change. No per-file reuse output is added.

## CK-V11316-006

Restore-specific help must publish both accepted forms:

```text
coldkeep restore <fileID> [<fileID> ...] <outputDir>
  [--input <file>] [--dry-run] [--overwrite] [--fail-fast]
  [--output <human|text|json>] [--json]

coldkeep restore --stored-path <path>
  [--mode <original|prefix|override>] [--destination <path>]
  [--overwrite] [--strict|--no-metadata]
  [--output <human|text|json>] [--json]
```

`restore --help` and `restore -h` exit zero without coordination, recovery,
database access, Engine/session construction, or filesystem mutation.
Stored-path mode accepts no positionals. Explicit blank stored-path, mode, or
destination values are usage errors. Mode defaults to `original`; original
forbids destination, while prefix and override require it. Mode, destination,
strict, and no-metadata are stored-path-only; strict and no-metadata are
mutually exclusive. Input, dry-run, and fail-fast remain unsupported with
stored-path mode. Overwrite remains valid in both modes.

`--output json` and `--json` independently select the existing JSON projection;
their existing combination conflict remains. Human success lines, JSON
envelope and keys, by-ID results, Engine contracts, and Phase 6 restore safety
and retention semantics remain unchanged.
