typed error unchanged, preserves cancellation/deadline and underlying cause

Deterministic driver tests cover query, scan, and row-iteration failures and

## 6. Packed file-deep verification

File-deep verification now consumes `Catalog.LoadChunkPlacements` as its sole
placement authority and visits every ordered recipe entry. Legacy placements
retain their decode/size/hash path. Packed placements verify the stored block,
authoritative table entry and range, exact reconstructed segment, plain size,
and chunk hash. Successful packed-block verification is cached by block while
each segment and chunk remains independently validated. Missing, malformed,
conflicting, incomplete, corrupt, or unsupported placement fails closed.

Healthy legacy, packed, and mixed recipes plus packed chunk-hash corruption
are covered. Public result shape is unchanged and checked counts now reflect
authoritative placements.

Changed files: `internal/verify/verify_file.go`, new
`internal/verify/verify_file_placement.go`, and new
`internal/verify/verify_file_placement_test.go`.

## 7. `simulate gc` coordination

Coordinator internals, repository identity, advisory locks, and GC algorithms

Policy and runtime tests prove acquisition before startup/recovery, cleanup

## 8. Exact restore routing

The storage restore primitive treats its output as an exact file destination.
It no longer appends the original basename when the target is an existing
directory or has a trailing separator. Directory-oriented Engine and
compatibility routes resolve the final child before entering storage, so dry
and live routes retain one final path meaning.

Tests prove existing-directory and trailing-separator rejection without
creating a reinterpreted child, plus the existing by-ID, stored-path,
snapshot-selector, Engine, and CLI routing matrices.

Changed files: `internal/storage/restore.go`, `restore_test.go`, and new
`restore_exact_destination_test.go`.

## 9. Secure installer

The new internal `fsx/secureinstall` package owns exact-destination temporary
creation, writer sync/close, atomic publication, retained-object metadata, and
confined cleanup.

- Linux retains directory/object descriptors, uses
  `Renameat2(RENAME_NOREPLACE)`, uses `Linkat` only as the approved atomic
  fallback, and otherwise fails closed. Intentional overwrite uses
  handle-relative rename.
- Darwin uses pinned `RenameatxNp(RENAME_EXCL)`, the approved atomic `Linkat`
  fallback, and fail-closed behavior. Both pinned Darwin architectures compile.
- Windows creates relative to retained handles with `NtCreateFile`, keeps the
  exact temporary-object handle after closing the duplicated writer, and
  publishes that object with `NtSetInformationFile(FileRenameInformation)`.
  It never reopens the temporary object by pathname.
- Unsupported platforms fail closed.

All platforms traverse below the retained boundary without following
symlinks/reparse points. Path identity checks fail closed; handle-relative
mutation remains authoritative. The implementation does not claim protection
against hostile relocation of an already-open Unix directory object.

The new files are the five production files and four test files under
`internal/fsx/secureinstall/`, exactly as authorized.

## 10. Restore integration and metadata

All production storage and snapshot restore paths now reconstruct into the
secure installer, verify bytes before publication, synchronize and close the
writer while retaining object identity, publish atomically, synchronize the
parent where supported, and apply metadata through the retained published
object. Cleanup is relative to retained authority.

Strict metadata application failure remains post-publication: it returns an
error while correct bytes remain visible. Best-effort failure returns a
structured warning. Neither path removes published content. Stored-path
incomplete-metadata behavior is preserved, and snapshot warnings are mapped
without changing their public projection.

Linux fault tests prove final-window occupation, atomic fallback/fail-closed
behavior, parent replacement before create/publication, trusted-root symlink
rejection, destination preservation, truthful sync errors, post-publication
strict/best-effort metadata behavior, retained-object metadata after pathname
replacement, and retained-parent cleanup. Storage fault seams prove sync,
publish, abort, and warning propagation. Existing pin, legacy, packed, mixed,
snapshot, Engine, CLI, and G5 routes remain green.

Integration changed `internal/storage/restore.go`, `restore_test.go`,
`restore_faultfs_test.go`, `internal/snapshot/snapshot.go`,
`snapshot_test.go`, and the secure-installer common/platform files and Linux
tests.
