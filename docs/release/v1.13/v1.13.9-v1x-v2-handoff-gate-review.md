## v2.0 handoff statement

`v2.0` implementation may begin after `v1.13.9` release closure completes,
provided the final pre-release validation and single release PR are also
finished cleanly.

Mandatory early-`v2.0` constraints:

- preserve engine-owned snapshot mutation execution for create, delete, and
  restore
- preserve explicit unsupported boundaries for partial active engine surfaces
  such as recursive `Engine.Store`
- preserve the current dependency direction and invariant protections
- preserve PostgreSQL compatibility gates and the documented SQLite portability
  baseline
- preserve explicit CLI ownership of `doctor` and `repair` until a later
  corrective-boundary redesign is intentionally activated

Deferred later `v2.x` work remains:

- daemon, API, UI, and broader productization
- broader routing and backend redesign beyond the proven `v1.13.x` seams
- any repair/recovery activation beyond current checked-in ownership
