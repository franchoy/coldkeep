## Active Contract Added

Phase 6 added this active engine method:

```go
RestoreStoredPath(
	ctx context.Context,
	req RestoreStoredPathRequest,
) (RestoreStoredPathResult, error)
```

And these dedicated active types:

```go
type RestoreStoredPathRequest struct {
	StoredPath      string
	DestinationMode RestoreDestinationMode
	DestinationRoot string
	DestinationPath string
	Overwrite       bool
	StrictMetadata  bool
	NoMetadata      bool
}

type RestoreStoredPathResult struct {
	StoredPath      string
	FileID          int64
	DestinationMode RestoreDestinationMode
	DestinationPath string
	RestoredHash    string
}
```

## Validation and Delegation Rules

The new engine boundary now follows this exact order:

1. `ctx.Err()` short-circuit
2. trim `StoredPath`
3. reject blank stored path
4. reject `StrictMetadata && NoMetadata`
5. default empty mode to `RestoreDestinationOriginal`
6. validate destination-field consistency by mode
7. validate engine dependencies
8. invoke storage

Locked validation errors:

- `engine: restore stored path is required`
- `engine: restore stored path strict metadata and no metadata are mutually exclusive`
- `engine: restore stored path original mode does not accept a destination root`
- `engine: restore stored path original mode does not accept a destination path`
- `engine: restore stored path prefix mode requires a destination root`
- `engine: restore stored path prefix mode does not accept an exact destination path`
- `engine: restore stored path override mode requires an exact destination path`
- `engine: restore stored path override mode does not accept a destination root`
- `engine: invalid restore stored-path destination mode %q`
- `engine: restore stored path database is required`
- `engine: restore stored path container directory is required`

The engine trims stored-path text only. It does not canonicalize, absolutize,
symlink-resolve, or case-normalize `StoredPath`.

## Storage Delegation Outcome

`DefaultEngine.RestoreStoredPath` now:

- validates the typed request and active dependencies;
- builds storage context only from the engine DB and effective container
  directory;
- translates destination mode explicitly to the storage restore mode;
- forwards `Overwrite`, `StrictMetadata`, and `NoMetadata`;
- calls `storage.RestoreFileByStoredPathWithStorageContextResultOptions`;
- maps storage success to `RestoreStoredPathResult`;
- returns storage/domain failures unchanged;
- never returns `ErrNotImplemented`.

The truthful mutation contract remains unchanged:

- no logical-file identity mutation;
- no current mapping mutation;
- no `logical_file.ref_count` mutation;
- no snapshot mutation;
- no `file_chunk` ownership mutation;
- no `chunk.live_ref_count` mutation;
- temporary `chunk.pin_count` mutation remains storage-owned and is released on
  success and failure.

## CLI Boundary Preserved

Production `cmd/coldkeep/main.go` was intentionally left unchanged.

Stored-path CLI restore still:

- keeps its current validation order;
- keeps its current human output;
- keeps its current JSON `output_path`;
- calls `storage.RestoreFileByStoredPathWithStorageContextResultOptions`
  directly;
- does not call `Engine.RestoreStoredPath`.

`TestRestoreStoredPathPreservesDirectCLIStoragePath` remained green as the
boundary proof.
