## 1. Purpose

Phase 6 ends discovery-driven audit disposition and freezes one bounded
remediation contract from the Phase 2–5 evidence. It changes documentation
only. It neither fixes a finding nor designs an implementation, and completion
does not mean that v1.x is ready to close.

## 3. Classification rules

A finding is a `V1_X_BLOCKER` only when all four tests hold:

1. its frozen requirement is mandatory before v1 closure;
2. current Phase 2–5 evidence proves the gap;
3. no authoritative explicit bound excludes the affected behavior; and
4. closure without remediation would contradict the frozen contract.

Expected classifications were treated as hypotheses. No finding was changed
for convenience, and Phase 6 preserves historical audit verdicts while making
the separate final-closure disposition. Blockers use `OPEN_FROZEN`; all other
items use `NOT_REQUIRED_FOR_V1_CLOSURE` and have one named destination.

## 5. `P2-ARCH-001` disposition

Phase 2 correctly reported the source state as `PARTIAL` with zero findings it
then classified as an architecture blocker. It also explicitly deferred the
v1-closure disposition. Phase 6 does not rewrite that audit result; it applies
the closure test.

`V1R-CAT-003` says the Catalog exposes neutral DTOs and typed errors, is
mandatory before v1, and contains no consumer, backend, or library-only
exception. Five aggregate methods still expose raw wrapped database errors.
Engine translation stabilizes only the two present production snapshot
consumers. That translation cannot satisfy a reusable Catalog boundary, and
the lack of current consumers for the other three methods is not an
authoritative scope bound. Closing v1 would therefore ship an incomplete
mandatory Catalog contract. Final disposition: `V1_X_BLOCKER`, owned by
`WS-CATALOG-TYPED-ERRORS`.

## 6. `P3-COR-001` disposition

Atomic non-destructive restore publication and authoritative exact
destinations are mandatory under `V1R-COR-001`, `V1R-COR-005`, and
`V1R-XPLAT-002`. The final no-overwrite check/rename window and lower-layer
directory reinterpretation affect every live route and have no backend or
platform deferral. Final disposition: `V1_X_BLOCKER`, owned by
`WS-RESTORE-DESTINATION`.

## 7. `P3-COR-002` disposition

`V1R-COR-004` requires destination confinement at the actual mutation
boundary. Source proves that path-component validation and later path-string
mutation are separate, allowing parent replacement after validation. This is
not the same invariant as atomic publication, even if one secure primitive may
close both. Final disposition: distinct `V1_X_BLOCKER`, also owned by
`WS-RESTORE-DESTINATION`.

## 8. `P3-COR-003` disposition

Fail-closed deep verification and packed/legacy/mixed compatibility are
mandatory under `V1R-COR-006` and `V1R-COR-007`. The legacy-only inner join
can return false success for packed-only content and incomplete success for
mixed content. No product or backend bound excludes those repository shapes.
Final disposition: `V1_X_BLOCKER`, owned by `WS-VERIFY-PACKED-DEEP`.

## 9. `P4-BE-001` disposition

Backend-neutral shared claims are mandatory under `V1R-BE-003`. The case
policy is not inferred from SQLite's default:

1. production current-file substring search uses
   `LOWER(path) LIKE LOWER(filter)`;
2. the pre-Catalog snapshot-list implementation used
   `LOWER(label) LIKE LOWER(filter)`;
3. SQLite's current result therefore preserves an existing Coldkeep query
   convention; and
4. the Catalog refactor changed the query to backend-native `LIKE` without
   declaring a new case-sensitive contract, creating the PostgreSQL split.

The frozen behavior is narrow ASCII case-insensitive substring matching for
snapshot labels across both supported backends. Locale-aware Unicode folding
or normalization is not included. Final disposition: `V1_X_BLOCKER`, owned by
`WS-BACKEND-LABEL-SEMANTICS`.

## 10. `P5-COORD-001` disposition

`V1R-COORD-001` mandates the bounded same-host/local-filesystem ownership
contract for cooperative Coldkeep processes. `simulate gc` is not isolated:
it opens the real application session and may run PostgreSQL schema work plus
GC planning while bypassing the native lease. Neither the word `simulate` nor
statement-level SQL coherence is an authoritative exception. Final
disposition: `V1_X_BLOCKER`, owned by
`WS-SIMULATE-GC-COORDINATION`.

## 11. Finding deduplication

All six IDs remain distinct roots. `P3-COR-001` and `P3-COR-002` share one
workstream because their safe implementation boundary overlaps, but atomic
publication and parent-identity confinement remain independently testable.
`P4-BE-001` is not a typed-error manifestation, and `P5-COORD-001` is one
policy root rather than separate schema and planning roots. No backend or
platform manifestation is double-counted.

## 14. Workstream dependencies

Catalog typed errors and snapshot-label semantics overlap the snapshot Catalog
query path. Phase 7 must co-design them, and Phase 8 must establish error
translation before or atomically with label normalization. Restore,
file-deep verification, and simulate-GC coordination are independent of that
overlap and of one another. Phase 9 follows completion of all Phase 8 changes.

## 15. Required regression contracts

Every workstream has frozen named obligations covering affected operations,
failure behavior, backends, platforms, fault injection, and race execution
where applicable. The contracts require all five Catalog methods and both
backends; every restore selector plus final-window and parent-swap adversaries
on Linux/macOS/Windows; packed/legacy/mixed file-deep corruption on both
backends; opposite-case limited/unlimited snapshot queries through Catalog,
Engine, and CLI; and simulate-GC startup ordering, real-holder contention,
safe exceptions, PostgreSQL subprocess behavior, and relevant races.

## 16. V2 deferral freeze

The [deferred-item matrix](v1.13.13-deferred-item-classification-matrix.md)
freezes v2 productization for `coldkeepd`, one local mutation owner, queue and
maintenance barriers, SQLite-default repository-local catalogs, clean-close
portability, daemon-backed CLI, local API/UI, scheduling, catalog transfer and
backup, local recovery workflows, normal-user SQLite live-GC flow, and
retained PostgreSQL compatibility. These deferrals retain every v1
correctness, backend, and compatibility guarantee.

## 17. V3 deferral freeze

V3 owns the network-exposed service and remote clients, NAS/multiple roots,
NFS/SMB/network filesystems, centralized PostgreSQL product mode,
multi-user/auth, cloud/object/S3 storage, replication/sync, cross-machine
coordination, and distributed locking. PostgreSQL advisory-session ownership
does not imply a cross-host repository lock.

## 18. Documentation debt

paragraphs in `docs/architecture/engine-boundary-plan.md` cannot downgrade

nonhistorical reconciliation; Phase 6 does not edit that document.

## 22. Phase 7 authorization contract

Phase 7 may design only the five frozen workstreams and their exact regression
fixtures. It must not implement a fix, add a feature, reopen a settled
deferral, merge finding identities for convenience, or begin Phase 8. It must
return a design that lets implementation proceed without reopening scope.

## 23. Phase 8 implementation contract

Phase 8 may implement the minimum approved design and tests for the six
blockers. It may not redesign APIs, schemas, formats, products, or unrelated
architecture unless Phase 7 proves a frozen outcome cannot otherwise be met
and records the narrowly necessary change. Phase 8 does not itself close a
blocker.

## 24. Phase 9 closure-proof contract

Phase 9 must execute every frozen targeted, adversarial, fault, race,
platform, and backend contract. Each blocker closes separately only when its
source outcome and full evidence are green. A workstream containing two roots
does not permit one root's proof to stand in for the other.

## 25. Post-remediation closure condition

Phase 10 may begin only when all six blocker statuses are `CLOSED`, all
required Phase 7–9 contracts pass, no Phase 8 regression is known, and
release-state validation succeeds. This is a necessary gate, not formal v1.x
approval; Phase 13 retains the closure decision.

## 26. Phase 10–16 unchanged responsibilities

Phase 10 reconciles current documentation, Phase 11 runs the independent full
local release gate, Phase 12 owns hosted security/quality evidence, Phase 13
makes the formal closure decision, Phase 14 records closure and v2 handoff,
Phase 15 owns merge/post-merge truth, and Phase 16 owns tag, tag CI, and stable
publication. Their order and responsibilities are unchanged.

## 27. Late-finding policy

A serious omitted technical root discovered after this freeze must be recorded
as `PHASE6_LATE_BLOCKER_CANDIDATE` with requirement, evidence, scope, and
deduplication analysis. It cannot be silently folded into a workstream or
fixed without explicit classification and authorization. Phase 6 found zero
such candidates.
