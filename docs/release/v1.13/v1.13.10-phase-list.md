## Phase 4 — Release-State Validator Contract

**Status:** Complete

Phase 4 created the canonical contract
`v1.13.10-release-state-validator-contract.md`. It froze the dependency-free
validator's four lifecycle states, local-versus-manual evidence boundary,
source-of-truth hierarchy, bounded current-versus-historical parsing model,
CKRS001–CKRS019 rule catalogue, deterministic human and JSON interfaces, exit
codes, fixture requirements, CI integration, and exact Phase 5 boundary.

The contract resolves the immutable-tag evidence problem by requiring
complete pre-tag evidence in the tagged tree and a later documentation closure
commit before the next version becomes active. External publication, CI,
Codacy, and remote branch-deletion facts remain manual rather than being
misrepresented as locally verifiable.

Phase 4 acceptance criteria:

- the canonical Phase 4 artifact contains every required contract section;
- the lifecycle model covers development, pre-release, merged-not-tagged, and
  released Git contexts without network access;
- the parsing model is structurally bounded and does not scan historical prose
  as current state;
- stable CKRS rules, deterministic output, exit codes, and all mandatory
  fixture cases are frozen;
- Phase 5 may implement only the validator, its isolated tests, checklist and
  CI integration, CI-audit enforcement, and normal active tracker updates;
- no validator, script, workflow, runtime, historical-document, or release
  publication change lands in Phase 4; and
- the contract verdict is `RELEASE-STATE VALIDATOR CONTRACT FROZEN`.

Phase 4 is complete.
