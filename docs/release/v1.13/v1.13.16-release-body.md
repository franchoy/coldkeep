## Coldkeep v1.13.16

### Exceptional critical-maintenance scope

Coldkeep v1.13.16 is the separately authorized exceptional critical-maintenance release. It repairs correctness, release-proof, and documentation/process defects found after v1.13.15 without opening a new feature train. v1.13.15 remains immutable published stable history and the final planned v1 release; its tag, release body, checksum, and publication evidence are not rewritten.

### Correctness and integrity repairs

- Makes snapshot capture and selection paths relative to the declared source root, rejects selector mismatches atomically, and preserves deterministic restore mapping.
- Aligns snapshot retention, Remove, GC, Restore, verification, and repair so reachable legacy and packed data remains protected while truly unreachable data can be reclaimed.
- Reports physical-file, retained, and reclaimable accounting from authoritative reachability without double-counting packed storage.
- Hardens Store/repair convergence and schema-17 compatibility so failed duplicate stores cannot destroy an existing completed object's authoritative recipe and pre-v17 binaries fail closed.
- Certifies the CK-V11316-009 through CK-V11316-015 reliability and enforcement recoveries, including required named SQLite/PostgreSQL proofs and benchmark provenance.
- Completes the CK-V11316-007 documentation/process candidate after the full Phase 13 audit, remediation, hosted evidence, and independent 8-of-8 re-audit.

### Compatibility, security, and certification

The established public API, stable JSON, repository, storage, and container-format boundaries remain compatible, and supported SQLite and PostgreSQL behavior remains aligned. The module language floor is Go 1.25; release-critical certification uses exact Go 1.26.7 with `GOTOOLCHAIN=local`.

Blocking local and exact-head evidence covers CI, Required Gate, CodeQL, reachable-vulnerability scanning, governance, cross-platform behavior, correctness, and benchmark integrity. Coldkeep remains integrity-first rather than a hardened defense against an attacker who can modify both catalog and storage. Distribution is source-only.

### Source-only installation

The final release will provide no prebuilt Coldkeep executable or custom binary asset. After the `v1.13.16` tag is published, use Go 1.26.7 and a supported native C compiler on the certified OS families.

Linux and macOS:

```bash
GOTOOLCHAIN=local go install github.com/franchoy/coldkeep/cmd/coldkeep@v1.13.16
```

Windows PowerShell:

```powershell
$env:GOTOOLCHAIN = 'local'
go install github.com/franchoy/coldkeep/cmd/coldkeep@v1.13.16
```

These commands become usable only after the tag is published.

### Lifecycle boundary

Materializing this canonical body does not merge the release branch, create a tag, or publish a GitHub release. Phases 14 through 18 remain future release operations. This candidate does not establish final v1.x repository closure: `V1_X_FULL_CLOSURE: NOT_ESTABLISHED`. Only Phase 19T may establish `V1_X: FULLY_CLOSED`. V2 implementation remains unauthorized by this release-body materialization and requires a separate plan.
