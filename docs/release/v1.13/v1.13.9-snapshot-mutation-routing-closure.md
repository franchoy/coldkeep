# v1.13.9 Phase 12 — Snapshot mutation routing closure and boundary hardening

Starting SHA: `1066a8a01c5e4c3325fa0ec53c3d3b11b442ce33`

## Summary

Phase 12 closes the snapshot mutation routing boundary after all three
production CLI snapshot mutations became engine-routed in earlier phases.

This phase does not change snapshot mutation semantics. It hardens and records
the ownership boundary so production CLI routing, compatibility seams, and
boundary evidence are explicit and non-misleading.

## Active production CLI routing

- `snapshot create` -> `Engine.SnapshotCreate`
- `snapshot delete` -> `Engine.SnapshotDelete`
- `snapshot restore` -> `Engine.SnapshotRestore`

No production CLI snapshot mutation path should call the legacy direct
snapshot-domain seams.

## Remaining compatibility seams

The following direct seams intentionally remain:

- `createSnapshotPhase = snapshot.CreateSnapshotWithOptions`
- `deleteSnapshotPhase = snapshot.DeleteSnapshot`
- `snapshotDeleteLineagePreviewPhase = loadSnapshotDeleteLineagePreview`
- `restoreSnapshotPhase = snapshot.RestoreSnapshot`

These remain only for lower-level compatibility tests and non-CLI callers.
They are no longer part of the production CLI mutation routes.

## Boundary hardening completed

- updated compatibility-seam comments in `cmd/coldkeep/main.go` so they state
  active engine ownership and compatibility-only direct seams explicitly;
- removed the stale `restoreSnapshotPhase` keepalive artifact;
- strengthened restore routing tests so production CLI restore fails if the
  legacy direct restore seam is touched;
- corrected stale restore test wording that still referenced the legacy seam.
