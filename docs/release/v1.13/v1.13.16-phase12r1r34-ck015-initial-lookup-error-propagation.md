## Defect and correction contract

`tryRepairCompletedLogicalFile` scans `id,status`, then currently tests the
possibly unassigned `status` before a non-`sql.ErrNoRows` error. The helper's
sole caller tests `handled` first; `(false, zero, nil)` therefore admits the
legacy claim/reuse-failure path. If the one-shot lookup failure clears, that
path can demote a degraded completed object and delete its authoritative
recipe. No shared transaction or later rollback prevents that source-level
consequence.

The only production correction is this decision order in
`internal/storage/store_repair.go`:

```go
if errors.Is(err, sql.ErrNoRows) {
    return false, StoreFileResult{}, nil
}
if err != nil {
    return true, StoreFileResult{}, err
}
if status != filestate.LogicalFileCompleted {
    return false, StoreFileResult{}, nil
}
```

The query, return tuple, caller, completed-repair state machine, schema, public
API, dependencies, workflows, and storage/container formats remain unchanged.

one-shot connector/connection wrapper around the existing SQLite and
PostgreSQL drivers. It must match only the normalized initial query, consume
exactly one operational-error, partial-Scan, or no-row response, remain usable
afterward, and count any fallback `INSERT INTO logical_file`. It may not use
`driver.ErrBadConn`, global state, a production hook, an exported API, a new
dependency, randomness, sleep, or an environment bypass.

Exactly five named tests cover SQLite operational error, SQLite partial Scan,
SQLite no rows, SQLite supported status routing, and PostgreSQL operational
error. The error tests require original cause propagation, `AlreadyStored`
false, one consumed fault, zero fallback claims, unchanged logical/recipe/
chunk/placement/container/mapping/pin/liveness/snapshot authority, no repair
attempt or staged payload, exact held-byte restoration, and immediate plus
supported post-reopen Restore. The no-row and successful-status tests preserve
ordinary routing. Existing packed/legacy, successful/failing repair, retry,
contention, convergence, simulation, codec, compression, and backend controls
remain required.
