## Defect and correction contract

`tryRepairCompletedLogicalFile` scans `id,status`, then currently tests the
possibly unassigned `status` before a non-`sql.ErrNoRows` error. The helper's
sole caller tests `handled` first; `(false, zero, nil)` therefore admits the
legacy claim/reuse-failure path. If the one-shot lookup failure clears, that
path can demote a degraded completed object and delete its authoritative
recipe. No shared transaction or later rollback prevents that source-level
consequence.

The only production correction is this decision order in
`internal/storage/store_repair.go`:

```go
if errors.Is(err, sql.ErrNoRows) {
    return false, StoreFileResult{}, nil
}
if err != nil {
    return true, StoreFileResult{}, err
}
if status != filestate.LogicalFileCompleted {
    return false, StoreFileResult{}, nil
}
```

The query, return tuple, caller, completed-repair state machine, schema, public
API, dependencies, workflows, and storage/container formats remain unchanged.
