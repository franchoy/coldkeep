## 3. Root-cause classification

`TestReuseRefusesSemanticallyCorruptedCompletedFile` previously overwrote one
stored byte with fixed value `0xEE`. AES-GCM produces variable ciphertext, so
the target byte could already equal `0xEE`. In that case the write made no byte
change, semantic reuse correctly observed intact storage, and the test
incorrectly failed its expectation that the `AlreadyStored` shortcut be
refused.

## 4. Corrective test commit

The corrective commit is:

```text
CORRECTIVE_TEST_COMMIT: bd84206a1de5fc5568e83abcfae1e382f44c2ba1
CORRECTIVE_TEST_PARENT: 1668a7490048144f4dea0fd795f4779b5e7108b5
AUTHORIZED_PRODUCT_CHANGES: 0
AUTHORIZED_TEST_FILES_CHANGED: 1
AUTHORIZED_TEST_FILE: tests/integration/integration_test.go
PRODUCT_BEHAVIOR_CHANGED: NO
```

Packed AES-GCM payloads use the stored layout `nonce (12 bytes) ||
ciphertext`. The test record's `block_offset` is the start passed to payload
reads and `stored_size` is its on-disk bound. The correction therefore targets
`block_offset + 12`, the first ciphertext byte for AES-GCM and an in-bounds
payload byte for plain storage. It reads the original byte, XORs it with
nonzero mask `0x01`, and writes the result. XOR with a nonzero mask guarantees
the persisted byte differs for every possible original value.

No production path or test assertion changed. The test continues to prove that
semantic corruption prevents reuse of a completed file and forces a truthful
rebuild.
