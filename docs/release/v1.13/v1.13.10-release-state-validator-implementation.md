# Coldkeep v1.13.10 Phase 5 — Release-State Validator Implementation and CI Integration

## Purpose

Implement and enforce the frozen Phase 4 release-state validator contract.

## Implemented files

- `scripts/validate_release_state.py`
- `scripts/test_validate_release_state.py`
- CI quality-job, local CI-audit, and pre-release checklist integration.

## Lifecycle inference

The standard-library validator derives the source version and evaluates
`development`, `pre-release`, `merged-not-tagged`, and `released` from local
Git state and the allowed GitHub environment fields. It accepts release-branch
and pull-request merge-ref contexts, `main`, and detached annotated tags.

## Implemented rule catalogue

All frozen rules are implemented: `CKRS001`, `CKRS002`, `CKRS003`, `CKRS004`,
`CKRS005`, `CKRS006`, `CKRS007`, `CKRS008`, `CKRS009`, `CKRS010`, `CKRS011`,
`CKRS012`, `CKRS013`, `CKRS014`, `CKRS015`, `CKRS016`, `CKRS017`, `CKRS018`,
and `CKRS019`.

## Current versus historical parsing

The implementation parses only bounded current README, release README, and
release-train sections. Historical branch, pending, and retired-proposal text
is retained as evidence and does not trigger current-state rules.

## Human and JSON interfaces

The validator emits deterministic, sorted human violations or exactly one
compact JSON object. It returns `0` for success, `1` for CKRS violations, and
`2` for usage, layout, Git, parser, or internal errors. It has no repair or
network behavior.

## Fixture and negative-test coverage

The 44-test standard-library `unittest` suite creates isolated temporary Git
repositories. It covers every CKRS rule, malformed source, document and phase
drift, artifact resolution, release branch/PR/main/tag contexts, explicit
roots, cross-directory invocation, deterministic output, JSON, and exit-code
boundaries.

## CI integration

The quality checkout now fetches full history. Every quality execution runs
the fixture suite. A blocking real-repository validator step runs only for
release branches, release pull requests, `main`, and version tags; it neither
uses the network nor uploads JSON artifacts.

## CI enforcement audit

The local audit extracts the quality job and exact named validator steps. It
requires checkout depth zero, exact commands, all lifecycle condition parts,
and no failure suppression.

## Local pre-release integration

The quality-equivalent checklist runs fixture tests then auto-state validation.
It documents that the fixture suite is branch-independent while real-state
validation expects an active release branch, main candidate, or tag checkout.

## Automated and manual evidence boundary

Local documentation, phase, artifact, branch, and annotated-tag evidence is
automated. GitHub publication, remote branch deletion, external CI results,
and Codacy remain manual post-tag evidence.

## Explicit non-changes

No runtime source, Go tests, schema, migration, historical v1.13.9 evidence,
release tag, PR, or release was changed. No third-party Python dependency,
network integration, auto-repair, JSON artifact upload, or
`actions/upload-artifact` migration was introduced.

## Validation evidence

Static compilation, help output, 44 isolated validator tests, explicit
unittest execution, auto/explicit/root/JSON real-repository validation,
shell syntax, local CI audit, documentation checks, and exact scope review
passed.
