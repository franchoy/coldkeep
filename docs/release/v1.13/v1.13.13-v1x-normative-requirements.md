## Frozen v2 productization boundary

`V2_PRODUCTIZATION` consists of `coldkeepd`, one local mutation owner, a
mutation queue, daemon maintenance barriers, SQLite-default repositories and a
repository-local catalog, clean-close portability, a daemon-backed CLI, local
API/UI, scheduling, catalog export/import/backup, local recovery workflows,
and retained PostgreSQL compatibility.

The v1 CLI requirement means a thin local Engine wrapper. The v2 CLI decision
means a thin daemon-backed client. This phase authorizes neither implementation
nor Phase 2 audit work.

## Frozen v3 network-expansion boundary

`V3_NETWORK_EXPANSION` consists of a network-exposed service, LAN/remote
clients, NAS or multiple storage roots, NFS/SMB/network-filesystem semantics,
centralized PostgreSQL product mode, multi-user/auth, cloud/object storage,
replication/sync, cross-machine coordination, and distributed operation.
