## Frozen runtime contract

- By-ID `Engine.Remove` remains logical deletion and must return
  `SNAPSHOT_RETAINED_DELETE_BLOCKED` for a snapshot-retained logical file.
- `Engine.RemoveStoredPaths` and storage stored-path unlink remove current
  `physical_file` mappings even when snapshots retain the logical recipe.
- `chunk.live_ref_count` equals the number of `file_chunk` recipe occurrences
  owned by completed logical files having at least one current physical
  mapping. Multiple mappings do not multiply that contribution; repeated
  chunk occurrences do.
- Recipe current-liveness activates exactly once on `ref_count` `0 -> 1` and
  deactivates exactly once on `1 -> 0`. Snapshot membership and restore pins do
  not contribute.
- Store keeps its existing in-progress liveness reservation. First attachment
  of a new already-accounted recipe does not increment again; reattachment of
  an existing completed zero-current recipe does.
- Verify and explicit chunk-live-ref repair use the same current-root formula.
- Snapshot-only content remains reachable through `snapshot_file ->
  logical_file -> file_chunk -> chunk -> placement` for legacy and packed
  storage.
- Live GC may transactionally remove a completed recipe only when it has no
  physical mapping, no snapshot reference, and no pinned recipe chunk. This
  metadata cleanup precedes chunk sweep. Snapshot deletion stays metadata-only,
  and dry-run must model the same eligibility without mutation.

No schema, migration, dependency, public request/result, JSON schema, CLI
syntax, workflow, or error-taxonomy change is authorized.
