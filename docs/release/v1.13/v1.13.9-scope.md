# Coldkeep v1.13.9 Scope

**Release:** `v1.13.9 — Snapshot Mutation Boundary: Create / Delete / Restore`
**Status:** Released and operationally closed
**Historical implementation branch:** `release/v1.13.9` (deleted)
**Starting baseline:** `584d6e8db8f54f4fdf5f4785aad698c71cad66dd`

## Goal

Stabilize truthful ownership boundaries for snapshot mutation by defining the
release frame for snapshot create, snapshot delete, and snapshot restore.

Phase 0A is release-state closure and activation only. Phase 0B addresses the
inherited restore destination trust-boundary finding
`CK-1139-P0-01 — Outer symlink-prefix restore compatibility`. Phase 0C closes
stored-path batch compatibility findings
`CK-1139-P0-02` and `CK-1139-P0-03`.

## Phase 0A release activation objective

Before later implementation phases begin, Phase 0A must:

- close the already-published `v1.13.8` release records truthfully;
- activate `v1.13.9` on `release/v1.13.9`;
- create the `v1.13.9` planning documents;
- change the source version from `1.13.8` to `1.13.9`.

## Required final contract

- snapshot create ownership is explicit and test-backed;
- snapshot delete ownership is explicit and test-backed;
- snapshot restore ownership is explicit and test-backed;
- preview versus live mutation behavior is honest at the engine boundary;
- CLI compatibility is preserved while ownership becomes truthful.

## Release-wide constraints

1. Phase 0A changes only release records and the reported version.
2. The only allowed observable code-behavior change in Phase 0A is that the
   version command reports `1.13.9` instead of `1.13.8`.
3. Restore/remove behavior shipped in `v1.13.8` remains unchanged in Phase 0A.
4. Do not implement snapshot create/delete/restore routing in Phase 0A.
5. Do not implement restore path-safety correction in Phase 0A.
6. Do not implement stored-path batch correction in Phase 0A.
7. PostgreSQL remains the current normal local runtime backend.
8. No schema-version bump unless a later proven requirement makes it
   unavoidable.
9. No storage or repository format change.

## Active corrective finding

`CK-1139-P0-01` requires Coldkeep to:

- allow legitimate system-managed aliases above an explicitly trusted
  destination root;
- continue rejecting symlinks at the trusted root, below the trusted root, and
  at the requested target path;
- preserve fail-closed restore behavior for stored-path and snapshot restore
  surfaces without broad symlink following.

`CK-1139-P0-02` and `CK-1139-P0-03` require Coldkeep to:

- keep stored-path batch summary totals aligned with emitted item results under
  fail-fast execution;
- preserve deterministic blank/duplicate target classification before
  repository initialization when no executable stored-path targets remain.

`CK-1139-P0-04` required Coldkeep to:

- make native cross-platform restore validation part of the required aggregate
  CI gate;
- make release-branch CI and CodeQL validation available without a temporary
  pull request;
- preserve lexical destination-path coverage for normal restore-success tests;
- keep outer aliases above trusted roots allowed while retaining fail-closed
  rejection for symlinks at or below the trusted root.
