## Compatibility finding and correction

The first complete isolated PostgreSQL plain-codec integration attempt found a
real public compatibility regression in the newly routed Doctor startup path:
an application-session open failure returned generic exit code `1` instead of
the frozen recovery exit code `4`. After restoring that classification, the
second complete attempt found the associated message had also lost the frozen
`doctor recovery phase failed:` prefix.

recovery stage and preserves the exact established message. Focused JSON
subprocess contracts passed after the correction, followed by a complete fresh
plain-codec integration run. No storage, schema, transaction, repository,
backend-default, or engine behavior changed.
