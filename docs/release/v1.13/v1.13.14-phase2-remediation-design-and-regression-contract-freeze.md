## 3. Frozen audit-finding designs

### CK-V1-AUD-001 — execution-derived verification results

Verification will carry a private per-invocation ledger from the actual stage
execution path through maintenance to Engine. Ledger keys distinguish legacy
block rows from packed `storage_block` objects and deduplicate references by
authoritative block identity.

`BlocksChecked` counts distinct physical block objects whose required work for
the selected level completed. Physical, compressed, and logical hash counters
count successful comparisons on either supported layout. A compressed-block
count is earned only by successful decompression/validation of a genuinely
compressed non-none payload. Metadata presence, repeated references, skipped
or quarantined objects, unselected stages, and aborted-before-stage work earn
no credit. On verification failure, the public result remains zero-valued.

### CK-V1-AUD-002 — caller context and cleanup ownership

Caller context reaches ordinary Store, Remove, RemoveStoredPaths, Restore,
RestoreStoredPath, Verify, and Doctor-stage work. Sequential batches stop
dispatch after cancellation. Safety cleanup for pins, transactions, writers,
rollback, quarantine, temporary outputs, and repository locks may use the
bounded context returned by `db.NewOperationContext(context.Background())`.
Operation and cleanup failures are composed so cancellation remains visible to
`errors.Is` and cleanup failure is not discarded. Unaffected paths and current
nil-context behavior are not broadened.

### CK-V1-AUD-003 and CK-V1-AUD-004 — GC execution contract

Negative Workers is `invalid_argument`; zero retains serial/default behavior;
a positive value is a strict maximum on concurrently executing per-container
reclaim units. Deterministic planning and output use container ID then filename
order. Cancellation stops new dispatch, and each unit repeats the authoritative
safety checks. Phase 10 owns the detailed scheduler design.

Physical reclaimed bytes come from one filesystem size observation per
container. Dry-run reports the unchanged successful plan; live execution
credits only a successfully removed file. Stat failure, unexpected absence, or
remove failure remains a non-nil fail-safe GC error and is never skipped. The
failed unit earns no bytes or successful affected entry. Earlier successful
units are returned as a truthful partial result together with the error.

### CK-V1-AUD-005 — publication truth lifecycle

Phase 0 remains the immutable v1.13.13 reconciliation. Phase 18 owns v1.13.14
candidate/current truth, and Phase 26 owns published/final truth. Historical
authored-state evidence is not rewritten.

### CK-V1-AUD-006 and CK-V1-AUD-009 — snapshot restore inputs

Phase 8 copies `SnapshotRestoreRequest.Overwrite` directly to the existing
lower restore option. The lower atomic replacement and collision contract is
not redesigned.

One private Engine selector normalizer serves SnapshotShow, SnapshotDiff, and
SnapshotRestore. Exact paths are lexically normalized and reject blank,
absolute, or traversal input. Internal exact matching is deduplicated while
public restore slices and requested-path counts remain intact. Prefixes must
normalize with trailing `/`; `docs/` means descendants and `docs` is invalid.
Glob and regex syntax, non-negative size ranges, and typed time ordering are
validated once. Malformed CLI timestamp text remains a parser usage error.

### CK-V1-AUD-007 — single-file Store finalization

`FinalizeContainer` retains ownership of physical finalization and its existing
quarantine-on-finalization-failure contract. The Store wrapper always invokes
required finalization, captures its error, composes it with an earlier Store
error using `errors.Join`, and never returns Engine Store success when
finalization fails. It does not add duplicate quarantine. `LocalWriter` owns
physical quarantine; `SimulatedWriter` owns no physical active container.

### CK-V1-AUD-008 — rollback close and quarantine

Rollback gains an internal poisoned state. Truncate and close are both
attempted and both errors are retained. Container identity remains available
until quarantine resolves the unsafe state. Successful rollback clears active
state. Any rollback failure prevents reuse. Successful quarantine marks the
container non-selectable and clears local state; failed quarantine retains the
poisoned identity and returns every cause.

### CK-V1-AUD-010 and CK-V1-AUD-012 — snapshot result truth

For SnapshotDiff, `TotalEntryCount` is the raw diff size before query/filter;
`MatchedEntryCount` and Summary describe all matches before Limit; Entries are
the deterministic first N matches ordered by normalized stored path. Limit is
applied after query and change filter; zero is unlimited and negative is
`invalid_argument`. Summary mode still summarizes the full pre-limit match set.

`SnapshotMeta.FileCount` is total persisted `snapshot_file` membership,
independent of filtering or Limit. Backend-neutral find/list/graph queries will
obtain it without N+1 work and list/show/graph/tree will project it.

### CK-V1-AUD-011, CK-V1-AUD-013, and CK-V1-AUD-014 — configuration truth

One Engine-private container-directory resolver uses a non-empty configured
value and otherwise `container.ContainersDir`. It does not change the global
default or introduce repository-local v2 directory semantics.

The Store codec wording becomes: explicit request, then `COLDKEEP_CODEC`, then
implementation default `aes-gcm`. No repository codec setting is invented.

The current Store-facing block-target resolution becomes the one shared
resolver used by Store and Stats. Existing environment precedence, integer
helper parsing (including accepted numeric prefixes), supported values,
fallback, and warning behavior are preserved. Stats reports that resolver's
effective value and does not reinterpret the environment. Stricter malformed
environment parsing is out of scope.

### CK-V1-AUD-015, CK-V1-AUD-016, and CK-V1-AUD-017 — CLI documentation parity

The invalid example becomes `coldkeep search --name report`; no positional
alias is added. Exit documentation freezes 0 success, 1 general/execution, 2
usage/pre-execution validation, 3 verification/invariant-integrity, and 4
recovery. Batch precedence is invariant, then execution, then validation.
Process `exit_code/error_class`, coarse `error.code`, stable `invariant_code`,
and `recommended_action` remain distinct.

Init documentation exposes `--compression none` and `--compression zstd
--compression-level 1`, with block-level, compression-before-encryption,
new-writes-only, and zstd-only-level semantics.

## 4. Frozen process-gate designs

### CK-V1-GATE-001 — isolated CLI storage identity

`DefaultCLIEnv(string)` remains source-compatible, rejects blank input, and
canonicalizes its root with `filepath.Clean` and `filepath.Abs`. Each schema
startup release-gate subtest owns a unique `t.TempDir()` container root. Tests
prove inherited environment and alternate cwd cannot redirect storage and no
repository-local `.coldkeep-control` artifact is created.

### CK-V1-GATE-002 — tracked-source evidence names

A dedicated validator uses `git grep` over tracked `*.go` files, with an
optional repository root for fixtures. Complete evidence passes, one missing
name fails with a diagnostic, and unreadable untracked/runtime directories do
not affect the result.

### CK-V1-GATE-003 — benchmark evidence lifecycle

The only in-worktree root is
`$REPO_ROOT/.release-evidence/v1.13.14/<candidate-SHA>/`; filesystem-root
`/.release-evidence` is forbidden. Transient work uses `mktemp -d` and cleanup
traps. Per-profile checksums and a top manifest are validated before atomic
same-filesystem promotion.

Phase 14 inventories current ignore policy and historical evidence before any
`.gitignore` decision. No ignore change is mandatory. Manifest/filesystem
inventory, `git status --ignored --short`, `git check-ignore -v`, and ordinary
untracked-inclusive status jointly prove that ignored evidence is expected and
that unrelated residue is neither leaked nor concealed.

### CK-V1-GATE-004 — release-local linearity

The validator requires `origin/main`, computes
`base=$(git merge-base HEAD origin/main)`, fails without a merge base, and
requires `git rev-list --merges "${base}..HEAD"` to be empty. Direct ancestry,
inherited main merges, and later main advancement pass; a release-local merge
and unrelated history fail. GitHub `non_fast_forward` remains enabled and
`required_linear_history` is not restored.

## 6. Phase 3 seam contract

Phase 3 may add only nil-by-default, per-instance deterministic seams:

- a verification-stage observer/ledger transport in verification ownership;
- private GC execution options carrying `fsx.FS` and dispatch observation;
- per-`StorageContext` restore hooks replacing unsafe global hooks;
- context-aware private Doctor callbacks;
- `faultfs.OpTruncate` in the existing filesystem fault facility.

Existing Store interleaving hooks and injected writers cover Store,
finalization, and quarantine. Remove cancellation tests use a test-only SQL
driver. No global mutable hook, duplicate quarantine layer, sleep-based
synchronization, broad mocking framework, or behavior correction is permitted.

## 7. Regression and baseline strategy

Behavioral regressions must fail against the unmodified pre-fix state or a
Phase 3 seam-only defect-preserving state, then pass in their owner phase.
Expectations are independently derived and exercise public Engine boundaries
where practical. They assert result, repository/filesystem side effects, typed
error behavior, cleanup, relevant backend/layout/codec/compression/platform
coverage, and race requirements without arbitrary sleeps.

Documentation and live-process rows may use source plus validator evidence when
runtime replay is not meaningful. A row is never called baseline-failing merely
because its finding text says so.
