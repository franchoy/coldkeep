## Purpose

Activate snapshot delete as a real engine mutation boundary while preserving
the frozen Phase 3 delete contract and leaving the production CLI on its
existing direct snapshot-domain route.

Phase 8 activates `Engine.SnapshotDelete`. It does not:

- route `snapshot delete` CLI through the engine;
- remove `snapshotDeleteLineagePreviewPhase`;
- remove `deleteSnapshotPhase`;
- change delete human output, JSON output, or exit behavior;
- run GC or estimate reclaimable bytes;
- activate snapshot restore; or
- begin Phase 9.

## Executive result

Phase 8 makes snapshot delete active in the engine and keeps production CLI
delete behavior unchanged.

The implemented outcome is:

- `SnapshotDelete` is now part of the active `Engine` interface;
- `DefaultEngine.SnapshotDelete` implements the frozen Phase 3 request/result
  contract;
- preview mode is read-only and DB-only through
  `snapshot.LoadDeleteLineagePreview`;
- execute mode is metadata-only and returns `Deleted=true` only after a
  committed one-row snapshot deletion;
- execute does not load preview data and does not fabricate preview metrics;
- normal parent deletion still leaves children alive and nulls `parent_id`
  through existing foreign-key behavior; and
- production CLI `snapshot delete` still uses
  `snapshotDeleteLineagePreviewPhase` and `deleteSnapshotPhase` directly.

## Interface activation

`Engine` now exposes:

```go
SnapshotDelete(ctx context.Context, req SnapshotDeleteRequest) (SnapshotDeleteResult, error)
```

The active-interface update preserves these boundaries:

- snapshot create is active;
- snapshot delete is now active;
- snapshot restore remains inactive; and
- the production CLI delete route remains direct.

## Engine delete behavior

`DefaultEngine.SnapshotDelete` now:

1. normalizes a nil context to `context.Background()`;
2. trims and validates `SnapshotID`;
3. rejects missing or unknown delete modes at the engine boundary;
4. maps preview mode to `snapshot.LoadDeleteLineagePreview`;
5. translates domain preview lineage facts into the frozen renderer-neutral
   parent/children/count result shape;
6. maps execute mode to a result-returning snapshot-domain delete core;
7. returns `Deleted=true` only after the delete core commits an actual
   one-row snapshot deletion; and
8. returns no preview payload for execute mode.

Frozen compatibility points preserved in Phase 8:

- preview/live CLI flag precedence remains CLI-owned;
- preview warning rendering remains CLI-owned from raw child facts;
- missing-parent preview remains compatibility handling only;
- no payload bytes are deleted; and
- no GC or reclaim estimate is introduced.

## Snapshot-domain result core

Phase 8 keeps the existing metadata-only delete transaction but introduces a
result-returning core:

```go
type DeleteSnapshotResult struct {
	SnapshotID string
	Deleted    bool
}
```

The new `DeleteSnapshotWithResult` path:

- preserves the existing delete transaction structure;
- deletes `snapshot_file` rows first and the target snapshot row second;
- checks `RowsAffected()` on the snapshot-row delete and requires exactly one
  deleted row;
- returns `Deleted=true` only after commit succeeds; and
- returns a zero result on failure so rollback cases do not report deletion.

The compatibility wrapper remains in place:

- `DeleteSnapshot(...) error` still exists for existing direct callers;
- the production CLI still routes through that wrapper and the existing direct
  preview helper.
