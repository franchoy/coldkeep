## 2. Frozen contract and baseline defect

`CK-V1-AUD-007` requires every single-file Store boundary that owns a writer to
attempt required end-of-operation finalization exactly once. Finalization
failure must be returned, or joined with a preceding Store error. Engine must
return `StoreResult{}` for every non-nil final outcome. `LocalWriter` retains
physical quarantine ownership, and Phase 7 retains rollback close handling.

| Call site | Layer/category | Purpose and current error handling | Quarantine owner | AUD-007 relevant |
| --- | --- | --- | --- | --- |
| `finalizeSingleFileStore` in `internal/storage/store.go` | storage wrapper / C | exactly-once end-of-single-file-operation finalization; returns finalization error or joins it with Store error | writer; `LocalWriter.FinalizeContainer` for physical state | YES — final owner |

| `StorageContext.Close` | outer resource boundary | defensive lifecycle finalization before DB/temp cleanup; error aggregated | writer | NO |

| direct test finalizers and injected implementations | tests / F | fixture setup, preservation checks, and fault observation | fixture-specific | NO production defect |

Engine no longer owns a second finalization call. Default and explicit codec
requests both delegate through `StoreFileWithStorageContextAndCodecResultContext`,
which reaches the single storage finalization owner. StoreFolder continues to
call the internal per-file implementation and retains worker ownership.

## 4. Implementation and error matrix

`StoreFileWithStorageContextAndCodecResultWithPolicyContext` is the lowest
common public single-file wrapper and owns one deferred call to
`finalizeSingleFileStore`. Compatibility result/non-result, contextless/context-
aware, default-codec/explicit-codec, and policy wrappers all delegate through
it. The lower StoreFolder per-file implementation deliberately does not.

The helper implements the frozen matrix without mutating result metadata:

| Store work | Finalize | Storage result/error | Engine projection |
| --- | --- | --- | --- |
| success | success | existing result, nil | existing success |
| failure | success | existing lower result semantics, original error | zero result, translated error |
| success | failure | existing lower result plus finalization error | zero result, `operation_failed` |
| failure | failure | existing lower result plus `errors.Join(storeErr, finalizeErr)` | zero result, translated joined error |

Tests use `errors.Is`, not message ordering, to prove both dual-error causes.
Cancellation and deadline causes remain `cancelled` at Engine while the
finalization cause remains discoverable.

## 5. Writer safety and repository state

`LocalWriter.FinalizeContainer` remains unchanged. Its physical sync/close
failure path quarantines the active container and returns the physical cause,
joined with quarantine failure when necessary. The caller performs no second
quarantine. A deterministic close fault proves the catalog row is quarantined,
the local active handle is cleared, and a later append selects a different
container. No post-commit metadata rollback, logical-file deletion, reference
rewrite, or new transaction model was added.

`SimulatedWriter` remains a logical reset with no physical quarantine. Empty
file and AlreadyStored paths preserve their existing catalog behavior and pass
through the same exactly-once wrapper boundary without opening synthetic
physical state.
