## Development environment

The new development container uses the pinned Go builder separately from the
minimal product image. It supplies the native compiler, Python, jq,
ShellCheck, and PostgreSQL client. Its Compose environment:

- has no privileged mode or Docker socket mount;
- forwards no host credentials or production secrets by default;
- uses development-only PostgreSQL credentials;
- does not inject encryption key material; and
- runs a fail-closed, idempotent bootstrap that verifies Go 1.26.7,
  `GOTOOLCHAIN=local`, PostgreSQL readiness, safe-directory configuration, and
  module availability.

## Product and source-install proof

The product Dockerfile executes the builder on BuildKit's native
`BUILDPLATFORM` and produces a static CLI for the requested `TARGETARCH`.
Required CI builds and runs `version` for Linux amd64 and arm64. The product
image no longer doubles as a contributor toolbox.

The clean-checkout source-install matrix runs natively on Linux, macOS, and
Windows with exact Go 1.26.7, `GOTOOLCHAIN=local`, `CGO_ENABLED=1`, and the
runner's native C compiler. Each row builds, runs `go install ./cmd/coldkeep`,
and requires `coldkeep version 1.13.15`. The public exact-revision proof remains
owned by Phase 6, and the final `@v1.13.15` proof remains owned by Phase 9.

## Documentation and secret handling

The Quickstart now builds before invoking the CLI and states that normal v1.x
CLI runtime remains PostgreSQL-backed. Contributor guidance names real Go test
packages. `.env.example` defaults to plain development mode and intentionally
contains no key assignment; AES-GCM developers generate private key material
with `coldkeep init`.
