## Blocker remediation attempt

### Blocker

The first Phase 10 gate attempt blocked on:

```text
COLDKEEP_CODEC=aes-gcm go test -race -count=1 -short ./tests/integration/...
```

### Root cause

The failing test path was deterministic and codec-specific after restoring the
recorded PostgreSQL gate prerequisites locally.

`TestPhase2PostMigrationStoreRestoreSnapshotRegressionIntegration` failed
because the integration test harness did not seed a deterministic
`COLDKEEP_KEY` in the parent `go test` process when `COLDKEEP_CODEC=aes-gcm`.
CLI child processes already received a fallback AES-GCM key through
`tests/utils.DefaultCLIEnv`, but direct in-process store/restore paths still
read `COLDKEEP_KEY` from the parent environment and failed with
`aes-gcm requires COLDKEEP_KEY: COLDKEEP_KEY must not be empty`.

This was a repository-owned test-harness bug, not a production storage or
restore correctness bug.

### Fix

Applied the smallest test-only remediation:

- seeded the deterministic AES-GCM test key from the shared DB gate helpers in
  `tests/utils/common.go` and `tests/utils/testgate/testgate.go` whenever
  `COLDKEEP_CODEC=aes-gcm` and the parent process has no key set
- updated `TestPhase2PostMigrationStoreRestoreSnapshotRegressionIntegration`
  to use the CLI `store` response `file_id` directly instead of re-querying the
  stored row by hash

No production code changed.
No runtime behavior changed.
No CLI or JSON contract changed.
