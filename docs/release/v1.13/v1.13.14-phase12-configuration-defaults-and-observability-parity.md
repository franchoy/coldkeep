## 3. One effective Engine ContainerDir

`DefaultEngine.effectiveContainerDir` is the sole affected-operation resolver.
It uses `strings.TrimSpace` only to decide whether configuration is absent. An
absent or whitespace-only value resolves to `container.ContainersDir`; a
non-empty value is returned byte-for-byte as supplied. The helper does not
clean, absolutize, evaluate symlinks, mutate `Config`, or change the global.

Verify, GarbageCollect, Recover, ordinary live Restore, and RestoreStoredPath
now consume that helper. RestoreStoredPath still requires the Engine DB but no
longer requires an explicit directory. Its derived StorageContext copies any
injected context first, then restores Engine DB and effective ContainerDir
ownership without erasing Writer, Chunker, hooks, or other injected fields.

The primary regression exercises all five operations against equivalent
default and explicit roots. PostgreSQL separately proves RestoreStoredPath with
an empty Engine ContainerDir and valid default root. Existing destination,
overwrite, metadata, normalization, context, error, and cleanup behavior is
unchanged.

## 4. Store codec contract parity

Only the `StoreRequest.Codec` comment changed. It now states:

```text
non-empty request -> explicit request value
empty request     -> COLDKEEP_CODEC
environment unset -> implementation default aes-gcm
```

No repository codec setting was added. `blocks.LoadDefaultCodec`, Engine Store
routing, codec validation, invalid-environment behavior, compression
independence, and the `aes-gcm` default are unchanged. The primary regression
stores data for explicit plain/AES-GCM, environment plain/AES-GCM, unset
environment, invalid environment, and explicit-over-invalid-environment cases,
then independently checks the stored codec metadata and the public comment.

## 5. Shared packed-block target resolution

`internal/blocks.ResolvePackedBlockTarget` is the one semantic environment
resolver. It is pure with respect to logging and preserves the Phase 11 Store
behavior exactly:

```text
presence precedence:
  COLDKEEP_BLOCK_TARGET_SIZE_MB when present
  otherwise COLDKEEP_PACKED_BLOCK_SIZE_MIB

integer behavior:
  existing utils_env.GetenvOrDefaultInt64 helper

supported values:
  1, 2, 3 MiB

default/fallback:
  1 MiB
```

The Phase 11 helper rejects suffix text such as `2MiB` and overflow-like text
to its numeric fallback; extraction preserves that observed helper behavior
and introduces no new parser or strictness change. A present empty, malformed,
or unsupported new variable never falls through to the legacy variable.

The resolution carries effective bytes, parsed/fallback MiB, selected
environment, and warning classification. Store's existing wrapper emits the
same non-positive, unsupported, or overflow-category message exactly once and
returns the shared bytes. Stats calls the same pure resolver, ignores warning
metadata, emits nothing, and uses the effective bytes for its unchanged
`AvgPlaintextSize / target` FillRatio definition.

Representative 1, 2, 3 MiB, and unsupported-to-1 MiB cases prove that the
target consumed by Store's `BlockBuilder` flushes only when the next addition
would exceed the effective target. Existing packed Store, codec, compression,
and layout suites preserve physical construction behavior.
