## Route change

Old production route:

```text
runSnapshotCreateCommand
  -> CLI flag validation
  -> CLI type derivation
  -> CLI ID generation when --id omitted
  -> createSnapshotPhase / snapshot.CreateSnapshotWithOptions
  -> CLI SELECT COUNT(*) FROM snapshot_file WHERE snapshot_id = $1
  -> human or JSON rendering
```

New production route:

```text
runSnapshotCreateCommand
  -> CLI flag validation
  -> explicit blank --id / --label / --from rejection
  -> existing repository initialization
  -> existing command-engine construction path
  -> Engine.SnapshotCreate(ctx, SnapshotCreateRequest)
  -> human or JSON rendering from engine result
```

## Request construction

CLI now forwards:

```go
engine.SnapshotCreateRequest{
    ID:       suppliedIDOrEmpty,
    Label:    trimmedLabelOrEmpty,
    ParentID: trimmedParentOrEmpty,
    Paths:    rawPositionalPaths,
}
```

The CLI preserves raw positional path order and duplicates.

## Ownership changes

ID ownership transfer:

- explicit blank `--id` is still rejected before repository initialization;
- omitted `--id` now forwards `ID: ""`;
- the engine now generates the committed snapshot ID;
- CLI output now uses `result.SnapshotID`.

Type derivation ownership transfer:

- CLI no longer derives a production create type;
- the engine derives `full` vs `partial`;
- CLI output now uses `result.Type`.

Files-inserted ownership transfer:

- production CLI no longer runs post-create `COUNT(*)` SQL;
- CLI output now uses `result.FilesInserted`;
- successful JSON output now always includes `files_inserted`.

## Preserved behavior

Pre-initialization validation preserved:

- explicit blank `--id` still fails before repository initialization;
- explicit blank `--label` still fails before repository initialization;
- explicit blank `--from` still fails before repository initialization.

Human output parity preserved:

- full create text still renders the same shape;
- parented create text still renders the same shape;
- duration and hint lines remain CLI-owned.

JSON output parity preserved:

- `status`, `command`, `data.snapshot_id`, `data.type`,
  `data.paths_count`, `data.files_inserted`, `data.duration_ms`, and
  `data.perf_spans` remain in the same CLI envelope;
- optional `label` and `parent_id` remain conditional;
- committed values now come from the engine result.

Error compatibility preserved:

- engine errors flow through the existing CLI error path;
- stable error substrings remain visible to existing tests.

## Non-routing proof
