## Release-branch governance discovery and correction

The first publication attempt was rejected by GitHub with `GH013` because
release ruleset `21155858` applied `required_linear_history` to inherited
authoritative-main history and found merge commit
`f3b75dc0fbee44e4fe91eb2df1df724f9426640e`. Rebase, baseline replacement,
force-push, bypass, and temporary rule suspension were rejected as invalid
solutions.

Phase 0 permanently corrected the incompatible live rule from:

```text
RULESET_ID: 21155858
TARGET: refs/heads/release/**/*
ENFORCEMENT: active
BYPASS_ACTORS: 0
RULES: non_fast_forward, required_linear_history
```

to:

```text
RULESET_ID: 21155858
TARGET: refs/heads/release/**/*
ENFORCEMENT: active
BYPASS_ACTORS: 0
RULES: non_fast_forward
```

The normalized semantic delta is only removal of
`required_linear_history`; `non_fast_forward` continues to prevent history
replacement. Main, release-tag, and hotfix governance are unchanged. New gate
`CK-V1-GATE-004` records the remaining Phase 14 requirement for a
branch-relative merge-history validator that permits inherited main merges but
rejects release-branch-local merge commits.

Created documents: Phase 0 evidence, scope, phase list, validation checklist,
remediation tracker, release state, release-train reconciliation, and
release-state validator contract; plus the missing v1.13.13 Phase 16 record.
