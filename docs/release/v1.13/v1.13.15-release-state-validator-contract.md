# Coldkeep v1.13.15 Release-State Validator Contract

**Status:** Active development contract

## Aggregate Phase 0

The validator recognizes `^## Phase (\d+)` and intentionally ignores the
`### Phase 0A` and `### Phase 0B` evidence headings.

- Before and after Phase 0A, aggregate Phase 0 is `Next`.
- Phase 0A/0B detail is maintained in bounded evidence and release-state text.
- After successful Phase 0B, aggregate Phase 0 is `Complete`, Phase 1 is
  `Next`, and Phases 2–10 are `Not started`.

Phase 0A deliberately deferred validation while source identity remained
1.13.14. Phase 0B must pass:

```text
python3 scripts/validate_release_state.py --state development --json
```

with status `ok` and active version `1.13.15` before the first push.

## Lifecycle

Development, merged/pre-tag, released, and post-release-closed states must
continue to fail closed. The final released state requires the annotated
v1.13.15 tag to peel exactly to the certified commit. Post-release closure
requires that tag target to remain an ancestor of final main and that current
documentation/evidence is reconciled through the protected closure PR.

Do not modify the validator merely to expose 0A/0B as numeric phases. If the
aggregate representation is technically impossible, return to Plan mode.
