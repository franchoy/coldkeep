# Coldkeep v1.10.8 Release Notes

## Release: v1.10.8 — Filesystem Abstraction Groundwork

**Date**: 2026-05-25

**Branch**: `feature/v1.10.8-filesystem-abstraction-groundwork`

---

## Overview

v1.10.8 introduces a minimal filesystem abstraction layer to prepare all storage-related subsystems for deterministic filesystem fault injection in a future release. This release is a groundwork-only change: all production behavior is preserved exactly. No fault injection is activated, and no user-visible behavior is altered.

---

## What Changed

### New Package: `internal/fsx`

- `FS` interface: 8 filesystem-level methods (`OpenFile`, `Stat`, `MkdirAll`, `Remove`, `Rename`, `ReadDir`, `WalkDir`).
- `File` interface: extends `io.Reader`, `io.Writer`, `io.Closer`, `io.ReaderAt`, `io.Seeker` with `Sync` and `Truncate`.
- `OSFS`: concrete OS adapter delegating directly to `os.*` and `filepath.WalkDir`.
- `Default()`: returns the OS-backed filesystem adapter.
- `NoopFS`: transparent pass-through wrapper around any `FS`.
- `NewNoop(base FS)`: constructor for `NoopFS`.

### Filesystem Seams Introduced

- **Restore** (`internal/storage`): 8 filesystem call sites now route through `fsx.FS`. Default behavior: `fsx.Default()`.
- **Container** (`internal/container`): 10 filesystem call sites now route through `fsx.FS`. Default behavior: `fsx.Default()`.
- **Recovery / Quarantine** (`internal/recovery`): 4 helper functions extracted with `fsys fsx.FS` parameter. Existing public 3-param signatures preserved as thin wrappers calling `fsx.Default()`.
- **GC** (`internal/maintenance`): 2 `os.Remove` call sites routed through `removeContainerFileWithFS` helper. Default behavior: `fsx.Default()`.

### Tests Added

- Seam unit tests for all four subsystems confirming default OS-backed behavior.
- Head-to-head equivalence tests for all four subsystems confirming `fsx.Default()` and `fsx.NewNoop(fsx.Default())` produce identical results.

---

## What Did Not Change

- does **not** introduce filesystem fault injection
- does **not** introduce engine extraction
- does **not** introduce catalog abstraction
- does **not** change the default database backend
- does **not** introduce product features
- does **not** change public CLI, JSON, or exit-code behavior
- does **not** change existing test behavior or test signatures
- does **not** modify `go.mod`, `go.sum`, CI configuration, or scripts

---

## Migration

No migration is required. v1.10.8 is a groundwork-only internal change. All filesystem operations continue to use OS-backed behavior by default. Existing deployments, data formats, and database schemas are unaffected.

---

## Compatibility

- Backward compatible with v1.10.7.
- SQLite and PostgreSQL behavior unchanged.
- No API surface changes visible to callers of `internal/storage`, `internal/container`, `internal/recovery`, or `internal/maintenance`.
