# v1.10.10 Script Portability Audit

Status: Complete

## Purpose

This document records the v1.10.10 script portability audit.

The goal is to document which project scripts are Linux/POSIX-oriented, which are expected to work under Git Bash/WSL, and which are not claimed to be Windows-native.

## Core Invariant

v1.10.10 must document script portability boundaries honestly, without claiming Windows-native script support or weakening existing Linux release workflows.

## Audit Method

The audit reviewed:

- script file list;
- shebangs;
- shell assumptions;
- filesystem commands;
- Linux/POSIX command usage;
- GitHub Actions usage;
- Windows portability risks.

## Common Portability Risks

The following portability risks were observed in the script inventory:

- All Bash scripts use `#!/usr/bin/env bash` — not available in native Windows `cmd.exe` or PowerShell without Git Bash or WSL.
- POSIX utilities (`grep`, `sed`, `awk`, `find`, `xargs`) are used across multiple scripts — these require GNU or BSD variants; the exact invocation flags may differ between Linux and macOS.
- `rm -rf` filesystem cleanup is used; Windows does not support this natively.
- `/tmp` or relative path assumptions may be present in orchestration scripts.
- Path separator assumptions: Bash scripts use `/` throughout; Windows paths use `\` natively.
- Executable-bit assumptions: shell scripts require the executable bit, which is not a Windows concept.
- Python scripts invoking `go run` or shell subprocesses depend on POSIX subprocess behavior.
- Benchmark and GC sequence scripts invoke `python3` from within Bash — these expect a POSIX environment.
- No scripts were observed to use PowerShell, `pwsh`, or Windows-native shell syntax.

## Windows Policy

v1.10.10 does not claim scripts are Windows-native.

Scripts may be usable on Windows through:

- Git Bash;
- WSL;
- CI-specific shell environments.

Native PowerShell compatibility is not claimed unless explicitly validated.

## macOS Policy

Scripts using Bash/POSIX tools may work on macOS, but GNU/BSD tool differences must be treated carefully.

macOS ships BSD versions of `sed`, `grep`, `awk`, and `find`. Some GNU-specific flags may not be available.

v1.10.10 does not claim full macOS script parity unless validated.

## Linux Policy

Existing Linux release workflows remain the primary script baseline.

v1.10.10 must not weaken Linux script behavior to satisfy unvalidated portability assumptions.

## Release Claim Boundary

v1.10.10 may claim:

- cross-platform Go tests were introduced for selected path/restore/metadata surfaces;
- script portability risks were audited and documented.

v1.10.10 must not claim:

- all scripts are Windows-native;
- all scripts are macOS-equivalent;
- benchmark scripts are cross-platform;
- release scripts are PowerShell-compatible;
- shell portability is complete.
