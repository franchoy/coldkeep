# v1.10.7 Phase 7 — Regression Prevention Gate Design

Status: Complete

## Purpose

Phase 7 designs future critical-path coverage regression prevention behavior.

This phase is design-only. It does not implement regression comparison or coverage enforcement.

## Core Invariant

Regression prevention must protect correctness-critical coverage evidence without turning baseline variation or known low coverage into automatic release failure.

## Artifact

```text
docs/release/v1.10/v1.10.7-regression-prevention-design.md
```

## Design Summary

Phase 7 defines:

* baseline and current report terminology;
* regression classes;
* material decrease threshold direction;
* future `--soft-gate` behavior;
* future `--hard-gate` behavior;
* regression severity model;
* explanation requirement;
* invariant linkage requirement;
* future comparison artifact shape.

## Important Decision

Known low-visibility packages remain non-blocking in v1.10.7:

```text
internal/maintenance: 47.6%
internal/recovery: 44.9%
```

The future gate design may warn on regressions from those baselines, but it must not fail solely because those baselines are below target.

## Non-Goals

Phase 7 does not:

* change `scripts/critical_coverage.sh`;
* add `--soft-gate`;
* add `--hard-gate`;
* compare coverage against baseline;
* enforce thresholds;
* change CI workflows;
* add tests;
* change Go code;
* change dependencies.

## Validation

Phase 7 validation confirms:

* regression prevention design exists;
* future soft/hard gate behavior is documented but not implemented;
* known low-visibility baselines remain non-blocking;
* explanation and invariant linkage requirements are documented;
* no script, CI, Go, test, or dependency changes were made.
