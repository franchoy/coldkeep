# v1.10.9 Phase 3 — Container Write/Seal Fault Injection Scenarios

Status: Complete

## Purpose

Phase 3 adds deterministic container write/seal fault-injection scenarios using the v1.10.9 scripted fault filesystem helper.

## Core Invariant

Container filesystem failures must fail closed, must not falsely commit incomplete payload/header data, and must leave incomplete or failed containers detectable by verification or recovery.

## Implementation

Phase 3 adds container-focused tests for deterministic filesystem failures.

## Scenarios Covered

| Scenario | Fault | Test |
|---|---|---|
| open/create failure | `open_file` | `TestContainerFaultFSOpenFileFailureFailsClosed` |
| header write failure | `fail-write` | `TestContainerFaultFSHeaderWriteFailureFailsClosed` |
| payload write failure | `fail-write` | `TestContainerFaultFSPayloadWriteFailureFailsClosed` |
| partial payload write | `partial-write` | `TestContainerFaultFSPartialPayloadWriteFailsClosed` |
| sync failure | `fail-fsync` | `TestContainerFaultFSSyncFailureFailsClosed` |
| remove/retire failure | `fail-remove` | `TestContainerFaultFSRemoveFailurePreservesRetireFailure` |

## Seam Gaps

RollbackLastAppend still uses direct `os.Truncate` after the active handle has been closed.
That gap existed before Phase 3 and is not changed here.

## Behavior Preservation

Phase 3 does not change default container behavior.

Faults are injected only through test-specific `faultfs` scripts.

## Validation

Validated with:

```text
go test ./internal/container -run 'ContainerFaultFS|ContainerSeam' -count=1 -v
go test ./internal/container -count=1
go test ./...
go vet ./...
```
