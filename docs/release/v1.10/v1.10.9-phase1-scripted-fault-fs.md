# v1.10.9 Phase 1 — Scripted Fault FS Design & Test Helper

Status: Complete

## Purpose

Phase 1 introduces the deterministic, test-only scripted fault filesystem helper for v1.10.9.

The helper will be used by later phases to validate restore, container, recovery/quarantine, and GC behavior under deterministic filesystem failures.

## Core Invariant

The scripted fault filesystem must be deterministic, test-only, opt-in, and behavior-preserving when no fault script is configured.

## Implementation

Phase 1 adds:

```text
internal/fsx/faultfs
```

The package provides:

* `FS`
* `File`
* `Script`
* `Fault`
* operation names
* deterministic call counters
* write byte accounting
* path-operation failures
* write failures
* partial write failures
* ENOSPC-after-N-bytes failures
* sync failures
* close failures

## Fault Classes Supported

* fail-write
* partial-write
* fail-fsync
* fail-close
* fail-rename
* fail-mkdir
* fail-stat
* fail-remove
* enospc-after-bytes

## Behavior Preservation

When no script is configured, the helper delegates to the base filesystem.

When no base filesystem is configured, the helper falls back to `fsx.Default()`.

No production runtime path uses this package.

## Tests

Validated with:

```text
go test ./internal/fsx/faultfs -count=1 -v
go test ./internal/fsx/... -count=1
go test ./...
go vet ./...
```

Specific tests:

```text

```
