# v1.10.7 PR Summary — Critical-Path Coverage Gates

## Summary

v1.10.7 adds critical-path coverage visibility and release-control evidence for Coldkeep correctness-critical packages.

This release does not introduce product behavior changes. It establishes the coverage baseline, invariant mapping, soft threshold policy, report-only CI visibility, and regression-prevention design needed before any future coverage enforcement.

## What Changed

### Critical package inventory

Added an explicit inventory of critical packages across three tiers:

- Tier 1 — release-critical data safety, restore, verify, GC, snapshot, and recovery packages.
- Tier 2 — catalog, graph, block, container, and retention infrastructure packages.
- Tier 3 — observe-only CLI, observability, benchmark, scripts, and test-suite areas.

### Report-only coverage script

Added:

```text
scripts/critical_coverage.sh
```

The script supports:

```bash
scripts/critical_coverage.sh --report
scripts/critical_coverage.sh --report --csv-output <path>
```

It generates coverage visibility for tracked packages.

It does not enforce thresholds.

### Formal coverage baseline

Added formal baseline artifacts:

```text

docs/release/v1.10/v1.10.7-coverage-baseline.md
```

### Invariant coverage map

Added:

```text

docs/release/v1.10/v1.10.7-invariant-coverage-map.md
```

The map connects coverage evidence to named correctness invariants, including:

* GC reachability;
* deterministic restore;

* recovery fail-closed behavior;
* snapshot roots;
* packed/legacy parity;

* catalog compatibility;
* container placement;

### Report-only CI integration

Added a report-only CI job:

```text

```

The job runs:

```bash
scripts/critical_coverage.sh --report --csv-output docs/release/v1.10/v1.10.7-ci-coverage-report.csv
```

It uploads the CSV artifact.

It does not enforce thresholds or compare against baseline.

## What This PR Does Not Do

This PR does not:

* change Coldkeep product behavior;
* change storage, restore, verify, GC, snapshot, recovery, catalog, or retention logic;
* add tests;
* modify Go source files;
* modify Go test files;
* change dependencies;
* enforce coverage thresholds;
* compare coverage against baseline;
* add `--soft-gate`;
* add `--hard-gate`;
* introduce global coverage gates;
* claim improved runtime correctness from coverage numbers alone.

## Correctness Interpretation

v1.10.7 improves release visibility and coverage governance.

It does not prove correctness by coverage percentage.

Coverage is treated as evidence only when linked to named correctness invariants.
