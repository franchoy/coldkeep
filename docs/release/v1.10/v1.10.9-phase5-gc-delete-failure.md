# v1.10.9 Phase 5 — GC Delete Failure Scenarios

Status: Complete

## Purpose

Phase 5 adds deterministic GC delete-failure coverage using the v1.10.9 scripted fault filesystem helper.

## Core Invariant

GC delete failures must not corrupt reachability state, must remain retry-safe, and must not turn a committed metadata delete into a silent unsafe outcome.

## Implementation

Phase 5 exercises the GC physical-delete seam with a scripted remove fault on a fully dead active container cleanup path.

## Scenarios Covered

| Scenario | Fault | Test |
|---|---|---|
| GC physical delete failure | `fail-remove` | `TestGCDeleteFaultFSRemoveFailureIsLoggedAndRecovered` |

## Behavior

The GC delete helper logs remove failures after the metadata transaction commits.
Phase 5 confirms that a remove fault does not surface as a fatal GC error and leaves the file available for later cleanup.

## Behavior Preservation

Phase 5 does not change default GC behavior.

Faults are injected only through test-specific `faultfs` scripts.
