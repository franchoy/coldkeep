# v1.10.9 Phase 2 — Restore Fault Injection Scenarios

Status: Complete

## Purpose

Phase 2 adds deterministic restore fault-injection scenarios using the v1.10.9 scripted fault filesystem helper.

## Core Invariant

Restore filesystem failures must fail closed, must not produce a corrupted final destination file, and must not report successful restore unless the restored bytes are complete and correct.

## Implementation

Phase 2 adds restore-focused tests for deterministic filesystem failures.

## Scenarios Covered

| Scenario | Fault | Test |
|---|---|---|
| destination parent mkdir failure | `fail-mkdir` | `TestRestoreFaultFSMkdirFailureFailsClosed` |
| destination stat failure | `fail-stat` | `TestRestoreFaultFSStatFailureFailsClosed` |
| final rename failure | `fail-rename` | `TestRestoreFaultFSRenameFailureDoesNotReportSuccess` |
| cleanup remove failure | `fail-remove` | `TestRestoreFaultFSRemoveFailureDuringCleanupIsReportedOrPreserved` |
| output directory fsync failure | `fail-fsync` | `TestRestoreFaultFSSyncFailureDoesNotReportSuccess` |

## Seam Gaps

Restore still uses direct `os.CreateTemp` for temp-file creation.
Restore write/sync fault injection for the temporary output file is therefore deferred until the restore temp-file creation/write path is fully seam-routed.

## Behavior Preservation

Phase 2 does not change default restore behavior.

Faults are injected only through test-specific `faultfs` scripts.
