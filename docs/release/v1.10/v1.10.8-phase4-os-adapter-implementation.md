# v1.10.8 Phase 4 — OS Adapter Implementation

Status: Complete

## Purpose

Phase 4 implements the minimal OS-backed filesystem adapter designed in Phase 3.

## Core Invariant

The OS-backed filesystem adapter must preserve standard library filesystem behavior exactly and must not change any existing Coldkeep call site behavior yet.

internal/fsx

## Interface

The package defines:

* `FS`
* `File`

## OS Adapter

The package implements:

* `OSFS`
* `Default`

`OSFS` delegates directly to:

* `os.Open`
* `os.OpenFile`
* `os.Stat`
* `os.MkdirAll`
* `os.Rename`
* `os.Remove`
* `os.ReadDir`
* `filepath.WalkDir`

## Behavior Preservation

The adapter must not:

* rewrite paths;
* normalize errors;
* retry operations;
* swallow errors;
* add fault injection;
* change permissions;
* change sync behavior;
* change traversal behavior.

## Tests

Phase 4 adds tests covering:

* open/write/sync/close/read behavior;
* stat/mkdir/rename/remove behavior;
* read-dir and walk-dir behavior;
* missing-path error preservation.

Note: `TestOSFSPreservesMissingPathErrors` uses an error-propagating WalkDirFunc
to verify that missing-root errors are delivered to the walker, matching stdlib
behavior where WalkDir returns whatever the walker returns for the root error.
