# v1.10.7 Scope — Critical-Path Coverage Gates

Status: Active

## Release Goal

v1.10.7 establishes critical-path coverage visibility and regression protection for Coldkeep correctness-critical packages.

The goal is not to chase global coverage percentages. The goal is to ensure that the paths most responsible for data safety, deterministic restore, GC safety, integrity verification, recovery safety, packed/legacy parity, and catalog compatibility are measured, mapped to invariants, and protected from silent regression.

## Core Invariant

v1.10.7 must improve visibility and regression protection for correctness-critical coverage without introducing noisy global coverage gates, product behavior changes, engine extraction, catalog abstraction, or default database changes.

## Included Scope

v1.10.7 may include:

- critical package inventory;
- critical-path coverage script in report mode;
- local critical-path coverage baseline capture;
- invariant-to-coverage mapping;
- soft threshold policy;
- optional report-only CI integration;
- regression prevention gate design;
- release checklist and validation documentation;
- coverage evidence files;
- PR/release notes.

## Excluded Scope

v1.10.7 must not include:

- global coverage gates;
- style-only coverage cleanup;
- broad test refactors;
- mutation testing;
- filesystem abstraction implementation;
- fault injection implementation;
- engine extraction;
- catalog abstraction;
- default database backend changes;
- product features;
- CLI behavior changes unrelated to coverage reporting;
- storage format changes;
- restore/GC/verify behavior changes except if a real correctness blocker is discovered;
- Codacy zero-warning work;
- CodeRabbit adoption.

## Critical Coverage Philosophy

Coverage must be tied to correctness invariants, not vanity metrics.

Priority is given to:

1. GC safety.
2. Deterministic restore.
3. Integrity verification.
4. Recovery fail-closed behavior.
5. Packed/legacy storage parity.
6. Snapshot retention semantics.
7. Catalog/schema compatibility.
8. CLI/JSON release-contract stability where it protects automation correctness.

Global coverage percentage is advisory only.

- `cmd/coldkeep`

- `docs`

## Coverage Gate Direction

v1.10.7 starts with:

- baseline measurement;
- report mode;
- soft threshold policy;
- release-candidate regression prevention design.

v1.10.7 should not hard-fail PRs solely because a package is below an aspirational threshold.

Initial hard blocking should only be considered for:

- coverage tool failure;
- missing baseline evidence;
- regression from committed baseline without rationale;
- malformed coverage artifact;
- missing invariant mapping for a Tier 1 package.

## Expected Deliverable

A release where Coldkeep knows:

- which critical paths are covered;
- which critical paths are partially covered;
- which critical paths are missing;
- which package coverage levels are current baseline;
- which invariants are protected by tests;
- how future releases will prevent silent critical-path coverage regression.
