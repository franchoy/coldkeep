# v1.10.7 Phase 1 — Critical Package Inventory

Status: Complete

## Purpose

Phase 1 expands the v1.10.7 critical package inventory from a simple package list into a release-control artifact that explains why each package is tracked, which invariant it protects, and how it should be treated by v1.10.7 coverage reporting.

## Core Invariant

Every package included in v1.10.7 coverage tracking must have an explicit correctness reason, tier, coverage role, and gate mode before coverage scripts or thresholds are introduced.

## Package Tier Model

### Tier 1 — Release-critical

Tier 1 packages directly protect data safety, restore determinism, GC safety, verification correctness, snapshot roots, or recovery fail-closed behavior.

Tier 1 packages are:

- `internal/storage`
- `internal/verify`
- `internal/maintenance`
- `internal/gc`
- `internal/snapshot`
- `internal/recovery`

### Tier 2 — Catalog / graph / storage infrastructure critical

Tier 2 packages support Tier 1 invariants through catalog schema, graph reachability, block abstractions, container placement, or retention policy.

Tier 2 packages are:

- `internal/db`
- `internal/graph`
- `internal/blocks`
- `internal/container`
- `internal/retention`

### Tier 3 — Observe-only

Tier 3 packages are important but should not become v1.10.7 release blockers by raw package coverage percentage.

Tier 3 areas are:

- `cmd/coldkeep`
- `internal/observability`
- `internal/benchmark`
- `scripts`
- `tests/adversarial`
- `tests/integration`

## Gate Mode Decision

v1.10.7 uses the following initial gate modes:

| Mode | Meaning |
|---|---|
| `baseline-report-and-soft-gate` | Coverage must be measured and reported. Warnings are allowed. Hard blocking is limited to missing baseline evidence, malformed artifacts, or unexplained regression from committed baseline. |
| `report-only` | Coverage is visible but does not block v1.10.7. |

No package receives a hard absolute percentage gate in Phase 1.

## Release-Blocking Meaning in v1.10.7

A package marked `release_blocking_in_v1107=yes` does not mean it must satisfy a fixed absolute coverage percentage immediately.

It means the package must have:

- baseline coverage captured;
- invariant mapping recorded;
- no unexplained coverage regression from baseline;
- no malformed coverage artifact;
- no missing coverage evidence at release-candidate time.

## Non-Goals

Phase 1 does not:

- add a coverage script;
- run coverage;
- change CI workflows;
- change Go code;
- change tests;
- set hard absolute coverage thresholds;
- chase global coverage percentage;
- refactor tests;
- add mutation testing;
- add filesystem fault injection.
