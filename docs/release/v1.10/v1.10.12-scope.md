# v1.10.12 Scope — Engine Boundary Readiness

Status: Active

## Purpose

v1.10.12 prepares Coldkeep for v1.11 engine boundary work without starting engine extraction.

## Core Invariant

v1.10.12 must identify engine-boundary contracts and migration rules without changing runtime behavior, repository format, CLI behavior, JSON contracts, database defaults, or storage semantics.

## Scope

Included:

- close stale v1.10.11 release evidence;
- define v1.10.12 engine-boundary readiness scope;
- inventory CLI/business-logic coupling;
- inventory direct DB/filesystem/storage-context access;
- identify operation contract candidates;
- map invariant ownership;
- define no-behavior-change migration rules;
- inventory SQLite/PostgreSQL assumptions;
- prepare v1.11 transition checklist.

Excluded:

- No engine extraction;
- No catalog abstraction implementation;
- No package moves into `internal/engine`;
- No package moves into `internal/catalog`;
- catalog abstraction implementation;
- package moves into `internal/engine`;
- package moves into `internal/catalog`;
- default database backend changes;
- repository format changes;
- CLI behavior changes;
- JSON contract changes;
- new product features;
- broad refactors;
- style-only cleanup.

## Release Goal

v1.10.12 should leave the project ready to start v1.11 with a clear, evidence-backed engine-boundary plan.

It should not implement that boundary.
