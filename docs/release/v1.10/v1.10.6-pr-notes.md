# v1.10.6 PR Notes — CI / Codacy / Copilot Workflow Hardening

## Summary

v1.10.6 is a CI / Codacy / Copilot workflow hardening release in the v1.10 correctness train.

This release is focused on process, tooling guidance, release discipline, and validation policy.

During PR CI (Phase 11), the adversarial aes-gcm job exposed a storage correctness regression in the chunk reuse/reclaim physical metadata path. A narrow blocker fix was added to:

- require strict reusable metadata validation before reclaim reuse,
- clear stale packed/legacy physical rows when validation fails, and
- prevent stale rows from being treated as reusable completion evidence.

The release strengthens how Coldkeep uses:

- Copilot instructions and prompts,
- CI guidance,
- critical-path coverage planning,
- Codacy passive-mode policy,
- scanner suppression and acceptance rules,
- CI/Codacy release gate boundaries,
- CI workflow delta review,
- local validation and workflow consistency evidence.

## Pre-PR Requirement

Before opening the PR, run the Pre-PR Code Quality / Codacy-Risk Gate and record the result.

Required post-Phase-9 gate:

```bash
git status --short

go vet ./...
go test ./... -count=1
go test -race ./... -count=1

golangci-lint run ./...
staticcheck ./...
gosec ./...

git fetch origin
git diff --name-only origin/main...HEAD
git diff --stat origin/main...HEAD
git diff origin/main...HEAD -- '*.go'
```

Merge only after:

- PR CI is green,
- Codacy analysis is complete,
- no unclassified release-delta Codacy findings remain,
- any actionable release-delta findings are fixed or explicitly accepted with rationale.

## Phase 11 Codacy SQL Injection Classification (2026-05-22)

Codacy/OpenGrep reported SQL injection findings in production Go paths. Each finding was classified per:

- `docs/release/v1.10/v1.10.6-codacy-passive-policy.md`,
- `docs/release/v1.10/v1.10.6-ci-codacy-gate-boundary.md`.

Classification outcome: no release-delta actionable SQL injection defect identified in the reviewed paths; findings are either false-positive or parameterized-safe advisory patterns.

| File | Scanner signal | Classification | Rationale | Release impact |
| --- | --- | --- | --- | --- |
| `internal/storage/store.go` (1132, 1177, 1263, 1268) | Opengrep SQL injection (critical/potential) | false positive | Static SQL literals with positional placeholders and bound args (`QueryRowContext`/`ExecContext`); no user-controlled SQL construction. Existing inline `nosemgrep` rationale is present. | advisory, non-blocking |
| `internal/db/migrations.go` (84, 483) | Opengrep SQL injection potential | false positive | SQLite `PRAGMA table_info(...)` introspection with internal schema identifiers; not user-input driven SQL text. | advisory, non-blocking |
| `internal/repository/capabilities/derive.go` (340) | Opengrep SQL injection potential | false positive | Same SQLite schema introspection pattern as migrations; internal table-name scope only. | advisory, non-blocking |
| `internal/observability/stats.go` (353, 402) | Opengrep SQL injection potential | duplicate analyzer finding / parameterized-safe | Dynamic placeholder list only (`$1..$N`) with values supplied via args; query values are parameterized, not concatenated into SQL literals. | advisory, non-blocking |
