# v1.10.11 S0/S1 Inventory

Status: Complete
Owner phase: Phase 2 — Remaining S0/S1 Inventory Refresh

---

## Purpose

This document records the S0/S1 risk inventory for v1.10.11. It classifies every
S0/S1 candidate identified during the Phase 12 static analysis review and cross-references
current remediation-matrix.csv and issue-tracker.csv status to determine which items are:

- `needs_review` — not yet confirmed closed, accepted, or deferred; must be audited in Phase 3
- `closed_by_previous_release` — confirmed closed by a prior v1.10.x release with evidence

No S0/S1 candidates are modified in this document; source docs remain authoritative.

---

## Method

Cross-reference the following source documents:

1. `docs/release/v1.10/known-s0-s1.md` — Phase 12 review of 72 candidates; 28 confirmed S1; 0 confirmed S0
2. `docs/release/v1.10/issue-tracker.csv` — individual scanner findings with status (triaged/fixed/accepted/closed)
3. `docs/release/v1.10/remediation-matrix.csv` — grouped remediation items M001–M088 with status and release targets
4. `docs/release/v1.10/external-audit-inventory.md` — external audit supplemental findings

Classification rule:
- If remediation-matrix.csv shows `fixed`, `closed`, or `accepted` for the item → `closed_by_previous_release`
- If remediation-matrix.csv shows `triaged` (regardless of release target) → `needs_review`
- If the item is listed in known-s0-s1.md as backlog with no corresponding closure evidence → `needs_review`

## Severity Model

| Severity | Criteria |
|---|---|
| S0 | Catastrophic: data loss, data corruption, false-positive verify pass, GC deletes retained data |
| S1 | Critical: crash-consistency failure, refcount error, restore writes outside destination, recovery legitimizes corrupt mapping, JSON/CLI automation broken, known CVE in production toolchain |
| S2 | Major: significant correctness gap but does not trigger S0/S1 invariant directly |
| S3 | Minor: quality, test coverage, or non-critical correctness gap |
| S4 | Style or documentation only |
