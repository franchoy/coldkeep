# v1.10.2 Phase 5 — Symlink Policy & Regression Coverage

Status: Complete

## Purpose

Phase 5 defines and enforces symlink-sensitive path safety policy for scoped restore/write paths.

The expected invariant is:

> Coldkeep must not follow unsafe symlink paths in a way that writes outside the intended trusted root.

## Scope

Included:

- define symlink policy for restore destination writes
- detect symlinked parent-directory escape attempts where practical
- detect existing symlink target overwrite attempts where practical
- ensure restore writes do not follow symlinks outside the destination root
- platform-aware regression tests
- deterministic failure behavior for unsafe symlink cases

Excluded:

- container filename validation, already covered by Phase 2
- stored/snapshot path ingestion, already covered by Phase 3
- lexical restore target containment, already covered by Phase 4
- unsafe temp/rename cleanup policy, Phase 6
- script path validation, Phase 10
- full filesystem abstraction
- full filesystem fault injection
- storage format changes
- GC behavior changes
- packed-storage changes
- broad restore/recovery rewrite
- CI workflow changes
- dependency/toolchain changes

## Design Rule

Phase 5 must protect filesystem write boundaries from symlink escape behavior without introducing a broad filesystem abstraction or platform-specific rewrite.

## Symlink-Sensitive Boundary Survey

| File | Function / Area | Boundary | Current pattern | Phase 5 action |
|---|---|---|---|---|
| `internal/storage/restore.go` | `resolveRestoreOutputPath` | restore destination root + target construction | destination mode mapping + path containment helper calls | keep containment and route symlink checks through explicit restore write-boundary helper |

## Symlink Policy Used

```text
Restore writes reject existing symlink components in the restore target path when those components participate in a write.
Existing final target symlinks are rejected.
Missing directories may be created after restore target containment and symlink checks pass.
```

Phase 5 defined and enforced symlink-sensitive restore write safety.

## Rejected Symlink Classes

- symlinked parent path that could redirect restore writes
- existing final restore target that is a symlink
- symlink escape attempts pointing outside the destination root

## Preserved Valid Restore Classes

- valid destination roots
- normal nested restore paths without symlink components
- existing non-symlink directories inside the destination root
