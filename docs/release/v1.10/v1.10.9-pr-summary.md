# v1.10.9 PR Summary — Filesystem Fault Injection Phase 1

## Summary

v1.10.9 introduces deterministic, test-only filesystem fault injection for Coldkeep.

This release builds on the v1.10.8 filesystem abstraction groundwork and uses scripted filesystem failures to validate restore, container, recovery/quarantine, and GC delete safety.

The key result is that covered filesystem faults fail closed, remain retry-safe, or are detectable by verification/recovery. The release does not expose production fault injection controls.

## Core Invariant

v1.10.9 must prove that deterministic filesystem failures do not cause silent corruption, unsafe metadata, broken restore, unsafe GC, or unrecoverable repository state.

## What changed

### Scripted fault filesystem helper

Added:

```text
internal/fsx/faultfs
```

The helper supports deterministic, test-only scripts for:

* write failure;
* partial write;
* ENOSPC-after-N-bytes;
* fsync failure;
* close failure;
* rename failure;
* mkdir failure;
* stat failure;
* remove failure.

It is opt-in and test-focused. It is not wired into production runtime paths.

### Restore fault scenarios

Added deterministic restore fault tests for seam-reachable restore failure paths.

Covered outcomes:

* restore failures fail closed;
* restore does not report false success;
* final destination corruption is avoided;
* seam gaps are documented rather than hidden.

### Container write/seal fault scenarios

Added deterministic container fault tests for write/seal paths.

Covered outcomes:

* open/create failures fail closed;
* header write failures are not treated as valid containers;
* payload write and partial-write failures do not become complete placements;
* fsync failures do not report false durable success;
* remove/retire failures preserve failure semantics.

### Recovery / quarantine fault scenarios

Added deterministic recovery/quarantine fault tests.

Covered outcomes:

* stat failures fail closed;
* orphan-scan read-dir failures fail closed;
* active-tail stat failures do not legitimize unsafe mappings.

### GC delete failure scenario

Added deterministic GC delete/remove fault coverage.

Covered outcome:

* GC physical delete failure remains safe and retry-compatible under current behavior.

### No-silent-corruption matrix

Added release-level matrix evidence consolidating Phase 1–5 fault-injection coverage.

The matrix documents:

* helper fault-class coverage;
* restore failure safety;
* container failure safety;
* recovery/quarantine failure safety;
* GC delete failure safety;
* known seam gaps;
* no production fault injection exposure.

## Known seam gaps

The release documents known seam gaps instead of hiding them.

Examples include:

* restore temp-file creation/write/sync areas that remain partially outside `fsx.FS`;
* container rollback truncate behavior that remains direct OS behavior after closing the active file;
* no production-wide filesystem fault injection API.

These are not v1.10.9 blockers because v1.10.9 covers deterministic fault injection on the seam surfaces introduced in v1.10.8.
