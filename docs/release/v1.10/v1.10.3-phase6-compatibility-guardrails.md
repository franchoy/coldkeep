## Compatibility Guardrail Contract

### Current Format Rules

- Current packed metadata format is `format_version = 1` with supported codec values: 'none' (storage_blocks), 'plain' (blocks).
- Current packed metadata must still pass Phase 2–5 validation.
- Current valid packed containers must continue verifying successfully.

### Unsupported Format Rules

- Unsupported explicit versions (`format_version != 1`) must fail deterministically with `metadata_invalid` category at preflight gate.
- Unsupported codec values (not in approved list) must fail deterministically with `metadata_invalid` category at preflight gate.
- Ambiguous or corrupted block binary (magic/version mismatch) must fail at decode stage with `unsupported_block_format` category.

### Legacy / Missing Version Rules

- Packed metadata has no missing version/schema — `format_version` and `codec` are required NOT NULL fields.
- Missing `format_version` or `codec` is caught by database constraints and verify preflight gates.

### Fallback Rules

- No compatibility fallback path exists in current codebase.
- Compatibility rejection at preflight gate (`verifyStorageBlocks` query line 265) occurs before payload reads depend on metadata.
- Manifest/index validation (Phase 2) remains mandatory for any accepted packed metadata.
- Bounds validation (Phase 3) remains mandatory for any accepted packed metadata.
- Hash/checksum validation (Phase 4) remains mandatory for any accepted packed metadata.
- Malformed read-safety (Phase 5) remains mandatory for any accepted packed metadata.

### Error Behavior

- Unsupported compatibility states fail with deterministic errors at the preflight gate.
- Error category is `metadata_invalid` for version/codec preflight rejection.
- Error category is `unsupported_block_format` for decode-stage binary corruption.
- Errors identify the version/codec/format issue for operator debugging.

## Phase 6 Implementation Decision

Decision: **Path B — No explicit version/schema discriminator needed.**

Reason:

- Current packed metadata has no missing version/schema: `format_version` and `codec` are required NOT NULL fields in the database schema.
- Write paths always hardcode `format_version = 1`; only one format version exists in production.
- Current implicit format assumptions are documented: metadata must be `format_version = 1` with approved codec values.
- Compatibility guardrails already exist in production at the preflight gate (`verifyStorageBlocks` query, verify_repository.go line 265).
- No new explicit version/schema field is necessary; the constraint-based enforcement is sufficient.
- No migration engine is required; only regression tests to document the guardails and validate no bypass occurs.

Implementation impact:

- **No production code changes required.**
- Add 4 regression tests to document guaranteed behavior.
- Fill Phase 6 documentation and inventory.
- Extend test coverage to VerifyRepositoryFast and unsupported codec paths (existing VerifyRepository tests already cover format_version=2).
