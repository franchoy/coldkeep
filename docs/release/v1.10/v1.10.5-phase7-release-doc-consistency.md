## Cross-File Consistency Rules

### Phase Status vs Checklist

- If a phase is `Complete` in `v1.10.5-phase-status.md`, the matching phase checkbox must be checked in `v1.10.5-checklist.md`.
- If a phase is the `Current Next Phase`, it must remain unchecked in the checklist.
- Future phases must remain unchecked.
- Release gates must not be checked before the corresponding event occurs.

### Test Inventory Evidence

- Every `covered` test-inventory row must have:
  - `existing_test_files`
  - `existing_test_functions`
  - empty `missing_tests`
- Every pending/missing row must explain what is missing.
- Synthetic process/documentation rows must point to concrete document sections.

### Matrix / Issue Inventory

- Included matrix rows must have corresponding test-inventory evidence before closure.
- Deferred rows must not be closed accidentally.
- Issue inventory counts should match linked matrix ownership.

### Validation Reports

- Validation reports must distinguish:
  - local required gates,
  - environment-sensitive gates,
  - CI-authoritative gates,
  - advisory analyzer findings,
  - archived/non-gating checks.
- Known exceptions must reference their investigation phase.

### PR / Release / Changelog Docs

- PR notes, release notes, and changelog must agree on:
  - release name,
  - release type,
  - scope,
  - validation summary,
  - known exceptions,
  - out-of-scope items.
- Root `CHANGELOG.md` must include the same release summary as the release changelog.

### Final Release State

- After release publication, final release state gates must be updated.
- `phase-status` should include final published state.
- Checklist should record PR, CI, Codacy, merge, tag, publication, branch removal, and clean-tree completion.

## Validation Script Expectations

Each release should run a lightweight documentation consistency check before PR.

Minimum checks:

- required release docs exist
- phase-status and checklist agree on completed/current phases
- test inventory covered rows have evidence
- missing tests are cleared for completed phases
- release gates are not checked before execution
- final release gates remain unchecked until publication
- PR/release/changelog docs agree once created
- closure rows, if any, have closure proof

Suggested command pattern:

```bash
python3 docs/release/v1.10/validate_v1_10_x_release_docs.py v1.10.5
```

If no reusable script exists yet, use release-local validation snippets and document the result.
