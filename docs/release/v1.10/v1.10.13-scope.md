# v1.10.13 Scope — Post-Release Correctness Hardening

Status: Active

## Purpose

v1.10.13 fixes concrete correctness gaps found immediately after v1.10.12 through an adversarial post-release audit. It does not start v1.11 architecture work.

## Release Name

v1.10.13 — Post-Release Correctness Hardening

## Core Invariant

Never lose user data. Every fix must be narrower than the invariant it protects.

## Verdict summary

10 issues accepted. 1 issue excluded (C1 — already fixed). 1 issue modified from original plan (G1 — fail-closed, not no-op).

| ID | Area | Decision | Reason |
|----|------|----------|--------|
| V1 | Verify packed container file existence | Accept | Real gap. checkContainersFileExistence only covers legacy blocks, not storage_blocks. |
| V2 | NULL hash bypass for packed blocks | Accept | Packed blocks with NULL physical/compressed hash silently skip payload verify stages. |
| G4 | GC sealed scan excludes sealing=TRUE | Accept | One-line guard. Sealed scan does not filter sealing=TRUE containers. |
| G2 | GC FK violation diagnostic | Accept | FK violation on container delete returns raw DB error instead of actionable GC diagnostic. |
| V3 | UNIQUE(container_id, container_offset) on storage_blocks | Accept | No schema-level guard against overlapping packed block placement. Requires migration preflight. |
| S1 | Snapshot source requires completed logical files | Accept | snapshotSourceQuery joins physical_file to logical_file without lf.status filter. |
| S2 | Snapshot parent cycle detection | Accept | Only self-reference is checked; A→B→A cycles require direct DB manipulation but are unguarded. |
| X1 | SQLite foreign_keys=ON per session | Accept | ApplySQLiteSessionPragmas sets busy_timeout only; FK constraints unenforced on SQLite connections. |
| G1 | GC advisory lock hardcoded PostgreSQL | Modify | SQLite live GC must fail-closed (not silently proceed) to preserve GC singleton invariant. |
| C2 | Remove command JSON perf spans | Accept | runRemoveCommand does not pass perf spans; remove JSON output lacks timing metrics. |
| C1 | Duplicate singleton flag warning | Exclude | Already fixed in v1.10.12. rejectDuplicateSingletonFlag returns usageErrorf (hard reject, not last-wins). Do not downgrade. |

## Scope

Included:

- fix checkContainersFileExistence to cover storage_blocks-referenced containers (V1);
- fail-closed on NULL physical/compressed hash for non-legacy packed blocks (V2);
- add sealing=FALSE guard to GC sealed container scan (G4);
- improve GC FK violation error to actionable diagnostic (G2);
- add UNIQUE(container_id, container_offset) to storage_blocks with migration preflight (V3);
- add lf.status=COMPLETED filter to snapshotSourceQuery (S1);
- add ancestor cycle detection to snapshot parent validation (S2);
- add PRAGMA foreign_keys=ON to ApplySQLiteSessionPragmas (X1);
- make SQLite live GC fail-closed with clear error; allow dry-run (G1 modified);
- add perf spans to runRemoveCommand JSON output (C2);
- regression tests for each fix.

Excluded:

- No engine extraction;
- No catalog abstraction;
- No default database backend change;
- No new product features;
- No broad refactors;
- C1 (duplicate singleton flag warning) — already hard-rejected in v1.10.12;
- v1.10.14 release evidence closure work.

## Non-goals

```
v1.10.13 = correctness/runtime hardening
v1.10.14 = release evidence closure + README/CHANGELOG/source-of-truth cleanup
v1.11.0  = behavior-preserving engine facade begins
```
