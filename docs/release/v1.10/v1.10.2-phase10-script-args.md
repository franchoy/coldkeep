# Phase 10 — Script Argument Validation for Security-Sensitive Paths

**Release:** v1.10.2 — Validation Security Hardening  
**Phase:** 10 — Script Argument Validation  
**Status:** Complete  
**Date:** 2026-05-16

## Executive Summary

Phase 10 hardens five security-sensitive benchmark scripts with deterministic argument validation. Each script now:
- Rejects empty/whitespace-only identifiers (RUN_ID)
- Rejects shell metacharacters and path traversal in paths
- Validates executable paths and relative-path constraints
- Exits with code 1 and a diagnostic message on any validation failure

All modifications preserve valid input semantics and introduce no breaking changes to existing valid invocations.

**Invariant Enforced:**

## Implementation Details

### Validation Strategy

**Identifier Validation (RUN_ID, DATASET_LABEL):**
- Reject if empty or whitespace-only
- Reject if containing shell metacharacters: `; | & < > $ ` ( ) [ ] { } \ * ? !`
- Reject if containing path traversal sequence (`..`)

**Path Validation (--output-dir, --bin):**
- Reject if empty or whitespace-only
- Reject if absolute (leading `/`)
- Reject if containing path traversal sequence (`..`)
- Reject if containing spaces (for --output-dir)

**Executable Validation (--bin in run_v19_baseline_pair.sh):**
- Existing: Check executable bit with `-x`
- New: Reject if containing path traversal (`..`)

### Changes per Script

**Scripts 1–4 (store, gc, restore, dedup):**
- Added `validate_identifier()` and `validate_relative_path()` helper functions
- Validate `RUN_ID` immediately after positional argument parsing
- Validate `--output-dir` in options parsing case statement
- Validation occurs before filesystem operations (mkdir, rm)

**Script 5 (baseline_pair):**
- Added path traversal check for `--bin` after executable-bit check
- Rejects `.._containing_bin_paths`
