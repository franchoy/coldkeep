# v1.10.8 — Filesystem Abstraction Groundwork

Status: Active

## Release Goal

v1.10.8 prepares Coldkeep for deterministic filesystem fault injection by introducing a carefully scoped filesystem abstraction plan.

This release is groundwork only. It identifies filesystem operations, classifies critical seams, defines the minimum abstraction boundary, and prepares behavior-preserving implementation work for later phases.

v1.10.8 must not introduce actual filesystem fault injection behavior.

## Core Invariant

v1.10.8 must prepare filesystem abstraction seams for future deterministic fault injection while preserving current storage, restore, container, recovery, snapshot, and GC behavior exactly.

## Included Scope

v1.10.8 may include:

- filesystem operation inventory;
- critical seam classification;
- minimal filesystem interface design;
- OS adapter design;
- no-op deterministic wrapper design;
- behavior-preserving seam introduction;
- equivalence tests proving default OS-backed behavior matches current behavior;
- documentation for future v1.10.9 fault injection.

## Excluded Scope

v1.10.8 must not include:

- ENOSPC simulation;
- short write simulation;
- fsync failure simulation;
- rename failure simulation;
- partial write fault injection;
- crash injection;
- broad storage refactors;
- engine extraction;
- catalog abstraction;
- default database changes;
- product feature work;
- new CLI behavior;
- hard coverage gates;
- mutation testing.

## Primary Packages of Interest

The likely packages of interest are:

- `internal/storage`
- `internal/container`
- `internal/recovery`
- `internal/snapshot`
- `internal/gc`
- `internal/maintenance`

Additional supporting areas may be inventoried but should not become broad refactor targets.

## Filesystem Operation Categories

v1.10.8 should inventory and classify operations such as:

- `os.Open`
- `os.OpenFile`
- `os.Create`
- `os.ReadFile`
- `os.WriteFile`
- `os.MkdirAll`
- `os.Rename`
- `os.Remove`
- `os.RemoveAll`
- `os.Stat`
- `os.Lstat`
- `os.ReadDir`
- `filepath.WalkDir`
- `File.Read`
- `File.Write`
- `File.Sync`
- `File.Close`

## Release Philosophy

Filesystem abstraction must be introduced only where it supports future deterministic fault injection.

The abstraction should not become a large portability layer, virtual filesystem, storage rewrite, or engine extraction.

The default adapter must preserve existing behavior.

## v1.10.8 Success Criteria

v1.10.8 succeeds when:

- filesystem operations are inventoried;
- critical seams are classified;
- a minimal abstraction is defined;
- default OS behavior is preserved;
- equivalence tests pass;
- future v1.10.9 fault injection has a safe insertion point;
- no product behavior changes are introduced.
