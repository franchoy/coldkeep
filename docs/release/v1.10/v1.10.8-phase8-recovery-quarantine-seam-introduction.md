# v1.10.8 Phase 8 — Recovery / Quarantine Seam Introduction

## Phase Identity

Phase 8 of v1.10.8: Recovery / Quarantine Seam Introduction

## Goal

Introduce the `fsx.FS` filesystem seam into the recovery and GC physical-deletion paths without changing default OS-backed behavior.

## Scope

**In scope:**

- `internal/recovery/system_recovery.go` — `Stat` and `ReadDir` call sites
- `internal/maintenance/gc.go` — `Remove` call sites

**Out of scope:**

- No changes to `internal/storage`, `internal/snapshot`, `internal/container`
- No changes to `.github/`, `scripts/`, `go.mod`, `go.sum`
- No fault injection behavior

## Changes

### `internal/recovery/system_recovery.go`

- Added `"github.com/franchoy/coldkeep/internal/fsx"` import
- Extracted `recoverSealingContainersWithFS(dbconn, containersDir, stats, fsys fsx.FS)` with `fsys.Stat(path)` replacing `os.Stat(path)`; thin wrapper `recoverSealingContainers` delegates to `fsx.Default()`
- Extracted `quarantineMissingContainersWithFS(dbconn, containersDir, stats, fsys fsx.FS)` with `fsys.Stat(path)` replacing `os.Stat(path)`; thin wrapper `quarantineMissingContainers` delegates to `fsx.Default()`
- Extracted `quarantineCorruptActiveContainerTailsWithFS(dbconn, containersDir, stats, fsys fsx.FS)` with `fsys.Stat(path)` replacing `os.Stat(path)`; thin wrapper delegates to `fsx.Default()`
- Extracted `quarantineOrphanContainersWithFS(dbconn, containersDir, stats, fsys fsx.FS)` with `fsys.ReadDir(containersDir)` replacing `os.ReadDir(containersDir)`; thin wrapper delegates to `fsx.Default()`
- Existing 3-parameter public function signatures preserved (no test breakage)

### `internal/maintenance/gc.go`

- Added `"github.com/franchoy/coldkeep/internal/fsx"` import; removed `"os"` import
- Added `removeContainerFileWithFS(fsys fsx.FS, path string)` helper as the GC physical-delete seam
- In `RunGCWithContainersDirResult`: added `fsys := fsx.Default()` after DB connection; replaced `os.Remove(containerPath)` (main sealed-container loop) with `removeContainerFileWithFS(fsys, containerPath)`
- Updated `cleanupFullyDeadActiveContainers` signature to accept `fsys fsx.FS`; replaced `os.Remove` with `removeContainerFileWithFS(fsys, containerPath)`; updated call site to pass `fsys`

## Test Files

### `internal/recovery/recovery_seam_test.go` (new)

- `TestRecoverySeamDefaultFSPreservesScanBehavior` — verifies orphan scan returns 0 for empty dir with default FS
- `TestRecoverySeamNoopFSMatchesDefaultBehavior` — verifies orphan scan count is identical with default and noop FS (1 orphan file)
- `TestRecoveryMissingContainerSeamPreservesStatBehavior` — verifies present containers are not quarantined through the noop seam (exercises `fsys.Stat` path)

### `internal/maintenance/gc_seam_test.go` (new)

- `TestGCDeleteSeamDefaultFSPreservesDeleteBehavior` — verifies `removeContainerFileWithFS` with default FS deletes file
- `TestGCDeleteSeamNoopFSMatchesDefaultBehavior` — verifies `removeContainerFileWithFS` with noop FS delegates Remove through to default FS

## Invariant Preservation

- Default recovery behavior: unchanged (OS-backed via `fsx.Default()`)
- Default GC physical deletion: unchanged (OS-backed via `fsx.Default()`)
- GC must never delete reachable data: logic unchanged; only the physical delete call is routed through the seam
- Recovery must not legitimize corrupt mappings: logic unchanged
- Existing 3-param test signatures in `system_recovery_test.go` preserved exactly

## Findings

- Recovery `os.Stat` call sites: 3 (seaming: `recoverSealingContainersWithFS`, `quarantineMissingContainersWithFS`, `quarantineCorruptActiveContainerTailsWithFS`)
- Recovery `os.ReadDir` call sites: 1 (seaming: `quarantineOrphanContainersWithFS`)
- GC `os.Remove` call sites: 2 (both routed through `removeContainerFileWithFS`)
- Fault injection behavior added: 0
- Restore call sites changed: 0
- Container call sites changed: 0
- Snapshot call sites changed: 0
