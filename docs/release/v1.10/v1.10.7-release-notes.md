# Coldkeep v1.10.7 Release Notes

## Release Theme

Critical-path coverage gates — visibility and policy foundation.

## Summary

v1.10.7 establishes coverage visibility for correctness-critical Coldkeep packages.

This release adds a report-only coverage script, formal baseline coverage artifacts, invariant mapping, soft threshold policy, report-only CI integration, regression-prevention design, and local validation evidence.

v1.10.7 does not enforce coverage thresholds.

## Added

- Critical package inventory for Tier 1, Tier 2, and Tier 3 coverage tracking.
- Report-only critical coverage script.
- Formal critical-path coverage baseline CSV and Markdown summary.
- Invariant coverage map connecting coverage evidence to correctness invariants.
- Soft threshold policy defining blockers, non-blockers, future hard-gate candidates, and interpretation rules.
- Report-only CI job that generates and uploads the critical coverage CSV artifact.
- Regression-prevention gate design for future soft/hard gate behavior.
- Local validation results for standard quality gates and coverage evidence.

## Important Notes

Known low-visibility Tier 1 packages are documented:

```text
internal/maintenance: 47.6%
internal/recovery: 44.9%
```

These are future hardening priorities, not v1.10.7 release blockers.

## CI

A new report-only job was added:

```text
critical-coverage-report
```

It generates a coverage CSV artifact using:

```bash
scripts/critical_coverage.sh --report
```

The job does not enforce package thresholds or compare against baseline.

## Validation

Local validation passed:

```text
go test ./...
go test -race ./...
go vet ./...
scripts/critical_coverage.sh --report
```

## Non-Goals

v1.10.7 does not:

* change product behavior;
* change storage behavior;
* change restore behavior;
* change verify behavior;
* change GC behavior;
* change snapshot behavior;
* change recovery behavior;
* change catalog behavior;
* change dependencies;
* add threshold enforcement;
* add global coverage gates;
* add mutation testing;
* add filesystem fault injection;
* implement engine extraction;
* implement catalog abstraction.

## Upgrade Notes

No migration is required.

This release is release-process and CI-visibility oriented.
