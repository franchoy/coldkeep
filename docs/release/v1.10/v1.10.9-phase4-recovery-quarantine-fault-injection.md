# v1.10.9 Phase 4 — Recovery / Quarantine Fault Injection Scenarios

Status: Complete

## Purpose

Phase 4 adds deterministic recovery/quarantine fault-injection scenarios using the v1.10.9 scripted fault filesystem helper.

## Core Invariant

Recovery and quarantine filesystem failures must fail closed, must not falsely quarantine or rehabilitate rows, and must preserve deterministic diagnostics.

## Implementation

Phase 4 adds recovery-focused tests for deterministic filesystem failures in quarantine scans.

## Scenarios Covered

| Scenario | Fault | Test |
|---|---|---|
| missing-container stat failure | `fail-stat` | `TestRecoveryFaultFSQuarantineMissingStatFailureFailsClosed` |
| orphan-scan read-dir failure | `read_dir` fault | `TestRecoveryFaultFSQuarantineOrphanReadDirFailureFailsClosed` |
| active-tail stat failure | `fail-stat` | `TestRecoveryFaultFSQuarantineCorruptActiveTailStatFailureFailsClosed` |

## Seam Gaps

The sealing-recovery path still falls back to the default sealing flow after an initial stat error.
That behavior is documented as an existing seam gap and is not overclaimed as part of Phase 4 coverage.

## Behavior Preservation

Phase 4 does not change default recovery behavior.

Faults are injected only through test-specific `faultfs` scripts.
