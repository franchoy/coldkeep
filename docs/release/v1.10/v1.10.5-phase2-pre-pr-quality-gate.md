## Required Pre-PR Code Quality / Codacy-Risk Gate

The required gate must run after release-candidate docs are complete and before PR creation.

Required command bundle:

```bash
git status --short

go vet ./...
go test ./internal/maintenance ./internal/retention -count=1
go test -race ./internal/maintenance ./internal/retention -count=1
go test ./... -run 'GC|Snapshot|Retention|Repair|Physical|Orphan|Report|DryRun|Destructive|Candidate|Parity|Concurrency|Mutation' -count=1

golangci-lint run ./...
staticcheck ./...
gosec ./...

git fetch origin
git diff --name-only origin/main...HEAD
git diff --stat origin/main...HEAD
git diff origin/main...HEAD -- '*.go'
```

Required interpretation:

- `git status --short` must be clean before the quality pass.
- `go vet`, relevant tests, race tests, `golangci-lint`, and `staticcheck` should pass.
- `gosec` findings may be fixed or documented, but must not be ignored.
- Branch diff must be reviewed to determine changed files.
- Changed Go files must be reviewed for new static/security issues.
- Changed Markdown/docs must be reviewed for release-doc formatting drift.
- The final working tree must be clean.

## Finding Classification Policy

Quality-gate findings must be classified into one of the following categories:

| Category | Meaning | Required action |
| --- | --- | --- |
| release-delta issue | Finding introduced or touched by current release branch | Fix before PR unless explicitly accepted with rationale |
| baseline-wide finding | Existing finding not introduced by current branch | Document as baseline and defer to the appropriate phase/release |
| tool unavailable | Required analyzer not installed or unavailable | Install tool and rerun where possible; otherwise document as tooling exception |
| false positive | Finding is not a real defect in context | Document rationale |
| unrelated cleanup | Finding is real but outside release scope | Defer unless release-blocking |

Rules:

- Real correctness/security/static-analysis findings in changed files should be fixed.
- Baseline-wide findings should not trigger broad unrelated refactors in the release branch.
- Tooling failures should be made explicit, not silently skipped.
- `gosec` findings require special attention because they may represent security debt.
- The PR message should summarize any documented baseline/tooling exceptions.

## Evidence Format

Each release should record the pre-PR gate result in the release checklist.

If findings are non-trivial, create a dedicated evidence document:

`docs/release/v1.10/v1.10.x-pre-pr-quality-gate.md`

Minimum evidence:

- command bundle executed
- pass/fail result for each command
- changed file list from `origin/main...HEAD`
- changed Go files reviewed
- docs/Markdown review performed
- findings classification summary
- fixes committed or deferrals documented
- final working tree clean

For v1.10.5, the checklist is sufficient unless the gate produces non-trivial findings.
