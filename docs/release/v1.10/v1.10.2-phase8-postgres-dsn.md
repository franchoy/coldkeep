# v1.10.2 Phase 8 - PostgreSQL DSN / Options Escaping

Status: Complete

## Purpose

Phase 8 hardens PostgreSQL connection-string construction for security-sensitive runtime and benchmark flows.

The expected invariant is:

> PostgreSQL DSN components must be validated and safely escaped before composition, and malformed security-sensitive values must fail deterministically.

## Scope

Included:

- centralized DSN construction in DB layer
- strict validation for host/user/db name presence and NUL rejection
- strict numeric/range validation for DB port
- explicit allowlist validation for sslmode
- escaping of connection-string values to prevent token injection via spaces/quotes/backslashes
- refactor benchmark and shared test helper call sites to centralized DSN builder
- focused regression tests for escaping and malformed values

Excluded:

- migration SQL behavior changes
- tracker/matrix closure work beyond CK-110-M012 evidence row
- script/CI/dependency/toolchain changes
- non-PostgreSQL backend behavior changes

- `internal/db/db.go`

## Design Rule

DSN construction is security-sensitive parsing/composition logic and must not use raw string concatenation from environment variables.

## Implementation Summary

| Area | Change | Test coverage |
|---|---|---|
| DB DSN builder | Added centralized DSN builder (`BuildPostgresConnStringFromEnv`) with component validation and value escaping. | `TestBuildPostgresConnStringEscapesCredentialAndDatabaseValues`; `TestBuildPostgresConnStringRejectsInvalidPort`; `TestBuildPostgresConnStringRejectsInvalidSSLMode`; `TestValidateDBConnComponentRejectsNUL`; `TestBuildPostgresConnStringFromEnvSupportsDatabaseOverride` |
| Runtime connect path | `ConnectDB` now uses validated DSN builder and fails early on invalid connection env values. | Covered by `internal/db` DSN unit tests |
| CLI benchmark DB paths | `createTemporaryBenchmarkDatabase` and `captureBenchmarkState` now use centralized DSN builder with explicit error wrapping. | `TestCreateTemporaryBenchmarkDatabaseRejectsMalformedPort`; `TestCaptureBenchmarkStateRejectsInvalidSSLMode` |
| Shared Postgres test helper | `OpenRawPostgresDB` now uses centralized DSN builder. | Build/compile coverage through test suite |

## Hardened Classes

- unescaped string concatenation for connection-string fields
- DSN token injection via spaces/quotes/backslashes
- malformed DB port values (non-numeric and out-of-range)
- unsupported sslmode values
- NUL-containing env components

## Preserved Behavior

- default host/port/user/db/sslmode fallbacks remain unchanged when values are unset/blank
- connect timeout behavior remains unchanged (`max(1, connectTimeoutSeconds)`)
- non-PostgreSQL runtime behavior is unchanged
