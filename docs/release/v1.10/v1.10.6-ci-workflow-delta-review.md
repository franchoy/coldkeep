# v1.10.6 CI Workflow Delta Review

Status: Complete

## Purpose

This review determines whether v1.10.6 needs CI workflow changes.

## Core Rule

CI workflow changes must be justified by correctness/release-integrity value and must not introduce noisy, style-only, or premature gates.

## Existing CI Surface

| Area | File / path | Current role | Review result |
|---|---|---|---|
| GitHub workflows | `.github/workflows/ci.yml` | Multi-stage correctness/release validation (`quality`, `correctness-matrix`, `legacy-compatibility`, `integration-stress`, `integration-long-run`, `adversarial`, `smoke`, `benchmark-matrix`, `ci-required`) | Keep unchanged in v1.10.6 |
| PR template | `.github/pull_request_template.md` | Structured PR invariant and validation evidence capture | Keep unchanged in v1.10.6 |
| Release scripts | `scripts/` | CI/release validation helpers (`audit_ci_enforcement.sh`, `validate_validation_matrix.sh`, `validate_regression_thresholds.py`, `run_snapshot_release_gate.sh`, `run_phase7_v17_binary_gate.sh`, `smoke.sh`) | Keep unchanged in v1.10.6 |
| Copilot CI instructions | `.github/instructions/ci.instructions.md` | Guidance only | No workflow behavior change |
| Critical-path coverage prompt | `.github/prompts/critical-path-coverage.prompt.md` | Guidance only | No workflow behavior change |
| Codacy passive policy | `docs/release/v1.10/v1.10.6-codacy-passive-policy.md` | Policy only | No config behavior change |

## Candidate CI Deltas Reviewed

| Candidate | Value | Noise risk | Decision | Rationale |
|---|---|---|---|---|
| Add hard Codacy gate | low | high | reject | Conflicts with passive-mode policy |
| Add global coverage threshold | low | high | reject | Critical-path coverage preferred |
| Add style-only lint blocking | low | high | reject | Not correctness-first |
| Add CodeRabbit | unclear | medium/high | reject/defer | Out of v1.10.6 scope |
| Add mutation testing gate | future value | high | defer | Out of v1.10.6 scope |
| Add filesystem fault injection | future value | medium/high | defer | Out of v1.10.6 scope |
| Add documentation consistency script to CI | medium | low/medium | defer | Needs reusable script design |
| Keep CI unchanged | high | low | accept | v1.10.6 is policy/tooling-guidance release |

## Decision

Decision: No CI workflow changes in v1.10.6.

Rationale:

- v1.10.6 is focused on CI/Codacy/Copilot workflow policy and guidance.
- Existing local and PR validation remains sufficient for this release scope.
- Hard Codacy, global coverage, and style-only gates would increase noise.
- Critical-path coverage and CI evolution should be introduced only after policy is stable and specific gates are justified.

## Future Work

Potential future releases may consider:

- reusable documentation consistency validator;
- critical-path coverage reporting;
- dependency/security report export;
- targeted workflow annotations;
- non-blocking scanner artifact upload.

Each future CI change must identify the correctness invariant it protects and whether it is advisory or release-blocking.
