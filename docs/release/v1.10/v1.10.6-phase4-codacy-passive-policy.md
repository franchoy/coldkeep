# v1.10.6 Phase 4 — Codacy Passive-Mode Policy

Status: Complete

## Purpose

Phase 4 documents Codacy's role in v1.10.6 and future v1.10.x stabilization releases.

The expected invariant is:

> Codacy must surface useful risk without becoming architectural authority, correctness authority, or a style-only release blocker.

## Scope

Included:

- document Codacy passive-mode policy;
- define allowed Codacy uses;
- define forbidden Codacy uses;
- define release-blocking criteria;
- define advisory/non-blocking criteria;
- define finding classification categories;
- define suppression and acceptance rationale rules;
- define PR merge requirements for Codacy findings;
- update v1.10.6 checklist, phase status, and test inventory.

Excluded:

- changing Codacy configuration;
- changing CI workflows;
- adding hard Codacy gates;
- changing production code;
- changing tests;
- changing scripts;
- changing dependencies;
- tracker/matrix closure;
- CodeRabbit adoption.

## Source Inputs

- v1.10.6 Phase 2 CI-specific Copilot instructions;
- v1.10.6 Phase 3 critical-path coverage prompt;
- v1.10.5 Pre-PR Code Quality / Codacy-Risk Gate experience;
- Coldkeep CI/Codacy workflow direction.

## Implementation Decision

Phase 4 is policy-only.

No Codacy configuration, CI workflow, production code, test, script, or dependency changes are made.
