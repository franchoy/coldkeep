## Survey Summary

Current packed metadata flow is split across two layers:

- Storage metadata load in `StorageBlockReader.loadBlockMetadata` from
  `storage_blocks` joined with `container`
- Staged verification in `verify.VerifyStoredBlock` using
  `verify.BlockStorageMetadata`

There is no separate packed-manifest/index object in the current read path.
The manifest/index role is represented by relational metadata fields in
`storage_blocks`, `container`, and decode-time chunk entries from block payload.

Canonical internal metadata types are centralized in
`internal/storage/metadata/metadata.go` as:

- `CompressionMetadata`
- `HashMetadata`
- `PayloadMetadata`
- `BlockStorageMetadata`

## Trust Boundaries

1. Database metadata boundary:
- `loadBlockMetadata` treats DB values as untrusted and validates required
  size/offset/compression metadata constraints before read/decode.

2. Container payload boundary:
- `ReadStoredPayload` and stage-ordered verify checks treat container bytes as
  untrusted and verify hash layers before decoding logical payload.

3. Decode output boundary:
- `validateDecodedChunkLayout` treats decoded chunk tables as untrusted until
  offset/size/layout invariants pass.

4. Error mapping boundary:
- `mapVerifyPipelineFailure` maps verify failures to canonical restore/reader
  hash mismatch categories only when category/location metadata is complete.

## Phase Invariants

1. Metadata contract invariant:
- Compression metadata contract must be explicit and valid.
- `compression_codec=none` requires `compression_level=NULL`.
- `compression_codec=zstd` requires bounded non-nil compression level.

2. Size/offset invariant:
- `plaintext_size > 0`, `stored_size > 0`, and `container_offset >= 0` are
  required before container read/decode.

3. Hash-stage ordering invariant:
- Physical hash mismatch must fail before decrypt/decompress.
- Compressed hash mismatch must fail before decompression output is trusted.
- Logical hash mismatch must fail before logical block decode is trusted.

4. Decode layout invariant:
- Decoded block chunk table must be contiguous, in-bounds, and fully cover the
  payload without gaps/overlaps/zero-sized entries.

5. Fail-closed invariant:
- Malformed metadata or malformed payload must return explicit verification
  errors and must not produce partial restore output.

6. Legacy compatibility invariant:
- Legacy rows with nil physical/compressed hash metadata remain readable under
  current compatibility semantics, while logical hash remains required.
