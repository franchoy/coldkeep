## Reference Integrity Validation Contract

### Logical File → Chunk Rules

- Every live logical-file chunk reference (file_chunk row) must point to an existing chunk record.
- Missing chunk references must fail deterministically where GC safety depends on them.
- Duplicate/conflicting file-chunk references must not cause unsafe deletion.
- Live logical-file references are GC roots.

### Chunk → Block Rules

- Every chunk block reference (blocks row) must point to valid storage record.
- Missing or ambiguous block references must fail deterministically where GC safety depends on them.
- Shared/deduplicated block references must remain protected while any reachable chunk references them.
- Duplicate/conflicting chunk-block references must not cause unsafe deletion.

### Block → Physical Rules

- Every reachable stored block must either have valid physical backing or a deterministic missing-physical error.
- GC must not delete physical data if block reachability cannot be evaluated.
- Missing physical data must not cause GC to classify related metadata as safely collectible.

### GC Safety Rules

- GC must fail closed when the reference graph is inconsistent.
- GC candidate selection must not treat ambiguous references as unreferenced.
- Destructive GC must not proceed with unsafe deletion if reference integrity is broken.
- Dry-run must surface unsafe reference states clearly if it cannot compute a safe candidate set.
