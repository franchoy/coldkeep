# v1.10.3 Phase 2 - Container Manifest / Index Validation

Status: Complete

## Purpose

Phase 2 implements packed container manifest/index validation.

The expected invariant is:

> Packed container manifest/index metadata must be parseable, schema-compatible,
> complete, non-conflicting, and internally consistent before any packed data
> reads depend on it.

## Scope

Included:

- survey manifest/index decoding and load paths
- identify required manifest/index fields
- validate manifest/index version or schema compatibility
- validate required fields are present
- validate duplicate/conflicting manifest/index entries are rejected
- validate references point to known entries where applicable
- validate malformed manifest/index metadata fails deterministically
- preserve valid existing packed container behavior
- focused regression tests for manifest/index validation

Excluded:

- offset/length/bounds validation, Phase 3
- hash/checksum consistency, Phase 4
- broad malformed container read-safety matrix, Phase 5
- compatibility/migration guardrails beyond version/schema checks needed here, Phase 6
- corruption regression matrix consolidation, Phase 7
- GC reachability corrections
- restore/recovery rewrites
- storage format redesign
- engine extraction
- catalog abstraction
- CI workflow changes
- dependency/toolchain changes
- tracker/matrix closure

Phase 2 validates manifest/index structure and internal references only.

Do not implement offset/length/bounds enforcement or hash/checksum verification
in this phase unless an existing manifest/index validation cannot be separated
from a minimal structural check.

## Manifest / Index Validation Contract

### Required Fields

- `storage_blocks` rows must have valid required metadata fields and hash presence.
- `chunk_block_refs` rows must include valid `chunk_id`, `block_id`, `offset_in_block`, and `size_in_block` values.
- Every `storage_blocks` row must have at least one `chunk_block_refs` row.

### Version / Schema Rules

- Supported storage-block format version is `1`.
- Unsupported format versions are rejected deterministically.
- Supported packed storage codec set remains `none` and `aes-gcm` at metadata level.

### Duplicate / Conflict Rules

- Duplicate/conflicting index entries per block are rejected.
- Conflicting per-block offsets in `chunk_block_refs` are rejected.
- Duplicate `(block_id, chunk_id)` manifest/index entries are rejected.

### Reference Rules

- `chunk_block_refs.block_id` must point to known `storage_blocks` entries.
- `chunk_block_refs.chunk_id` must point to known `chunk` entries.
- Missing referenced entries fail before payload reads.

### Error Behavior

- Invalid manifest/index metadata returns deterministic metadata errors.
- Invalid manifest/index metadata must not panic.
- Invalid manifest/index metadata must fail before payload-dependent packed reads.
