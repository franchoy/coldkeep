## Hash / Checksum Validation Contract

### Required Metadata Rules

- Required digest/hash fields must be present for packed blocks/chunks where integrity depends on them.
- Empty digest/hash values are invalid unless payload semantics explicitly allow absence.
- Digest/hash values must use the expected encoding format.

### Algorithm Rules

- Supported algorithm in current packed integrity implementation: implicit SHA-256.
- Unsupported algorithm identifiers are not accepted (no alternate algorithm field is currently supported in packed verify metadata).
- Because SHA-256 is implicit, digest length/format must be validated deterministically.

### Digest Length / Format Rules

- Hex-encoded digests must decode successfully.
- Decoded digest length must match SHA-256 length (32 bytes).
- Invalid hex or malformed digest strings fail deterministically.
- Optional binary digest fields (`physical_hash`, `compressed_hash`) must be exactly 32 bytes when present.

### Payload Consistency Rules

- Payload bytes read from packed storage must match expected digest/hash metadata.
- Hash mismatch must fail verification deterministically.
- Hash mismatch must not be silently ignored.
- Hash mismatch must not panic.

### Error Behavior

- Invalid hash/checksum metadata fails deterministically.
- Payload mismatch fails deterministically.
- Errors identify block/chunk context in verification-stage messages.
