# v1.10.7 Phase 3 — Baseline Coverage Capture

Status: Complete

## Purpose

Phase 3 captures the formal v1.10.7 critical-path coverage baseline.

This baseline is evidence. It records what coverage Coldkeep has at the start of the v1.10.7 coverage-gate stabilization train. It does not enforce thresholds and does not affect release decisions by itself.

## Core Invariant

Coverage baseline capture must not:

- delete or modify any existing coverage data;
- change `scripts/critical_coverage.sh`;
- introduce threshold enforcement;
- modify Go source, tests, CI workflows, or dependencies.

The baseline is a read-only snapshot of the current test suite effectiveness against critical packages.

## Baseline Artifacts

| Artifact | Purpose |
|---|---|
| `docs/release/v1.10/v1.10.7-coverage-baseline.csv` | Machine-readable per-package baseline values |
| `docs/release/v1.10/v1.10.7-coverage-baseline.md` | Human-readable tier tables, averages, low-visibility notes |

## Baseline Command

The baseline was generated with:

```bash
scripts/critical_coverage.sh --report \
  --csv-output docs/release/v1.10/v1.10.7-coverage-baseline.csv
```

The script is the Phase 2 report-only implementation. No flags were added. No thresholds were set.

## Phase 3 Behavior

Phase 3 does not change any behavior. The coverage script continues to run in report-only mode.

The baseline CSV and Markdown are documentation artifacts only.

## Low-Coverage Packages

Two Tier 1 packages are below 50% baseline coverage:

- `internal/maintenance` — 47.6%
- `internal/recovery` — 44.9%

These are not release failures. They are recorded as low-visibility areas for Phase 4 invariant mapping. Future test additions should target named correctness invariants in these packages, not coverage percentages.
