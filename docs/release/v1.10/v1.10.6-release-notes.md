# Coldkeep v1.10.6 — CI / Codacy / Copilot Workflow Hardening

## Release Type

Process, tooling-guidance, and validation-policy hardening release.

## Summary

Coldkeep v1.10.6 improves the release workflow around CI, Codacy, scanner findings, Copilot guidance, and validation evidence.

This release does not change product behavior. It adds release-process guidance and documentation so future releases can better distinguish correctness-critical findings from style noise, baseline scanner findings, and advisory tooling signals.

## What Changed

### Copilot workflow hardening

- Audited existing Copilot instructions and prompts from v1.10.5.
- Added CI-specific Copilot instructions.
- Added a critical-path coverage prompt.
- Reinforced that Copilot should help preserve v1.10.x release discipline, not introduce architecture or product work.

### CI / Codacy policy hardening

- Defined Codacy passive-mode policy.
- Defined scanner suppression and acceptance policy.
- Defined CI/Codacy release gate boundaries.
- Reviewed CI workflow delta options.
- Recorded that no CI workflow changes are made in v1.10.6.

### Coverage guidance

- Added critical-path coverage guidance.
- Prioritized safety-critical behavior over global coverage percentages.
- Documented that future coverage work should focus on GC, restore, verify, recovery, repair, storage parity, catalog behavior, snapshots, CLI/JSON contracts, and backend compatibility.

### Scanner and Codacy handling

- Defined scanner decision categories:
  - fixed,
  - suppressed,
  - accepted,
  - deferred,
  - duplicate,
  - baseline,
  - false-positive,
  - test-only accepted,
  - tooling noise,
  - release-blocking unknown.
- Defined release-impact classification.
- Required rationale and evidence for suppression, acceptance, deferral, and false-positive decisions.
- Reaffirmed that Codacy is signal, not authority.

### Validation

- Recorded local validation and workflow consistency evidence.
- Confirmed:
  - `go vet ./...` passed,
  - `go test ./... -count=1` passed,
  - `go test -race ./... -count=1` passed,
  - documentation validation passed,
  - scope guard passed.

## Compatibility

No product behavior changes are intended.

This release does not change:

- repository format,
- storage format,
- restore behavior,
- snapshot behavior,
- GC behavior,
- verify behavior,
- repair behavior,
- CLI behavior,
- JSON output behavior,
- database backend behavior,
- CI workflow behavior unchanged,
- dependency versions.

## Known Notes

- v1.10.6 intentionally keeps CI workflow behavior unchanged.
- Hard Codacy gates, global coverage gates, style-only blocking, CodeRabbit adoption, mutation testing, and filesystem fault-injection implementation remain out of scope.
- Future CI changes should identify the correctness invariant they protect and whether the gate is release-blocking or advisory.
