# Coldkeep v1.10.9 — Filesystem Fault Injection Phase 1

## Summary

Coldkeep v1.10.9 adds deterministic, test-only filesystem fault injection for correctness validation.

This release validates how Coldkeep behaves when filesystem operations fail in restore, container, recovery/quarantine, and GC delete paths.

The main goal is safety: injected faults must not cause silent corruption, false success, unsafe metadata, broken restore, unsafe GC, or unrecoverable repository state.

## What changed

### Deterministic fault filesystem helper

Added a scripted filesystem fault helper under:

```text
internal/fsx/faultfs
```

It supports deterministic tests for:

* write failure;
* partial write;
* ENOSPC-after-N-bytes;
* fsync failure;
* close failure;
* rename failure;
* mkdir failure;
* stat failure;
* remove failure.

### Restore fault coverage

Added restore fault tests proving seam-reachable restore filesystem failures fail closed and do not produce corrupted successful restore output.

### Container fault coverage

Added container write/seal fault tests proving incomplete header or payload writes are not falsely committed as complete durable success.

### Recovery and quarantine fault coverage

Added recovery/quarantine tests proving stat and read-dir failures fail closed and do not legitimize unsafe mappings.

### GC delete fault coverage

Added GC delete/remove failure coverage proving physical delete failure remains safe and retry-compatible under current behavior.

### No-silent-corruption matrix

Added release-level evidence consolidating all v1.10.9 fault-injection surfaces and known seam gaps.

## Validation

Local validation passed:

```text
go test ./...
go test -race ./...
go vet ./...
```

Targeted fault slices and release-control consistency checks also passed.

## Compatibility

No migration required.

v1.10.9 does not change:

* repository format;
* container format;
* storage format;
* CLI behavior;
* runtime defaults;
* catalog/database behavior;
* dependencies.

## Important note

v1.10.9 does not expose production fault injection.

All fault injection added in this release is deterministic and test-only.

## Known limitations

Some filesystem paths remain outside the `fsx.FS` seam and are documented for future hardening, including some restore temp-file paths and container rollback truncate behavior.

These limitations are documented and do not change existing runtime behavior.
