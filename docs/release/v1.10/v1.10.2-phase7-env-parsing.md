# v1.10.2 Phase 7 — Environment Parsing Hardening

Status: Complete

## Purpose

Phase 7 hardens environment/config parsing for security-sensitive settings.

The expected invariant is:

> Environment-derived configuration must be parsed explicitly, validated deterministically, and must not silently accept malformed or dangerous values.

## Scope

Included:

- survey environment/config parsing
- reject malformed boolean values
- reject malformed integer values
- reject whitespace-only values where empty is invalid
- validate security-sensitive enum/config values
- validate environment-derived path values where applicable
- deterministic error behavior for malformed env/config
- focused regression tests for scoped env parsing cases

Excluded:

- PostgreSQL DSN/options escaping, Phase 8
- script argument validation, Phase 10
- CI workflow changes
- dependency/toolchain changes
- broad config system redesign
- tracker/matrix closure

- `docs/release/v1.10/v1.10.2-matrix-inventory.csv`

## Design Rule

Phase 7 should harden parsing and validation at environment/config ingestion boundaries without changing unrelated runtime behavior.

## Environment / Config Parsing Survey

| File | Variable / Setting | Kind | Current pattern | Phase 7 action |
|---|---|---|---|---|
| `internal/utils_env/env.go` | `GetenvOrDefaultInt64` | int helper | `fmt.Sscanf` accepts partial numeric prefixes | use strict full-token parse via `strconv.ParseInt` |
| `internal/execution/options.go` | `COLDKEEP_STORE_FOLDER_WORKERS` | int | trims env and parses with `Atoi`; whitespace-only currently treated as unset | reject whitespace-only when env var is explicitly set |
| `internal/blocks/key.go` | `COLDKEEP_KEY` | security-sensitive string | raw env value decoded as hex; no trim/NUL guard | trim, reject whitespace-only and NUL, preserve AES-256 validation |
| `internal/blocks/config.go` | `COLDKEEP_CODEC` | enum | default fallback; whitespace-only treated as default | reject whitespace-only explicit override; unknown values error with setting name |
| `internal/storage/store.go` | `COLDKEEP_REUSE_SEMANTIC_VALIDATION` | enum | invalid values silently fallback to suspicious mode | return deterministic error on invalid/whitespace-only values |
| `internal/db/migrations.go` | `COLDKEEP_DB_AUTO_BOOTSTRAP` | bool | truthy parsing fallback to false on unknown values | parse accepted bool tokens explicitly and error on unknown values |
| `internal/iodebug/counters.go` | `COLDKEEP_IO_COUNTERS_FILE` | path-like env value | trimmed path; NUL not explicitly rejected | reject NUL with setting-specific error during flush |
| `internal/db/db.go` | `COLDKEEP_DB_*` timeout/conn envs | int | helper-based parse + default fallback | inherit strict full-token int parsing while keeping fallback semantics |

## Parsing Policy Used

```text
Environment/config values are trimmed before validation.
Whitespace-only values are rejected where empty is invalid.
Malformed bool/int/enum values fail deterministically.
Errors identify the setting name.
DSN/options escaping is deferred to Phase 8.
```

## Implementation Summary

Phase 7 hardened scoped environment/config ingestion boundaries for bool/int/enum/path-like settings used by runtime behavior.

| Area | Change | Test coverage |

| Worker count env parsing | `internal/execution.FromEnv` now rejects whitespace-only explicit `COLDKEEP_STORE_FOLDER_WORKERS` values with deterministic setting-name errors. | `TestFromEnvRejectsWhitespaceOnlyStoreFolderWorkersWhenSet` |

| Codec enum env parsing | `internal/blocks.LoadDefaultCodec` now rejects whitespace-only explicit `COLDKEEP_CODEC` and reports setting-name context on invalid enum values. | `TestLoadDefaultCodec_WhitespaceEnvFailsDeterministically`; `TestLoadDefaultCodec_InvalidEnv` |

| DB numeric env fallback hardening | DB timeout/conn loaders now inherit strict integer token parsing behavior from shared helper. | `TestLoadConnectTimeoutFallsBackOnMalformedPartialToken`; `TestLoadMaxOpenConnsFallsBackOnMalformedPartialToken` |

## Hardened Classes

- malformed boolean values
- malformed integer values
- whitespace-only values where invalid
- unknown enum/config values
- NUL-containing path/config values where applicable
- silent partial-token integer parse behavior

## Preserved Valid Classes

- documented valid boolean values (`true/false/1/0/yes/no/on/off` where applicable)
- documented valid integer ranges and fallback defaults where already defined
- documented valid enum values
- valid existing config defaults when variables are not set
- valid existing explicit config values
