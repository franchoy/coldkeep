# v1.10.1 Phase 3 — Unexpected Positional Arguments

Status: Complete

## Purpose

Phase 3 fixes CLI commands that accept or ignore unexpected positional arguments.

The expected invariant is:

> Commands must reject unexpected positional arguments before stateful work.

## Scope

Included:

- command arity validation
- trailing positional argument rejection
- regression tests for affected commands
- validation that invalid calls do not silently mutate state

Excluded:

- JSON shorthand fixes
- JSON output contract fixes
- boolean flag parsing fixes
- duplicate flag fixes
- value-flag token fixes
- restore/recovery internals
- storage, GC, packed-storage, and repository format changes

## Source Inputs

- `v1.10.1-matrix-inventory.csv`
- `v1.10.1-test-inventory.csv`
- `v1.10.1-issue-inventory.csv`

## Implemented Fixes

- Added top-level arity guards in `runCLI` so `help`, `-h`, `--help`, `version`, `-v`, and `--version` reject unexpected positional arguments with usage errors.
- Added an early arity guard in `initCommand` so `init` rejects positional arguments before key generation and `.env` write behavior.
- Added an early arity guard in `runSearchCommand` so `search` rejects positional arguments before DB connection.
- Added stricter arity validation in `runSimulateCommand`:
	- `simulate gc` now rejects trailing positional arguments.
	- `simulate store` and `simulate store-folder` now require exactly one path positional argument.
