## Candidate Request/Result Boundaries

These are planning notes only. No production Go types are defined here.

### Restore operations (P0)

Candidate request fields include: logical_file_id or stored_path pattern; destination path or mode (original/prefix/override); overwrite flag; workers count; dry-run flag.

Candidate result fields include: per-file status (restored/skipped/failed); bytes restored; error with invariant_code; deterministic ordering.

The temp-write-then-rename-then-fsync pattern is the correctness constraint; future contracts must preserve it.

### GC operations (P0)

Candidate request fields include: containers_dir; dry_run flag.

Candidate result fields include: containers_to_delete or containers_deleted; bytes reclaimable or reclaimed; reachable_set_size.

Dry-run and live-run must produce equivalent reachability analysis results; the only difference is whether files are deleted.

### Snapshot operations (P0)

Candidate request fields include: snapshot query (id/label/latest); destination mode; path filter; parent_id.

Candidate result fields include: snapshot_id; files_inserted or files_restored; created_at; lineage chain.

All-or-nothing atomicity is the core constraint for snapshot_create. Deterministic_restore invariants apply to snapshot_restore.

### Recovery and bootstrap (P0)

Candidate request fields include: containers_dir; quiet_if_healthy flag; command context.

Candidate result fields include: StorageContext handle; recovery_report with quarantined_containers and incomplete_ops_aborted; healthy flag.

The recovery gate must always run before any other DB write. This sequencing is the core invariant.

## Error Boundary Notes

The following error handling boundaries must remain stable across all future engine-boundary work:

- **CLI exit behavior**: exit codes 1 (general), 2 (usage), 3 (verify failure), 4 (recovery failure) must not change.
- **JSON error shape**: the error JSON envelope with `invariant_code`, `recommended_action`, `dbHint`, and `verifyDetails` fields is frozen.
- **Validation-before-mutation**: numeric flags (limit/offset/workers/min_size/max_size) must be validated before any DB access.
- **Fail-closed verification**: verify must report all errors; must not partially succeed; GC must not run on verify failure.
- **No partial restore success ambiguity**: a restore that writes a temp file but fails to rename must not report success.
- **GC dry-run/live equivalence**: the reachability set computed in dry-run must exactly match what live-run would delete.
- **Recovery must not legitimize corrupt mappings**: quarantine operations are fail-closed; stat() error aborts recovery.
- **Doctor JSON contract frozen**: the v1.0 doctor JSON schema with recovery counters must not change shape.
- **Snapshot atomicity**: CreateSnapshotWithOptions must be all-or-nothing; no partial snapshot row state is acceptable.
