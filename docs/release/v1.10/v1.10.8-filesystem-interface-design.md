# v1.10.8 Filesystem Interface Design

Status: Designed

## Purpose

This document defines the minimal filesystem abstraction boundary for v1.10.8.

The design is derived from the Phase 2 seam classification and is intended to prepare Coldkeep for future deterministic filesystem fault injection in v1.10.9.

v1.10.8 must remain behavior-preserving.

## Core Invariant

The v1.10.8 filesystem interface must be minimal, behavior-preserving, and derived only from classified seam groups needed for future deterministic fault injection.

## Design Scope

The interface covers the 9 seam groups classified in Phase 2:

* `FileOpen`
* `FileStat`
* `FileSync`
* `FileWrite`
* `FileRename`
* `FileRemove`
* `DirCreate`
* `DirRead`
* `DirWalk`

The design also includes `File.Read` and `File.Close` because returned files need a behavior-preserving lifecycle.

## Proposed Package

```text
internal/fsx
```

The name is intentionally small and internal.

It avoids claiming to be a complete virtual filesystem or portability layer.

## Proposed Interfaces

```go
package fsx

import (
	"io"
	"io/fs"
)

type FS interface {
	Open(name string) (File, error)
	OpenFile(name string, flag int, perm fs.FileMode) (File, error)
	Stat(name string) (fs.FileInfo, error)
	MkdirAll(path string, perm fs.FileMode) error
	Rename(oldpath string, newpath string) error
	Remove(name string) error
	ReadDir(name string) ([]fs.DirEntry, error)
	WalkDir(root string, fn fs.WalkDirFunc) error
}

type File interface {
	io.Reader
	io.Writer
	io.Closer
	Sync() error
}
```

## Intentional Omissions

The interface does not include:

* `RemoveAll`;
* `ReadFile`;
* `WriteFile`;
* `Lstat`;
* `Mkdir`;
* `Chmod`;
* `Chtimes`;
* path normalization helpers;
* repository layout helpers;
* catalog/database operations;
* fault injection controls.

These can be added later only if a future phase proves they are required.

## OS Adapter Direction

Phase 4 should implement an OS-backed adapter with direct behavior parity:

```go
type OSFS struct{}
```

The adapter should delegate to:

* `os.Open`
* `os.OpenFile`
* `os.Stat`
* `os.MkdirAll`
* `os.Rename`
* `os.Remove`
* `os.ReadDir`
* `filepath.WalkDir`

The adapter must not reinterpret errors, normalize paths, retry operations, swallow errors, or change permissions.

## File Adapter Direction

Phase 4 should wrap `*os.File` as the concrete `File`.

The wrapper must preserve:

* read behavior;
* write behavior;
* close behavior;
* sync behavior;
* error propagation.

## Behavior Preservation Rules

The default OS-backed filesystem must preserve existing behavior exactly:

* same error behavior;
* same permission behavior;
* same path interpretation;
* same atomic rename behavior;
* same sync behavior;
* same close behavior;
* same traversal behavior.

## Future v1.10.9 Fault Injection

Fault injection is intentionally not part of v1.10.8.

The interface should later allow deterministic wrappers to simulate:

* open failure;
* write failure;
* sync failure;
* rename failure;
* remove failure;
* stat failure;
* read directory failure;
* walk failure.

But v1.10.8 must not implement these failures.

## Non-Goals

This design is not:

* a general virtual filesystem;
* a portability layer;
* an engine boundary;
* a catalog abstraction;
* a broad storage rewrite;
* a fault injection implementation.
