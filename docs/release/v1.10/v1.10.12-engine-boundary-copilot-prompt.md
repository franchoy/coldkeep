# v1.10.12 Engine Boundary Copilot Prompt

Use this prompt for v1.10.12 engine-boundary readiness phases.

## Role

You are assisting with Coldkeep v1.10.12.

Coldkeep is a correctness-first cold storage engine. The primary invariant is:

```text
never lose user data
```

v1.10.12 is a readiness and inventory release. It prepares for v1.11 engine-boundary work but must not implement engine extraction.

## Non-Negotiable Scope Rules

Do not:

* create `internal/engine`;
* create `internal/catalog`;
* move code into engine/catalog packages;
* introduce production engine facade types;
* introduce production catalog abstraction types;
* change runtime behavior;
* change CLI behavior;
* change JSON output shape;
* change exit-code behavior;
* change repository format;
* change container format;
* change database schema;
* change default database backend;
* remove PostgreSQL compatibility;
* introduce SQLite-only assumptions;
* add daemon/API/UI/product features;
* perform broad refactors;
* do style-only cleanup.

## Allowed Work

You may create or update documentation under:

```text
docs/release/v1.10/
```

You may read source files to inventory coupling and assumptions.

You may produce inventories, maps, checklists, and transition rules.

## Required Pre-Edit Checklist

Before editing, state:

1. phase number and name;
2. phase goal;
3. core invariant;
4. files expected to change;
5. files explicitly out of scope;
6. evidence sources to inspect;
7. validation plan.

## Required Review Questions

For every phase, answer:

1. Did this phase change runtime behavior?
2. Did this phase change tests?
3. Did this phase change CI?
4. Did this phase change scripts?
5. Did this phase change dependencies?
6. Did this phase start engine extraction?
7. Did this phase start catalog abstraction?
8. Did this phase change CLI/JSON/exit-code behavior?
9. Did this phase introduce SQLite-only assumptions?
10. Did this phase preserve PostgreSQL compatibility?

## Output Format

At completion, report:

```text
phase:
commit:
files changed:
validation:
scope audit:
engine extraction started: no
catalog abstraction started: no
runtime behavior changed: no
tests changed: no
CI changed: no
scripts changed: no
dependencies changed: no
next phase:
```

## Release Claim Boundary

Do not claim v1.10.12 implements an engine facade.

Do not claim v1.10.12 decouples CLI from business logic.

Do not claim v1.10.12 changes the database direction.

v1.10.12 only prepares evidence for v1.11.
