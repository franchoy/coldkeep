# v1.10.1 Scope

Status: Complete  
Owner phase: v1.10.1 Phase 0 — Branch Baseline & Scope Lock

## Release

v1.10.1 — CLI Correctness & Contract Stabilization

## Purpose

v1.10.1 remediates the CLI and JSON contract issues identified during the v1.10.0 baseline/freeze work.

The goal is to make invalid CLI inputs fail deterministically, make JSON-mode behavior consistent for targeted commands, and ensure invalid input does not perform unexpected stateful work.

## Included Scope

v1.10.1 may change:

- CLI argument arity validation
- unexpected positional argument rejection
- value flag validation
- boolean flag explicit false behavior
- duplicate singleton flag behavior
- JSON shorthand consistency
- JSON output-mode contract for targeted commands
- pre-stateful validation ordering where directly tied to CLI misuse
- CLI-focused regression tests
- documentation, changelog, and release notes for v1.10.1

## Included Matrix Families

Expected v1.10.1 matrix families include:

- CLI unexpected positional arguments
- CLI value flags accepting another flag as value
- CLI boolean explicit false semantics
- CLI duplicate singleton flags
- JSON shorthand mismatch
- JSON mixed/human output in machine mode, if targeted to v1.10.1
- CLI validation before repository initialization, only where directly tied to CLI contract

Primary matrix rows currently identified for this release:

- `CK-110-M008` — JSON mode must be consistently accepted and emit machine-consumable output
- `CK-110-M028` — Boolean flags with explicit false must not be interpreted as true
- `CK-110-M029` — Commands must reject unexpected positional arguments before stateful work
- `CK-110-M030` — Singleton flags must reject duplicate occurrences instead of last-win behavior
- `CK-110-M086` — Value flags must reject another flag token as their value

## Excluded Scope

v1.10.1 must not include:

- packed-storage remediation
- GC, refcount, or reachability remediation
- restore or recovery internals remediation
- storage format changes
- repository format changes
- filesystem abstraction
- filesystem fault injection
- cross-platform CI expansion
- Codacy hard blocking
- coverage gates
- dependency or toolchain upgrades unless release-blocking
- engine extraction
- new product features
- broad CLI redesign
- unrelated refactors
- broad style-only cleanup

## Boundary Rule

If a finding requires changing storage, GC, packed storage, restore or recovery internals, or repository format, it is not v1.10.1 scope unless the change is strictly limited to CLI-level validation before entering that subsystem.

## Success Criteria

v1.10.1 is successful when:

- selected v1.10.1 matrix rows are fixed, accepted, deferred, duplicated, or proven not applicable
- CLI invalid input behavior is deterministic
- targeted JSON shorthand behavior is consistent
- targeted machine output is valid and not mixed with human output
- regression tests cover each fixed contract class
- tracker and matrix closure proof are updated
- local validation and CI are green
