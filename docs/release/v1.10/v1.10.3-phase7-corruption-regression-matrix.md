# v1.10.3 Phase 7 — Corruption Regression Test Matrix

Status: Complete

## Purpose

Phase 7 consolidates packed-storage metadata-integrity and corruption regression coverage.

The expected invariant is:

> Packed-storage corruption coverage must be explicit, reproducible, and mapped to each metadata-integrity failure class.

## Scope

Included:

- collect and map Phase 2–6 packed-storage validation tests
- map each corruption/failure class to concrete tests
- identify and document coverage gaps
- preserve valid packed-storage behavior evidence
- define stable targeted test commands for packed corruption coverage
- update release tracking evidence

Excluded:

- new production behavior (unless a release-blocking gap is discovered)
- GC reachability corrections
- restore/recovery rewrites
- storage format redesign
- engine extraction
- catalog abstraction
- CI workflow changes
- dependency/toolchain changes
- tracker/matrix closure

## Source Inputs

- Phase 2 manifest/index tests in `internal/verify/verify_system_test.go`
- Phase 3 offset/length/bounds tests in `internal/verify/verify_system_test.go`
- Phase 4 hash/checksum tests in `internal/verify/verify_system_test.go`
- Phase 5 malformed read-safety tests in `internal/verify/verify_system_test.go`
- Phase 6 compatibility guardrail tests in `internal/verify/verify_system_test.go`
- corruption fixture tests in `internal/verify/verify_corruption_fixtures_test.go`

## Design Rule

Phase 7 is a regression-matrix consolidation phase.

Prefer documenting and mapping existing coverage. Add new tests only where a concrete coverage gap remains.
