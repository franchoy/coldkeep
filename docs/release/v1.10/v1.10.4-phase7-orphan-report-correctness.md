# v1.10.4 Phase 7 — Orphan Detection & Reporting Correctness

Status: Complete

## Purpose

Phase 7 validates orphan detection and reporting correctness for GC/maintenance flows.

The expected invariant is:

> GC and maintenance reports must not misclassify protected, missing, or ambiguous data as safely reclaimable orphan data.

## Scope

Included:

- survey orphan detection paths
- survey GC dry-run/report fields
- survey maintenance/doctor/repair report classifications
- document report categories and meanings
- confirm unreachable metadata is distinguished from missing physical data
- confirm snapshot-retained data is not reported as collectible
- confirm ambiguous/inconsistent graph states are not reported as actionable deletion candidates
- confirm reclaimable counts/bytes map to actual validated candidates
- add or identify regression tests for reporting/classification correctness

Excluded:

- candidate-selection safety already covered in Phase 4
- dry-run/destructive parity already covered in Phase 5
- physical deletion guardrails already covered in Phase 6
- concurrency/mutation guardrails, Phase 8
- regression matrix consolidation, Phase 9
- full restore/recovery rewrite
- packed-storage metadata work
- CI workflow changes
- dependency/toolchain changes
- tracker/matrix closure

## Orphan / Report Classification Contract

### Category Rules

- `reclaimable` must mean validated GC candidate.
- `orphan` must not mean missing physical backing unless explicitly documented.
- `missing_physical` must be distinct from collectible/reclaimable data.
- `retained` or snapshot-protected data must not be reported as reclaimable.
- `ambiguous` or inconsistent graph states must not be reported as actionable candidates.

### Count / Byte Rules

- Reclaimable counts must map to validated candidates.
- Reclaimable bytes must map to validated candidate physical data.
- Missing physical data must not inflate reclaimable bytes.
- Retained/protected data must not inflate reclaimable bytes.

### Error / Warning Rules

- Inconsistent graph state should be reported as an error or warning, not as reclaimable.
- Missing physical data should be deterministic and distinguishable.
- Partial report generation must not silently drop unsafe states.

### Consumer Rules

- JSON output should preserve machine-readable category distinctions.
- Text output should not imply protected/missing data is safely deletable.
