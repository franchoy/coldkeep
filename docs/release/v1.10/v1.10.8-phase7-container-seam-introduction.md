# v1.10.8 Phase 7 — Container Seam Introduction

Status: Complete

## Purpose

Phase 7 introduces the filesystem abstraction seam into container write, sync, create, quarantine, and seal paths while preserving default OS-backed behavior.

## Core Invariant

Container behavior must remain byte-for-byte and failure-semantics equivalent when using the default OS-backed filesystem seam.

## Implementation

### fsx.File extension (internal/fsx/fs.go)

`fsx.File` was extended to include `io.ReaderAt`, `io.Seeker`, and `Truncate(size int64) error`. These methods are required by `FileContainer` (which uses `ReadAt`, `Seek`, and wraps a truncatable file). `*os.File` satisfies all seven methods. `OSFS` and `NoopFS` are unchanged.

### FileContainer (internal/container/container.go)

`FileContainer.f` changed from `*os.File` to `fsx.File`. This allows the container handle itself to be backed by any file implementation satisfying the interface.

### format.go (internal/container/format.go)

Both `writeNewContainerHeader` and `readAndValidateContainerHeader` changed from `*os.File` to `fsx.File`. The `"os"` import was removed; `"github.com/franchoy/coldkeep/internal/fsx"` was added.

### Internal container helpers (internal/container/container.go)

- `openExistingContainer(readonly bool, path string, maxSize int64, fsys fsx.FS)` — added `fsys` parameter. Uses `fsys.OpenFile` for open and `fsys.Stat(path)` for file size (replacing `f.Stat()`).
- `getOrCreateOpenContainerInDirExcluding(tx, dbconn, containersDir, excludeID, fsys fsx.FS)` — added `fsys` parameter. Uses `fsys.MkdirAll`, `fsys.OpenFile`, `fsys.Remove`, and `quarantineContainerInDirWithFS`/`openExistingContainer` with the injected FS.
- `sealContainerInDirWithFS(tx, containerID, filename, containersDir, fsys fsx.FS)` — extracted from `SealContainerInDir`. Uses `fsys.Stat` for sealed-file size.
- `quarantineContainerInDirWithFS(dbconn, containerID, containersDir, fsys fsx.FS)` — extracted from `QuarantineContainerInDir`. Uses `fsys.Stat` for physical file size; `os.IsNotExist` stays direct since it inspects error values, not filesystem calls.

Public-facing functions `OpenReadOnlyContainer`, `OpenWritableContainer`, `GetOrCreateOpenContainerInDirExcluding`, `SealContainerInDir`, and `QuarantineContainerInDir` retain their existing signatures and delegate to the internal variants with `fsx.Default()`.

### LocalWriter seam injection (internal/container/local_writer.go)

An unexported `fs fsx.FS` field was added to `LocalWriter` (with comment documenting seam-injection intent). `NewLocalWriterWithDirAndDB` sets `fs: fsx.Default()`. All internal FS operations route through `w.fs`:

- `ensureActiveExcluding`: `os.MkdirAll` → `w.fs.MkdirAll`; delegates to `getOrCreateOpenContainerInDirExcluding` with `w.fs`.
- `RollbackLastAppend`: `os.Stat` ×2 → `w.fs.Stat` ×2. `os.Truncate` remains direct (path-based truncate operates on a closed file; not in `fsx.FS`).
- `quarantineContainer`: delegates to `quarantineContainerInDirWithFS` with `w.fs`.

## Scope

Phase 7 is limited to container paths. Storage, restore, recovery, GC, snapshot, and maintenance paths are not changed.

## Seam Tests

Three new tests in `internal/container/container_seam_test.go`:

- `TestContainerSeamDefaultFSPreservesWriteBehavior`: full `AppendPayload` cycle with the default OS-backed seam; verifies bytes at the returned offset.
- `TestContainerSeamNoopFSMatchesDefaultBehavior`: same cycle with `fsx.NewNoop(fsx.Default())` injected into `LocalWriter.fs`; verifies byte-identical output.
- `TestContainerSeamPreservesRetireRemoveBehavior`: quarantine path with NoopFS injected; verifies DB row quarantined and active state cleared.
