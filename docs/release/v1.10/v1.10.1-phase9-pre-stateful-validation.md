# v1.10.1 Phase 9 - Pre-Stateful Validation Ordering

Status: Complete

## Purpose

Phase 9 verifies and fixes validation ordering for scoped invalid CLI inputs.

The expected invariant is:

> Invalid CLI usage should fail before stateful work whenever the invalidity can be detected from arguments alone.

## Scope

Included:

- argument-only validation before repository initialization
- argument-only validation before key generation
- argument-only validation before env-file load/write behavior
- argument-only validation before destructive/stateful command execution
- regression tests proving invalid usage does not mutate filesystem state where practical

Excluded:

- new CLI contract categories beyond Phases 3-8
- storage behavior changes
- GC/refcount/reachability changes
- packed-storage changes
- restore/recovery internals
- CI workflow changes
- dependency/toolchain changes
- broad command dispatcher redesign

- `docs/release/v1.10/v1.10.1-matrix-inventory.csv`

## Implementation Summary

Phase 9 changed validation ordering for the following command families:

| Command / Family | Invalid usage guarded | Stateful work protected | Test coverage |
|---|---|---|---|
| config get | unexpected extra positional arguments (`config get compression-level extra`) | storage context initialization for config read path | `TestConfigGetPreStatefulRejectsExtraPositionalBeforeStorageInit` |
| repair ref-counts batch | missing input-file path (`repair ref-counts --batch --input missing.json`) | repair execution path (`repairLogicalRefCountsPhase`) is not entered on invalid input | `TestRepairBatchPreStatefulRejectsMissingInputBeforeRepairExecution` |
| snapshot create (`--from`) | missing parent snapshot remains repository-state dependent | deterministic missing-parent error behavior in JSON mode remains explicit and covered | `TestSnapshotCreateFromMissingParentStateDependentDeterministicError` |

## Validation Ordering Policy Used

```text
Argument-only CLI validation must complete before repository initialization, key generation, env-file behavior, filesystem mutation, or destructive command execution where practical.
```
