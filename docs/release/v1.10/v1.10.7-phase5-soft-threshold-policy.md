# v1.10.7 Phase 5 — Soft Threshold Policy

Status: Complete

## Purpose

Phase 5 defines the soft threshold policy for v1.10.7 critical-path coverage.

This phase explains how baseline coverage and invariant coverage evidence should be interpreted without adding enforcement.

## Core Invariant

Soft thresholds must guide future coverage hardening without turning v1.10.7 into a raw percentage chase or blocking release on known baseline gaps.

## Artifact

```text
docs/release/v1.10/v1.10.7-soft-threshold-policy.md
```

## Policy Summary

v1.10.7 uses soft threshold interpretation only.

The policy defines:

* baseline-required evidence;
* regression warning semantics;
* soft targets;
* hard-gate candidates for future work;
* Tier 1 / Tier 2 / Tier 3 interpretation;
* explicit release blockers;
* explicit non-blockers.

## Important Decision

Known low-visibility Tier 1 packages are not release blockers in v1.10.7:

```text
internal/maintenance: 47.6%
internal/recovery: 44.9%
```

They are future hardening priorities because they are now visible, documented, and mapped to correctness invariants.

## Non-Goals

Phase 5 does not:

* change `scripts/critical_coverage.sh`;
* add `--soft-gate`;
* add `--hard-gate`;
* enforce thresholds;
* compare coverage against baseline;
* change CI workflows;
* add tests;
* change Go code;
* change dependencies.

## Validation

Phase 5 validation confirms:

* soft threshold policy exists;
* policy identifies blockers and non-blockers;
* policy does not introduce hard absolute gates;
* policy keeps low-visibility packages as future hardening priorities;
* checklist/status/test inventory are updated;
* no code/script/CI/dependency changes were made.
