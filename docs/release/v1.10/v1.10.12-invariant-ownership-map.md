## Migration Rules

The following migration rules govern how ownership must be transferred safely:

- **wrap_first** (6 rows): v1.11 must wrap existing behavior before extracting internals for store, restore, snapshot-restore, GC reachability, and remove. Wrapping preserves current behavior while establishing the contract boundary.
- **preserve_current_ordering** (7 rows): GC dry-run/live equivalence, packed/legacy parity, recovery sequencing, bootstrap ordering, SQLite/PostgreSQL parity, and list/stats ordering must not change during boundary work.
- **filesystem_boundary_before_move** (5 rows): Restore destination safety, temp/rename/fsync, traversal rejection, GC deletion, and OSFS seam must remain in a filesystem boundary until failure semantics are explicit.
- **catalog_before_engine_split** (4 rows): Snapshot atomicity, snapshot delete retention, ref-count repair, and transaction scope must be owned by a catalog contract before any engine split.
- **preserve_fail_closed_behavior** (3 rows): Verify fail-closed, chunk-ordering verification, and recovery quarantine must continue to fail closed after any boundary move.
- **preserve_json_shape** (1 row): JSON error envelope shape is frozen and must not drift.
- **preserve_cli_exit_semantics** (1 row): Exit codes 1/2/3/4 are frozen.
- **keep_in_cli** (2 rows): CLI validation-before-mutation and config mutation safety stay at CLI boundary.
- **defer_until_daemon** (2 rows): Benchmark and simulation are deferred until daemon/catalog facade work.
