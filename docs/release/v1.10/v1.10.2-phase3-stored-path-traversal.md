# v1.10.2 Phase 3 — Snapshot / Stored Path Traversal Rejection

Status: Complete

## Purpose

Phase 3 hardens snapshot and stored-path handling so logical snapshot paths are validated centrally before they are normalized, persisted, or resolved back out of storage.

The expected invariant is:

> Snapshot/stored paths must remain relative, must not escape root, and must reject traversal, absolute, drive-qualified, UNC-like, and NUL-containing forms before persistence or reuse.

## Scope

Included:

- stored-relative validation for snapshot path normalization
- resolver ingress validation for snapshot_path persistence
- traversal rejection
- absolute path rejection where appropriate
- Windows drive path rejection where appropriate
- UNC-like rejection
- NUL-byte rejection
- focused regression tests

Excluded:

- restore destination policy, Phase 4
- symlink policy integration, Phase 5
- unsafe temp/rename integration, Phase 6
- CLI-layer snapshot input validation beyond the core snapshot package
- container filename validation, Phase 2
- script validation, Phase 10
- CI/workflow changes
- dependency/toolchain changes

## Design Rule

Phase 3 should reuse the shared stored-relative validator rather than duplicating path policy in the snapshot package.

## Implementation Summary

Phase 3 currently hardens two internal trust boundaries:

| Area | Change |
|---|---|
| Snapshot normalization | `NormalizeSnapshotPath` now validates the normalized stored path with `internal/pathsafe.ValidateStoredRelativePath` before returning. |
| Snapshot path resolver | `ResolveSnapshotPath` and `ResolveSnapshotPaths` now validate each candidate path before persistence operations. |
