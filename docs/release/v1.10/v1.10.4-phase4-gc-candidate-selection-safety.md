## Candidate-Selection Validation Contract

### Inclusion Rules

- A GC candidate may be selected only when it is proven unreachable from all live logical-file roots.
- A GC candidate may be selected only when it is proven unreachable from all snapshot-retained roots.
- A GC candidate may be selected only when it is not referenced by any shared/deduplicated still-live reference.
- A GC candidate may be selected only when reference integrity checks have passed.

### Exclusion Rules

- Live logical-file data must never appear as collectible.
- Snapshot-retained data must never appear as collectible.
- Shared/deduplicated data must not appear as collectible while any live or retained reference remains.
- Ambiguous reachability must be excluded from candidates.
- Missing physical data must not be confused with safely collectible data.

### Fail-Closed Rules

- If candidate reachability cannot be evaluated, GC must fail closed.
- If graph integrity fails, candidate selection must not continue.
- If candidate queries disagree with safety checks, destructive GC must not proceed.

### Reporting Rules

- Dry-run candidate reports must be conservative.
- Candidate counts must represent actionable candidates, not protected roots.
- Candidate reports must not classify protected data as reclaimable.
