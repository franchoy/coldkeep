# v1.10.1 Phase 7 — JSON Shorthand Consistency

Status: Complete

## Purpose

Phase 7 fixes CLI JSON shorthand inconsistencies.

The expected invariant is:

> If a command supports JSON output mode, the documented `--json` shorthand must behave consistently with the long-form output mode.

## Scope

Included:

- `--json` shorthand routing
- equivalence between `--json` and long-form JSON output selection where both are supported
- deterministic errors for unsupported JSON shorthand
- regression tests for affected command families

Excluded:

- full JSON output purity and no-human-text guarantees, handled in Phase 8
- unexpected positional argument handling, already covered by Phase 3
- value-flag token handling, already covered by Phase 4
- boolean explicit false handling, already covered by Phase 5
- duplicate flag behavior, already covered by Phase 6
- storage, GC, packed-storage, restore/recovery internals
- CI workflow changes
- dependency/toolchain changes

# Implementation Summary

Phase 7 changed JSON shorthand routing for the following command families:

| Command / Family | JSON selectors | Change | Test coverage |
|---|---|---|---|
| Output mode resolver | `--json`, `--output` | strict duplicate selector policy: `--json` cannot be combined with `--output` | `TestResolveOutputModeRejectsJSONConflictWithHumanOutput`, `TestResolveOutputModeRejectsDuplicateJSONSelectors` |
| Startup mode inference | `--json`, `--output json` | `inferOutputModeFromArgs` now treats `--json` as JSON mode for all output-supported commands, including `inspect` | `TestInferOutputModeFromArgsSupportsStatsJSONShorthand`, `TestInferOutputModeFromArgsSupportsInspectJSONShorthand`, `TestInferOutputModeFromArgsSupportsDoctorJSONShorthand`, `TestInferOutputModeFromArgsSupportsSnapshotJSONShorthand` |
| Command allowlists | `--json` | JSON-capable commands now accept shorthand `--json` consistently alongside `--output` | `TestRunListCommandJSONShorthandAccepted`, `TestRunInspectCommandJSONShorthand`, `TestStatsCommandJSONShorthand` |
| Unsupported shorthand | `--json` on unsupported command | unsupported shorthand still fails deterministically as usage error | `TestRunBenchmarkCommandRejectsJSONShorthand` |

## Conflict / Duplicate Selector Policy

Policy used:

```text
Strict duplicate selector rejection.
`--json` and `--output ...` are treated as conflicting duplicate output-mode selectors.
```

## Unsupported JSON Shorthand Cases

|---|---|---|
