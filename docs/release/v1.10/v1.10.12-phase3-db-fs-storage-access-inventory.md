### Key Findings

- `ConnectDB()` in `internal/db/db.go` is the root engine boundary candidate; all DB access flows through or beside it.
- `OpenLocalStorage()` in `internal/storage/context.go` bundles recovery + DB + writer into a single entry point; this is the correctness-critical startup sequence.
- `SystemRecoveryWithContainersDir()` in `internal/recovery/system_recovery.go` is the fail-closed startup invariant; it must run before any DB writes.
- GC, Restore, Snapshot, Recovery, and Store all use explicit `BeginTx`/`Commit` scopes; all are correctness-critical.
- Filesystem access is fully behind the `fsx` abstraction; OSFS delegates to `os` package.
- Phase 2 carry-forwards: all 6 `needs_phase3_db_fs_review` rows resolved.
