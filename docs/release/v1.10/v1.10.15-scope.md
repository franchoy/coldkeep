# v1.10.15 Scope — Release Metadata Reconciliation

Status: Complete

## Release

v1.10.15 — Release Metadata Reconciliation

## Purpose

v1.10.15 corrects release metadata after v1.10.14.

The v1.10.14 tag was published externally, but the repository still reported version `1.10.13`, lacked a v1.10.14 CHANGELOG entry, and had v1.10.14 Phase 7 marked pending inside the repository documents. v1.10.15 reconciles those gaps so the repository self-describes the completed v1.10.14 release correctly, then closes v1.10.x definitively before v1.11 starts.

This is a metadata-only corrective release.

## Core Invariant

v1.10.15 corrects release metadata only. It must not change runtime behavior, repository format, storage format, schema behavior, migrations, restore behavior, verify behavior, GC behavior, snapshot behavior, engine code, or catalog code.

## In Scope

- bump reported version from `1.10.13` to `1.10.15`;
- update version test from `1.10.13` to `1.10.15`;
- reconcile v1.10.14 Phase 7 release evidence inside repository documents;
- add CHANGELOG entries for v1.10.14 and v1.10.15;
- document the v1.10 release-notes source-of-truth convention;
- optionally document `COLDKEEP_STRICT_RECOVERY` in README.

## Out of Scope

v1.10.15 must not:

- change storage behavior;
- change restore behavior;
- change verify behavior;
- change GC behavior;
- change snapshot behavior;
- change schema or migration behavior;
- change CLI behavior except the reported version output;
- change JSON behavior;
- change CI;
- change scripts;
- change dependencies;
- start engine extraction;
- create `internal/engine`;
- start catalog abstraction;
- create `internal/catalog`;
- change the default database backend;
- remove PostgreSQL compatibility;
- implement SQLite-first behavior;
- perform v1.11 implementation work.

## Release Position

v1.10.13 — final correctness-hardening release.
v1.10.14 — final evidence-closure and v1.11 handoff release.
v1.10.15 — release metadata reconciliation; the final v1.10.x release.

v1.11 may begin only after v1.10.15 is complete, under the rules documented in `docs/release/v1.10/v1.10.14-v111-handoff-gate.md`.
