# v1.10.8 Phase 6 — Restore Seam Introduction

Status: Complete

## Purpose

Phase 6 introduces the filesystem abstraction seam into restore-related paths while preserving default OS-backed behavior.

## Core Invariant

Restore behavior must remain byte-for-byte and failure-semantics equivalent when using the default OS-backed filesystem seam.

## Implementation

Phase 6 changes restore-related filesystem operations in `internal/storage/restore.go` to use `fsx.FS`.

An unexported `fs fsx.FS` field is added to `RestoreOptions`. In `restoreFileWithDBAndDir`, the seam is resolved at the top of the function:

```go
fsys := opts.fs
if fsys == nil {
    fsys = fsx.Default()
}
```

All restore-path filesystem operations then use `fsys.*` instead of direct `os.*` calls.

## Scope

Phase 6 is limited to restore/storage paths. Container, recovery, GC, snapshot, and maintenance paths are not changed.

## Files Changed

```text
internal/storage/restore.go
internal/storage/restore_seam_test.go
```

## Seamed Operations

Phase 6 covers restore-side uses of:

* `Stat` — destination directory check, overwrite guard, pre-rename overwrite check
* `MkdirAll` — create destination directory, create parent directories
* `Remove` — cleanup temp file on error (in defer)
* `Rename` — atomic replace of temp file with target path
* `Open` — open output directory for fsync
* `Sync` — directory fsync after rename (via `fsx.File.Sync`)

## Not Seamed

* `os.CreateTemp` — not in `fsx.FS` interface; stays as direct OS call
* `outFile.Sync()` — handle from `os.CreateTemp`, `*os.File` already satisfies `fsx.File`

## Behavior Preservation

The default restore seam uses the OS-backed adapter.

The restore path must not:

* inject failures;
* retry filesystem operations;
* normalize errors;
* rewrite paths;
* change permissions;
* change destination safety behavior;
* change restore output bytes;
* change atomic rename behavior.
