# v1.10.7 Regression Prevention Design

Status: Designed

## Purpose

This document defines how Coldkeep should prevent future critical-path coverage regressions.

It is a design document only. v1.10.7 does not implement hard regression enforcement.

## Core Principle

Regression prevention must protect correctness-critical coverage evidence without turning baseline variation or known low coverage into automatic release failure.

Coverage regression prevention exists to protect named correctness invariants, not to chase raw percentages.

## Definitions

### Baseline

The committed v1.10.7 coverage baseline:

```text
docs/release/v1.10/v1.10.7-coverage-baseline.csv
```

### Current report

A newly generated coverage report from:

```bash
scripts/critical_coverage.sh --report --csv-output <path>
```

### Regression

A regression is one of:

1. a tracked Tier 1 package disappears from the current report;
2. a tracked Tier 2 package disappears from the current report;
3. a package marked `release_blocking_in_v1107=yes` reports `n/a`;
4. a Tier 1 package coverage decreases materially from the committed baseline;
5. a Tier 2 package coverage decreases materially from the committed baseline;
6. a Tier 1 invariant disappears from the invariant coverage map;
7. an artifact is malformed or missing required columns.

### Material decrease

For future policy, a material decrease should mean:

```text
coverage drop >= 2.0 percentage points
```

This avoids failing builds on small coverage noise while still detecting meaningful loss of evidence.

## Proposed Future Modes

The report script may later gain these modes:

```bash
scripts/critical_coverage.sh --soft-gate
scripts/critical_coverage.sh --hard-gate
```

These modes are **not implemented in v1.10.7 Phase 7**.

### Future `--soft-gate`

Potential behavior:

* generate current report;
* compare against committed baseline;
* warn on Tier 1/Tier 2 material decreases;
* warn on missing Tier 3 coverage;
* print invariant context;
* exit zero unless artifacts are malformed or coverage generation fails.

### Future `--hard-gate`

Potential behavior:

* generate current report;
* compare against committed baseline;
* fail on missing Tier 1 package;
* fail on missing Tier 1 invariant;
* fail on `n/a` coverage for release-blocking packages;
* fail on unexplained Tier 1 material regression;
* fail on malformed baseline/current report;
* never fail on global coverage percentage.

## v1.10.7 Interpretation

For v1.10.7, regression prevention remains design-only.

The current CI job is report-only. It must not compare against baseline, enforce thresholds, or fail because of known low coverage in:

```text
internal/maintenance: 47.6%
internal/recovery: 44.9%
```

## Regression Severity Model

| Regression Type                          | Tier          | v1.10.7 Action | Future Hard-Gate Candidate |
| ---------------------------------------- | ------------- | -------------- | -------------------------- |
| Missing baseline CSV                     | Any           | Block release  | Yes                        |
| Malformed baseline CSV                   | Any           | Block release  | Yes                        |
| Missing Tier 1 package in current report | Tier 1        | Design only    | Yes                        |
| Missing Tier 2 package in current report | Tier 2        | Design only    | Maybe                      |
| Tier 1 material decrease                 | Tier 1        | Design only    | Yes, if unexplained        |
| Tier 2 material decrease                 | Tier 2        | Design only    | Maybe                      |
| Tier 3 decrease                          | Tier 3        | Observe only   | No                         |
| Known low baseline below target          | Tier 1/Tier 2 | Non-blocking   | No                         |
| Global coverage below target             | Any           | Non-blocking   | No                         |

## Explanation Requirement

A future regression gate should allow an explicit explanation field before blocking on coverage decreases.

Possible explanation categories:

* test moved to another package;
* package split or refactor;
* generated code excluded;
* flaky coverage noise;
* invariant coverage preserved elsewhere;
* intentional future hardening deferral;
* actual coverage regression requiring fix.

No explanation mechanism is implemented in Phase 7.

## Invariant Linkage Requirement

A future hard gate must not rely only on package percentages.

Before failing a release, the gate should identify:

* affected package;
* affected tier;
* linked invariant IDs;
* baseline percentage;
* current percentage;
* delta;
* whether invariant evidence still exists.

## Future Artifact Shape

A future regression comparison artifact could use:

```csv
package,tier,baseline_percent,current_percent,delta_percent,regression_class,linked_invariants,action
```

Possible `regression_class` values:

* `none`
* `warning`
* `blocking-candidate`
* `missing-package`
* `missing-baseline`
* `malformed-artifact`
* `observe-only`

## Non-Goals

Phase 7 does not:

* change `scripts/critical_coverage.sh`;
* add `--soft-gate`;
* add `--hard-gate`;
* compare reports;
* enforce thresholds;
* change CI workflows;
* change Go code;
* change tests;
* change dependencies.
