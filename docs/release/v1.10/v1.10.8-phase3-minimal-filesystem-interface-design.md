# v1.10.8 Phase 3 — Minimal Filesystem Interface Design

Status: Complete

## Purpose

Phase 3 defines the minimal filesystem interface needed by v1.10.8.

The design is derived from the Phase 2 seam classification and remains documentation-only.

## Core Invariant

The v1.10.8 filesystem interface must be minimal, behavior-preserving, and derived only from classified seam groups needed for future deterministic fault injection.


## Interface Boundary

The proposed interface includes:

* `Open`
* `OpenFile`
* `Stat`
* `MkdirAll`
* `Rename`
* `Remove`
* `ReadDir`
* `WalkDir`

The proposed file abstraction includes:

* `Read`
* `Write`
* `Close`
* `Sync`

## Design Decision

The interface is intentionally narrow.

It only covers seam groups required by the Phase 2 classification.

It does not include full filesystem behavior, path policy, repository layout policy, catalog operations, or fault-injection controls.

## Non-Goals

Phase 3 does not:

* create `internal/fsx`;
* add Go code;
* add tests;
* change existing filesystem calls;
* change restore behavior;
* change container behavior;
* change recovery behavior;
* change GC behavior;
* implement fault injection;
* change CI;
* change dependencies.

## Validation

Phase 3 validation confirms:

* interface design document exists;
* method map exists;
* all 9 Phase 2 seam groups are represented;
* no implementation work was introduced;
* no restricted files were changed.
