# Coldkeep v1.10.1 Release Notes

## Release

v1.10.1 — CLI Correctness & Contract Stabilization

## Release Type

Stabilization / correctness release.

## Summary

v1.10.1 hardens the Coldkeep CLI contract so malformed commands fail deterministically, JSON-mode behavior is automation-safe, and argument-only invalid usage is rejected before stateful work where practical.

This release does not add product features. It is part of the v1.10 reliability freeze and correctness burn-down.

## Highlights

- Rejects unexpected positional arguments for scoped commands.
- Rejects known flag tokens used as values for value flags.
- Honors explicit boolean false values such as `--reverse=false`.
- Rejects duplicate singleton flags.
- Aligns `--json` shorthand with canonical JSON output mode.
- Validates JSON-mode stdout as machine-readable JSON.
- Improves validation ordering before stateful work.
- Closes official v1.10.1 tracker and remediation matrix rows with proof.
- Records full local validation and CI simulation evidence.

## Compatibility Notes

This release intentionally makes malformed CLI invocations fail earlier and more strictly.

Scripts that relied on ignored extra arguments, duplicate flags, or ambiguous boolean parsing may need adjustment.

## Out of Scope

The following are intentionally deferred to later v1.10.x releases:

- path traversal and validation/security hardening
- container filename trust hardening
- packed-storage metadata integrity
- GC reachability corrections
- restore/recovery safety hardening
- Codacy passive integration
- critical-path coverage gates
- filesystem fault injection
- engine boundary work
