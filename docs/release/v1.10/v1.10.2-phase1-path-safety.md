# v1.10.2 Phase 1 — Central Path Safety Package

Status: Complete

## Purpose

Phase 1 creates the central path safety primitives for v1.10.2 validation and security hardening.

The expected invariant is:

> Path validation rules must be centralized, explicit, tested, and reused by later v1.10.2 phases.

## Scope

Included:

- shared path safety package/helper
- validation contract for stored/snapshot paths
- validation contract for user-provided filesystem paths
- validation contract for safe child joins under a trusted root
- traversal rejection primitives
- absolute path rejection primitives where appropriate
- Windows drive path rejection primitives where appropriate
- NUL-byte rejection
- deterministic error behavior
- focused unit tests

Excluded:

- full snapshot/stored-path integration, Phase 3
- full restore destination integration, Phase 4
- symlink policy integration, Phase 5
- unsafe temp/rename integration, Phase 6
- script path validation integration, Phase 10
- storage, GC, packed-storage, restore/recovery rewrites
- CI workflow changes
- dependency/toolchain changes

## Design Rule

Phase 1 should introduce reusable primitives, not broad behavior changes across the whole application.

## Existing Path Handling Survey

| Area | Current pattern | Phase using this later |
|---|---|---|
| Stored/snapshot paths | Snapshot normalization already exists in `NormalizeSnapshotPath` using slash normalization and relative-path checks (`internal/snapshot/snapshot.go`). | Phase 3 |
| Container filenames | Runtime joins use container filename values with trusted container dir during restore/read flows (for example `filepath.Join(containersDir, chunk.ContainerName)` in `internal/storage/restore.go`). | Phase 2 |
| Restore destinations | Restore destination modes are resolved centrally in `resolveRestoreOutputPath` and then temp-write/rename logic applies (`internal/storage/restore.go`). | Phase 4 |
| Symlink-sensitive paths | Physical path canonicalization currently resolves symlinks via `filepath.EvalSymlinks` in `normalizePhysicalFilePath` (`internal/storage/physical_file_repository.go`). | Phase 5 |
| Temp/rename paths | Restore currently writes via `os.CreateTemp` in destination dir and atomically renames (`internal/storage/restore.go`). | Phase 6 |
| Script path inputs | Script inputs and sample path env handling are currently script-local (for example `COLDKEEP_SAMPLES_DIR` in `scripts/smoke.sh`). | Phase 10 |
