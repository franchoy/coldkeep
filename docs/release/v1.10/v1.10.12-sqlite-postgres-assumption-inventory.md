## Critical Database Assumptions

The ten critical assumptions are:

- **DBA-11012-001** — v1.10.12 must not alter backend defaults (`backend_agnostic`). Phase 1 scope contract and Phase 6 migration rules forbid any default backend change.
- **DBA-11012-002** — Both SQLite and PostgreSQL must remain supported catalog backends (`dual_backend`). Phase 6 MIG-11012-027 is a release blocker.
- **DBA-11012-007** — EnsureSchema unified bootstrap entry must continue routing to the correct backend-specific path (`dual_backend`). Any catalog contract must preserve this routing.
- **DBA-11012-010** — Both backends target schema version 15; version tracking must remain deterministic on both (`dual_backend`). Version drift is a catalog correctness bug.
- **DBA-11012-018** — All mutating catalog operations must use explicit BeginTx/Commit/Rollback on both backends (`dual_backend`). Phase 6 MIG-11012-013 is a release blocker.
- **DBA-11012-022** — BackendFromDB() must remain the authoritative basis for all backend capability derivation (`dual_backend`). A catalog facade must not bypass this detection.
- **DBA-11012-027** — Dual-backend test coverage must not silently drop PostgreSQL (`dual_backend`). Phase 6 MIG-11012-031 is a release blocker.
- **DBA-11012-028** — The PostgreSQL 16 CI service in correctness-matrix must not be removed (`postgres_only`). Removing it would silently break PostgreSQL compatibility.
- **DBA-11012-031** — A future v1.12 catalog facade must not assume SQLite-only behavior (`dual_backend`). Phase 6 MIG-11012-029 blocks catalog abstraction until inventory is complete.
- **DBA-11012-032** — A future v1.11 engine facade must not hide backend-specific behavior behind an incomplete abstraction (`dual_backend`). All backend capability differences must remain visible at the catalog boundary.

## Future Direction Clarification

v1.10.12 may document this strategic direction:

```text
SQLite-first is the future local repository direction.
PostgreSQL remains the future centralized/server catalog direction.
```

But v1.10.12 must not implement either direction.

```text
v1.10.12 does not change default database behavior.
v1.10.12 does not move catalog behavior behind an abstraction.
v1.10.12 does not make SQLite the only supported path.
v1.10.12 does not remove PostgreSQL compatibility.
```
