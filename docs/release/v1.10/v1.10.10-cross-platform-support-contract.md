# v1.10.10 Cross-Platform Support Contract

Status: Draft for Phase 1

## Purpose

This document defines the support contract for v1.10.10 cross-platform validation.

v1.10.10 is a validation and documentation release. It must verify Coldkeep behavior across supported platforms without overclaiming unsupported platform behavior.

## Core Invariant

v1.10.10 must validate and document Coldkeep behavior across supported platforms without claiming unsupported behavior, weakening correctness guarantees, or introducing platform-specific runtime hacks.

## Target Platforms

v1.10.10 validation targets:

| Platform | Status | Notes |
|---|---|---|
| Linux / Ubuntu | Required | Primary CI platform and baseline behavior |
| macOS | Required where feasible | Validate path, restore, permissions, and timestamp behavior |
| Windows | Required where feasible | Validate path separator, rename, file locking, restore, and SQLite behavior |

## Support Language

Use careful wording:

- `validated on Linux`
- `validated on macOS`
- `validated on Windows where feasible`
- `documented limitation`
- `platform-specific behavior documented`

Avoid overclaiming:

- do not claim full Windows production support unless CI proves it;
- do not claim identical metadata semantics across platforms;
- do not claim POSIX permission behavior on Windows;
- do not claim shell scripts are Windows-native unless validated.

## Required Validation Areas

v1.10.10 should validate or document:

- path normalization;
- Windows drive/path separator behavior;
- restore determinism;
- rename/overwrite behavior;
- symlink behavior;
- permission behavior;
- timestamp behavior;
- SQLite file behavior;
- line endings;
- shell script portability;
- CI OS matrix feasibility.

## Explicit Non-Goals

v1.10.10 does not require:

- Windows-native shell benchmark scripts;
- full enterprise packaging;
- installer work;
- GUI work;
- network/NAS/cloud behavior;
- engine extraction;
- catalog abstraction;
- default database changes;
- broad runtime rewrites.

## Compatibility Contract

v1.10.10 must not change:

- repository format;
- container format;
- storage format;
- CLI behavior unless explicitly documented;
- default database behavior;
- runtime correctness guarantees.

## Decision Rule

If a behavior differs across platforms, v1.10.10 should either:

1. make the behavior deterministic and tested; or
2. document it as a platform-specific limitation.

Do not silently accept ambiguous platform behavior.
