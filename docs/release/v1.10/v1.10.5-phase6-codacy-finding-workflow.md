# v1.10.5 Phase 6 — Codacy Finding Workflow Hardening

Status: Complete

## Purpose

Phase 6 defines the standard workflow for handling Codacy findings during PR review.

The expected invariant is:

> Codacy findings must be triaged by release impact before merge: new actionable issues are fixed or explicitly accepted; baseline findings are documented/deferred.

## Scope

Included:

- define Codacy finding categories
- define release-delta vs baseline classification
- define required actions for new actionable findings
- define when findings may be documented/deferred
- define PR update requirements after Codacy feedback
- define checklist and evidence requirements for future releases

Excluded:

- production code changes
- test implementation changes
- CI workflow changes
- Codacy configuration changes
- dependency/toolchain changes
- tracker/matrix closure
- broad style cleanup
- fixing historical baseline findings

## Design Rule

Phase 6 is a PR-review workflow hardening phase.

It defines how to process Codacy feedback without changing product behavior or Codacy configuration.

## Codacy Finding Categories

| Category | Meaning | Required action |
| --- | --- | --- |
| release-delta actionable | Finding introduced or touched by current PR and likely real | Fix before merge |
| release-delta accepted | Finding introduced or touched by current PR but intentionally accepted | Document rationale before merge |
| baseline finding | Existing issue not introduced by current PR | Document/defer; do not do broad unrelated cleanup |
| duplicate analyzer finding | Already covered by local lint/static/gosec evidence | Reference local evidence |
| false positive | Analyzer finding does not represent a real defect in context | Document rationale |
| tooling/config noise | Finding caused by analyzer/config limitation | Document and defer |
| release-blocking unknown | Finding cannot be classified confidently | Block merge until classified |

## Required Codacy PR Workflow

When Codacy reports findings on a release PR:

1. Wait for Codacy analysis to finish.
2. List all findings reported on the PR.
3. Determine whether each finding is in the release delta.
4. For each release-delta finding:
   - inspect the changed file and diff context;
   - classify as actionable, accepted, false-positive, duplicate, or tooling/config noise;
   - fix actionable findings before merge;
   - document accepted/deferred findings.
5. For each baseline finding:
   - confirm it is not introduced by the release branch;
   - document as baseline/deferred;
   - avoid broad unrelated cleanup inside the release branch.
6. Rerun relevant local checks after fixes.
7. Wait for Codacy to rerun or confirm no new actionable issues remain.
8. Update PR comment/body if material findings were fixed or documented.
9. Merge only after CI is green and Codacy has no unclassified release-delta findings.

## Evidence Format

If Codacy reports findings, record the review in either the PR body/comment or a release evidence document.

Recommended evidence document:

```text
docs/release/v1.10/v1.10.x-codacy-review.md
```

Minimum evidence:

- Codacy analysis status
- finding count
- finding file/path
- finding category
- whether it is in the release delta
- action taken
- fix commit if applicable
- rationale for accepted/deferred/false-positive findings
- local checks rerun after fixes
- final Codacy status before merge

For green/no-finding runs, the checklist entry is sufficient:

```markdown
- [x] Codacy / code-quality review completed
- [x] No unclassified release-delta Codacy findings remain
```

## Merge Blocking Rules

A PR must not be merged if:

- CI is failing.
- Codacy has unfinished analysis.
- Codacy has unclassified release-delta findings.
- Codacy has actionable release-delta findings without a fix.
- Codacy has accepted release-delta findings without explicit rationale.
- Local reruns after Codacy fixes are missing.
- The PR body/checklist does not reflect the final Codacy state.

A PR may proceed if:

- CI is green.
- Codacy analysis is complete.
- all release-delta actionable findings are fixed;
- accepted/false-positive/tooling findings are documented;
- baseline findings are documented or already covered by baseline triage;
- final local checks after fixes pass.
